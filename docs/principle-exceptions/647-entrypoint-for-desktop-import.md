# CLI를 띄울 때 문서화되지 않은 환경변수 `CLAUDE_CODE_ENTRYPOINT`에 우리 이름을 주고, 이미 쌓인 세션 기록의 같은 값을 바꾼다

> 마지막 갱신: 2026-11-07
> 수정 이력은 이 파일을 고쳐 적지 말고 `git log -- docs/principle-exceptions/647-entrypoint-for-desktop-import.md`로 확인한다.

- 관련 이슈: [#647](https://github.com/Swttch/swttch/issues/647) (플러그인에서 만든 세션이 Claude 데스크탑의 Code 탭에 나타나지 않는다는 요청)

## 어떤 원칙을 위반하는가

`CLAUDE.md`의 **★ 핵심 원칙** 중 **2번 「공식 지원 비의존」**이다. 두 가지가 문서화되지 않은 것에 기댄다.

1. `CLAUDE_CODE_ENTRYPOINT`는 CLI가 소스 안에서 읽는 환경변수이고 공식 문서에 없다.
2. 이 값이 데스크탑의 가져오기에 통하는 이유는 데스크탑 앱 안에 있는 제외 목록이다. 이 역시 공식 문서에 없다.

원칙 문장은 고치지 않았고, 여기 예외로 남긴다.

## 무엇이 문제였나

Claude 데스크탑은 Code 탭 목록을 자기 색인 파일(`claude-code-sessions/<계정>/<조직>/local_<id>.json`)로 만든다. 터미널에서 시작한 세션은 데스크탑 메뉴 **도움말 → 문제 해결 → Claude Code CLI 세션 가져오기…**(`/resume`도 같은 일을 한다)로 그 색인에 올릴 수 있다. 플러그인에서 만든 세션은 이 가져오기에 잡히지 않았다.

2026-11-07에 이 맥(데스크탑 앱, CLI 2.1.318)에서 확인했다.

| 세션의 `entrypoint` | 데스크탑 가져오기 |
|---|---|
| `sdk-cli` (플러그인이 `-p`로 띄운 CLI가 받는 값) | 잡히지 않는다 |
| `claude-desktop` | "잃어버린 게 아님"으로 빠진다 |
| `claude-jetbrains` | 잡힌다 |
| `banana-quokka-7` (아무 관련 없는 단어) | 잡힌다 |

원인은 두 곳에서 읽었다.

- CLI: `CLAUDE_CODE_ENTRYPOINT`가 이미 있으면 그 값을 그대로 쓰고, 없으면 `-p`·`--print`로 띄운 경우 `sdk-cli`, 아니면 `cli`로 정한다(CLI 2.0.22 번들에서 읽었다). 2.1.318에서는 `cli`를 주어도 `-p`이면 `sdk-cli`로 남았고, 그 밖의 값은 그대로 기록됐다.
- 데스크탑: 가져오기 스캔이 `sdk-cli`, `sdk-ts`, `sdk-py`, `mcp`, `local-agent` 같은 값을 가진 기록을 제외 목록으로 빼고, 목록에 없는 값은 받아들인다. 앱 로그의 `Scan complete` 줄(`skippedFiltered`, `skippedNotLost`)로 같은 결과를 확인했다.

가져온 세션에서 데스크탑으로 메시지를 보내면 같은 기록 파일에 이어졌고, 그 세션을 플러그인에서 다시 열면 데스크탑에서 이어 쓴 대화도 보였다.

## 선택지

| 방법 | 결과 |
|---|---|
| 아무것도 하지 않는다 | 플러그인 세션은 데스크탑에서 이어 쓸 수 없다. 사용자는 `claude --resume`으로 터미널에서 이어야 한다 |
| 데스크탑의 색인 파일에 우리가 직접 쓴다 | 앱의 미문서화 파일에 쓰는 것이라 원칙 2번을 가장 크게 어기고, 앱이 형식을 바꾸면 조용히 깨진다. 개발자가 금지했다 |
| `entrypoint`를 `cli`로 위장한다 | 2.1.318의 `-p`에서는 되지 않는다. 되더라도 터미널 세션이라고 거짓을 적게 된다 |
| **CLI를 띄울 때 `CLAUDE_CODE_ENTRYPOINT`에 우리 이름을 준다** | 새 세션이 데스크탑 가져오기에 잡힌다. 값이 사실이다(어디서 시작했는지를 적는다) |
| **이미 쌓인 세션 기록의 `sdk-cli`를 같은 이름으로 바꾼다** | 옛 세션도 가져오기에 잡힌다. 설정 화면에서 사용자가 버튼을 눌러야만 일어난다 |

## 어느 기준으로 예외가 되는가

[README](./README.md)의 **첫 번째(다른 대안이 없어 불가피한 경우)** 에 해당한다. 앱 파일에 쓰지 않고 데스크탑에서 플러그인 세션을 이어 쓰게 하는 방법은, 데스크탑이 스스로 가져오는 길을 여는 것뿐이다. 그 길의 조건이 기록의 `entrypoint`이고, 그 값을 정하는 입구가 이 환경변수다.

## 위반의 범위를 어떻게 좁혔는가

- **값은 사실이다.** IDE 안에서 시작한 세션은 `swttch-jetbrains`, 브라우저(`ccg`)에서 시작한 세션은 `swttch-standalone`이다. 터미널이나 데스크탑이라고 속이지 않는다.
- **사용자가 이미 정한 값이 이긴다.** 셸이나 Claude 설정의 `env`에 이 변수가 있으면(빈 문자열 포함) 건드리지 않는다. 값이 없을 때만 채운다. (`buildEntrypointEnv`)
- **환경변수 하나만 보낸다.** 요청·응답 형식을 새로 가정하지 않는다.
- **옛 세션의 기록은 사용자가 누를 때만 고친다.** 설정 → 일반의 버튼을 눌러야 한다. 고치는 것은 줄마다 있는 `"entrypoint":"sdk-cli"` 한 쌍뿐이고, 나머지는 바이트까지 같게 둔다.
  - 복사본에 쓴 뒤 한 번의 이름 바꾸기로 교체하므로, 중간에 실패해도 원본은 그대로다.
  - 복사하는 동안 원본이 자랐으면 복사본을 버리고 원본을 둔다.
  - CLI가 실행 중인 세션은 건드리지 않는다. 실행 중인 CLI는 기록 파일을 열어 둔 채 덧붙이므로, 교체하면 그 뒤의 대화가 사라진다. 실행 중인 목록은 공식 명령 `claude agents --json`으로 읽고, 읽지 못하면 요청 전체를 거절한다.
  - 현재 열린 폴더의 세션만 바꾼다.
- **다른 쪽이 `sdk-cli`로 만든 세션도 같은 폴더에 있으면 함께 바뀐다.** 이 앱이 만든 세션과 SDK를 쓰는 다른 도구가 만든 세션은 기록만으로 구분되지 않는다. 사용자가 버튼을 눌러 자기 폴더의 세션을 가져오기 대상으로 만드는 것이므로 받아들인다.
- **변수가 사라져도 망가지지 않는다.** CLI가 읽지 않게 되면 새 세션이 `sdk-cli`로 돌아갈 뿐이고, 데스크탑에서 가져오기만 안 된다.

## 이 예외가 정당하지 않게 되는 조건

- 데스크탑이 SDK로 띄운 세션도 가져오게 되거나, 가져오기 말고 공식적인 연결(예: 세션을 지정해 여는 링크)을 주는 경우: 그 방법으로 갈아탄다.
- CLI가 `-p` 세션의 `entrypoint`를 공식 옵션으로 정하게 해 주는 경우: 그 옵션으로 갈아탄다.
- 데스크탑이 제외 규칙을 바꿔 이 이름도 빼게 되는 경우: 이 예외는 효과가 없어지므로 철회하고 안내 문서만 남긴다.
- 이 변수를 주면 터미널과 다른 동작이 생기는 경우(`entrypoint`로 동작을 가르는 기능이 CLI에 생기는 경우).

## 확인하지 못한 것

- 이 맥의 데스크탑 앱과 CLI 2.1.318 외의 버전. 제보자는 Windows이므로 Windows 데스크탑에서도 같은지 확인하지 못했다.
- 데스크탑이 이후 업데이트에서 제외 목록을 어떻게 바꾸는지.
- 다른 SDK 도구가 만든 세션이 같은 폴더에 있을 때의 실제 빈도.
