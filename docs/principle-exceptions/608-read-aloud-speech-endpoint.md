# 답변을 소리로 읽을 때 미문서화 음성 합성 엔드포인트를 쓴다

> 마지막 갱신: 2026-11-09
> 수정 이력은 이 파일을 고쳐 적지 말고 `git log -- docs/principle-exceptions/608-read-aloud-speech-endpoint.md`로 확인한다.

- 관련 이슈: [#608](https://github.com/Swttch/swttch/issues/608) (Claude 데스크탑의 Transcript view를 따라 하는 작업. 답변 아래 줄의 "소리 내어 읽기"가 그 일부다)
- 관련 PR: [#659](https://github.com/Swttch/swttch/pull/659)
- 판단한 사람: 김용현. 2026-11-09에 "소리 내어 읽기는 이번 PR에 같이 들어간다"고 정했고, 구현은 받아쓰기와 같은 확장킷 방식으로 하기로 확인했다.

## 어떤 원칙을 위반하는가

`CLAUDE.md`의 **★ 핵심 원칙** 중 **2번 「공식 지원 비의존」**이다. 읽어 주는 서버는 `wss://api.anthropic.com/api/ws/text_to_speech/text_stream`이고 공식 문서에 없다. Claude 데스크탑 앱의 "소리 내어 읽기"가 같은 엔드포인트를 부르는 것을 설치된 앱의 번들(`ion-dist.asar`)에서 읽어 확인했다. 원칙 문장은 고치지 않았고, 여기 예외로 남긴다.

1번 「CLI 동등성」과는 부딪히지 않는다. 터미널의 `claude`에는 답을 소리로 읽는 기능이 없어서, 같게 맞출 CLI 명령이 애초에 없다. 이 기능은 데스크탑 앱의 화면(UX)을 따라 하는 것이다(3번: 참고 대상에서는 화면만 따른다)이고, 그 화면을 만드는 수단이 미문서화 엔드포인트라서 2번 예외가 된다.

## 선택지

| 방법 | 결과 |
|---|---|
| 읽기 기능을 넣지 않는다 | 데스크탑에는 있는 버튼이 없다 |
| 브라우저의 `speechSynthesis`로 읽는다 | 공식 API라 원칙은 지키지만, 목소리가 기기마다 다르고 한국어 외 언어 품질이 들쭉날쭉하다. JetBrains의 JCEF는 음성 목록이 비는 경우가 있어 보장할 수 없다. Claude의 목소리도 아니다 |
| **확장킷이 데스크탑과 같은 서버에 말을 건다** | 데스크탑과 같은 목소리와 속도. 로그인 토큰은 확장킷 프로세스 안에서만 쓰이고 플러그인은 소리만 받는다 |

## 어느 기준으로 예외가 되는가

[README](./README.md)의 **두 번째(예외의 방법이 지나치게 압도적으로 이득이 큰 경우)** 에 해당한다. 목소리 품질과 데스크탑과의 일치가 이득이다. 이 판단은 사람이 했다.

## 위반의 범위를 어떻게 좁혔는가

- **플러그인은 토큰을 만지지 않는다.** 로그인을 읽고 서버에 말을 거는 코드는 전부 `@swttch/extend-kit`의 `swttch-ext tts`에 있고, 플러그인 백엔드는 그 명령을 실행해 글을 넣고 소리를 받는다. 확장킷을 import하지 않는다.
- **보내는 것은 읽을 글과 속도·언어뿐이다.** 요청 형식은 데스크탑 앱이 보내는 것(`text_chunk`, `close_stream`, `keep_alive`)만 쓰고, 모르는 응답 종류는 무시한다.
- **계정의 음성 설정은 읽기만 한다.** 목소리·속도·언어는 `GET https://api.anthropic.com/api/oauth/account/settings`의 `voice_preference`, `voice_speed`, `voice_language_code`에서 읽는다. 이것도 문서에 없는 경로이고, 같은 OAuth 토큰으로 열린다. 아무것도 쓰지 않으며, 못 읽으면 서버 기본값으로 읽는다.
- **로그인이 없으면 하지 않는다.** Claude 계정 로그인(OAuth)이 있어야 하고, API 키로 대신하지 않는다(받아쓰기와 같은 판단).
- **없어도 망가지지 않는다.** 서버가 거절하거나 엔드포인트가 사라지면 버튼이 오류 문구를 띄울 뿐이고, 채팅의 다른 부분은 영향이 없다.
- **확장킷이 오래됐거나 없으면** 누르는 순간 "확장킷을 설치/업데이트하세요"라고 알린다.

- **목소리 미리듣기는 서비스가 공개한 샘플을 그대로 재생한다.** 목소리마다 `https://assets.claude.ai/voice/selection/<id>-v<번호>.mp3`가 있고, 로그인 없이 받아진다(캐시 기간 1년). 파일을 내려받아 보관하거나 우리 서버에 올리지 않는다(남의 음원을 배포하는 일이라 하지 않기로 했다). 파일 이름의 번호는 서비스가 샘플을 다시 녹음할 때 바뀌므로, 서버 설정의 `preview_url`을 2026-11-09에 읽어 옮긴 것이고 낡으면 미리듣기만 멈춘다.

## 이 예외가 정당하지 않게 되는 조건

- 공식 문서에 음성 합성 API가 생기는 경우: 그쪽으로 갈아탄다.
- 서버가 OAuth 토큰으로 이 엔드포인트를 받지 않게 되는 경우: 기능을 철회한다.
- 이 호출이 사용량이나 요금에 잡히는 것으로 밝혀지는 경우: 개발자님께 다시 판단을 받는다.

## 측정한 것

2026-11-09, 확장킷의 로그인 읽기 코드로 같은 OAuth 토큰을 `Authorization: Bearer`로 실어 접속했다. 접속이 열렸고(HTTP 101), 영어 한 문장에 `{"type":"SpeechComplete","audio_sent_ms":2300}`와 PCM 73,600바이트(16kHz, 16비트, 모노 2.3초)가 왔다. 한국어 두 문장은 129,600바이트(4.05초)가 왔다.

## 확인하지 못한 것

- 무료 계정이나 조직 계정에서도 같은지, 사용 한도가 있는지.
- 서버가 한 번에 받는 글의 최대 길이. 데스크탑이 800자씩 나눠 보내는 것을 그대로 따랐다.
- 언어 22개와 언어별 목소리 목록(`READ_ALOUD_LANGUAGES`)은 데스크탑이 받는 서버 설정(`mobile_deedee_config`)에서 온 것이다. OAuth 토큰으로는 받을 수 없어, 2026-11-09에 개발자님이 내장 브라우저에서 로그인한 claude.ai 세션으로 `/api/bootstrap` 응답의 `speech_input.supported_languages`를 한 번 읽어 고정 목록으로 옮겼다(읽기만 했고 다른 것은 옮기지 않았다). 그래서 서버가 목록을 바꾸면 이 목록은 낡는다. 아래 두 문단은 그 전에 목록을 찾던 기록이다. 한국어는 `ko-balgeun` 밝은, `ko-chabunhan` 차분한이고, 영어는 `buttery`, `airy`, `mellow`, `glassy`, `rounded`다.
- (목록을 찾던 기록) 스타일 목록은 한국어(`ko-balgeun` 밝은, `ko-chabunhan` 차분한)와, 그 밖의 언어에 쓰는 기본 다섯 개(`buttery`, `airy`, `mellow`, `glassy`, `rounded`)뿐이었다. 한국어 두 id는 데스크탑이 받는 서버 설정(`mobile_deedee_config`)을 받을 방법을 찾지 못해, 데스크탑 앱이 이 컴퓨터에 남긴 캐시의 미리듣기 주소(`voice/selection/ko-chabunhan-v6.mp3`)와 계정에 저장된 값(`ko-balgeun`)에서 확인했다. 어느 쪽이 "밝은"이고 "차분한"인지는 데스크탑의 선택 화면 순서에서 읽은 것이다. 다른 언어의 목소리 목록은 모른다. 서버는 모르는 목소리 id도 오류 없이 받아 아무 목소리로나 읽으므로, id를 추측해 시험하는 것으로는 확인할 수 없었다.
