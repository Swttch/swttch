# CLI를 띄울 때 문서화되지 않은 환경변수 `CLAUDE_CODE_ARTIFACT=1`을 준다

> 마지막 갱신: 2026-10-23
> 수정 이력은 이 파일을 고쳐 적지 말고 `git log -- docs/principle-exceptions/584-artifact-env-for-slides.md`로 확인한다.

- 관련 이슈: [#584](https://github.com/Swttch/swttch/issues/584) (`/slides`를 플러그인에서 쓰고 싶다는 요청)
- 관련 PR: [#591](https://github.com/Swttch/swttch/pull/591)

## 어떤 원칙을 위반하는가

`CLAUDE.md`의 **★ 핵심 원칙** 중 **2번 「공식 지원 비의존」**이다. "공식 SDK 라이브러리나 미문서화 내부 프로토콜에 의존하지 않는다."

`CLAUDE_CODE_ARTIFACT`는 CLI가 소스 안에서 읽는 환경변수이고, 공식 문서에는 없다. 2026-10-23에 공식 환경변수 문서(code.claude.com/docs/en/env-vars)를 읽었다. 이 문서의 표에는 이름에 ARTIFACT가 들어간 변수가 `CLAUDE_CODE_ARTIFACT_AUTO_OPEN`, `CLAUDE_CODE_ARTIFACT_COMMENTS`, `CLAUDE_CODE_ARTIFACT_COMMENTS_AUTOREACT`, `CLAUDE_CODE_ARTIFACT_PUBLISH_EDITS`, `CLAUDE_CODE_DISABLE_ARTIFACT`로 다섯 개 있고, 이름이 정확히 `CLAUDE_CODE_ARTIFACT`인 항목은 없다. 다만 그 표는 이 페이지의 앞쪽 100,000자까지만 읽었다.

공식 아티팩트 문서(code.claude.com/docs/en/artifacts)의 「Availability」 표는 아티팩트가 "Agent SDK, GitHub Action, MCP 서버 맥락, 사용자의 터미널이나 스크립트에서 `-p`로 실행할 때, 그리고 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`가 설정됐을 때" 기본으로 꺼져 있다고 적는다. 즉 **SDK형 세션에서 꺼 두는 것은 문서화된 기본값이다.** 같은 문서는 `/slides`가 Claude Code v2.1.265 이상과 아티팩트를 쓸 수 있는 세션을 요구하고, 조직이 Slides 템플릿을 끄면 `/slides`가 나타나지 않는다고 적는다. 그러나 SDK형 세션에서 아티팩트를 켜는 방법은 적혀 있지 않다.

그러므로 이 예외는 문서화된 기본값을 소스에서 읽은 스위치로 뒤집는 일이다. 원칙 문장은 고치지 않았고, 여기 예외로 남긴다.

원칙 문장은 고치지 않았고, 여기 예외로 남긴다.

## 무엇이 문제였나

사용자가 터미널에서 `claude`를 치고 `/sli`까지 입력하면 슬래시 메뉴에 `/slides`가 뜬다. 플러그인의 채팅 입력창에서는 같은 입력에 `/slides`가 뜨지 않았다. 이슈 #584의 요청이 바로 이것이다.

2026-10-23에 같은 계정(Max), 같은 CLI(2.1.308)를 쓰는 윈도우 노트북에서 재 보니 다음과 같았다.

| 실행 방식 | `/slides` |
|---|---|
| 노트북 터미널에서 `claude` | 메뉴에 있다 |
| 플러그인이 띄우는 `-p --input-format stream-json` | 메뉴에 없다. `initialize` 응답의 명령 71개 중에도 없다 |
| 같은 방식에서 `/slides`를 그대로 보내 본 경우 | CLI가 "이 세션에 설치되어 있지 않다"고 답한다 |

CLI 소스에서 이유를 읽었다. CLI는 세션마다 아티팩트 기능(`Artifact` 도구와 `/slides`, `/design`)을 켤지 정한다. 그 판정 함수는 다음 조건에서 꺼짐 사유 `sdk_default_off`를 돌려준다.

- 환경변수 `CLAUDE_CODE_ARTIFACT`가 켜져 있지 않고
- 환경변수 `CLAUDE_CODE_BRIDGE_CHILD_ARTIFACT`도 켜져 있지 않고
- 세션이 SDK형이다(비대화형으로 분류됐거나, 진입점이 `claude-code-github-action` 또는 `mcp`다)

터미널 REPL은 SDK형이 아니라서 아무것도 설정하지 않아도 켜진다. 우리는 `-p`와 `stream-json`으로 CLI를 띄우므로 SDK형에 걸린다. 그래서 터미널 사용자가 공짜로 받는 `/slides`를, 우리가 CLI를 띄우는 방식 때문에 받지 못했다.

## 선택지

| 방법 | 결과 |
|---|---|
| 아무것도 하지 않는다 | `/slides`가 없다. 이슈가 그대로 남는다 |
| `/slides`를 목록에 우리가 직접 더하고 텍스트로 보낸다(#270의 방식) | 안 된다. CLI가 그 세션에 `/slides`를 등록하지 않았기 때문에 "설치되어 있지 않다"고 답한다 |
| **CLI를 띄울 때 `CLAUDE_CODE_ARTIFACT=1`을 준다** | `/slides`가 목록에 돌아온다. 같은 노트북에서 명령 71개가 74개가 되고 `/slides`가 그 안에 있다 |
| Claude 데스크탑이 `/slides`를 얻는 방식을 따라 한다 | 데스크탑이 무엇으로 얻는지 찾지 못했다. 환경변수 몇 개를 하나씩 넣어 봤지만 재현되지 않았다 |

세 번째 방법으로 만든 배포본을 윈도우 노트북의 샌드박스 IDE(263)에 설치해서 `/slides`가 팔레트 맨 위에 뜨는 것, 보냈을 때 `Artifact` 도구가 돌아 아티팩트가 게시되는 것을 눈으로 확인했다. 마켓에 배포된 v0.34.7에서는 같은 입력에 `/slides`가 없었다.

## 어느 기준으로 예외가 되는가

[README](./README.md)의 세 기준 중 **첫 번째(다른 대안이 없어 불가피한 경우)** 에 해당한다. 확인한 범위 안에서 `/slides`를 GUI에 되돌리는 방법은 이것뿐이었다. 데스크탑이 쓰는 방식은 찾지 못했으므로, 더 나은 대안이 어딘가에 없다고까지는 말하지 못한다.

세 번째 기준(가장 근본적으로 정확한 방법)과도 겹친다. 이 변수는 우리가 만든 통신이 아니라 CLI가 직접 읽는 스위치이고, 켜면 터미널 사용자와 같은 상태가 된다. 새 기능을 얹는 것이 아니라 터미널과의 차이를 없애는 것이다.

판단은 사람이 했다. 2026-10-23 대화에서 개발자(@yhk1038)는 "터미널에서 되는 것 그대로 플러그인 GUI에서도 되어야 한다는 원칙이 모든 원칙에 우선하는 최고 원칙"이라고 말하며 방법을 찾아 되게 하라고 지시했다.

## 위반의 범위를 어떻게 좁혔는가

원칙 2번이 막으려는 것은 **종속**이다. "CLI에선 되는데 GUI만 막히는" 상태가 되는 것. 그래서 이 예외는 종속이 생기지 않는 모양으로만 쓴다.

- **보내는 것은 환경변수 하나뿐이다.** 요청 형식이나 응답 형식을 새로 가정하지 않는다. CLI가 돌려주는 목록과 도구 결과는 편집 없이 그대로 쓴다.
- **사용자가 이미 정한 값이 이긴다.** 우리를 띄운 셸에 `CLAUDE_CODE_ARTIFACT`가 정의돼 있으면(끄기 값인 `0`, `false`, 빈 문자열 포함) 건드리지 않는다. CLI가 그 값을 직접 읽으므로, 터미널에서 끈 사람은 여기서도 꺼진다. 값이 없을 때만 `1`을 채운다.
- **다른 조건은 CLI의 것 그대로다.** 기능 플래그, 구독 종류, 조직 정책은 CLI가 판정한다. CLI가 아티팩트를 주지 않는 계정이면 이 변수를 줘도 `/slides`는 나오지 않는다. 우리가 그 판정을 우회하지 않는다.
- **채팅 CLI와 명령 목록 조회 CLI 둘 다에 준다.** 한쪽에만 주면 한쪽 목록에는 있고 한쪽에는 없는 상태가 된다.
- **변수가 사라져도 망가지지 않는다.** CLI가 이 변수를 더 읽지 않게 되면 `/slides`가 목록에서 빠질 뿐이다. 다른 기능에는 영향이 없다. 이 경우는 이 예외를 철회하는 신호로 읽는다.
- **결과 카드는 문장 형식을 전제하지 않는다.** `Artifact` 도구 카드는 결과 문장에서 `https://claude.ai/artifact/<id>` 모양의 주소를 찾아 링크로 걸고, 못 찾으면 입력의 `url`을 쓴다. 둘 다 없으면 링크를 걸지 않고 결과 문장만 보여 준다.

같은 모양의 선례가 `buildCheckpointingEnv`(#356)다. CLI가 SDK형 세션에서만 꺼 두는 기능을 환경변수로 되살려 터미널과 동등하게 만든다.

## 이 예외가 정당하지 않게 되는 조건

다음 중 하나라도 성립하면 이 예외는 철회하고 공식 경로로 되돌린다.

- 공식 문서나 `claude --help`에 아티팩트를 SDK형 세션에서 켜는 방법이 생기는 경우. 그 방법으로 갈아탄다.
- CLI가 SDK형 세션에도 기본으로 아티팩트를 켜는 경우. 변수가 불필요해진다.
- 이 변수를 주면 터미널에는 없는 동작이 생기는 경우. 동등성이 아니라 새 동작이 된다.

## 문서화된 제한은 그대로 남는다

이 변수는 문서가 정한 사용 조건을 풀지 않는다. 공식 문서가 요구하는 조건은 CLI가 계속 판정한다.

- claude.ai 계정 로그인이 있어야 한다. API 키, 게이트웨이 토큰, 클라우드 공급자 자격증명으로는 게시되지 않는다.
- Amazon Bedrock, Google Cloud, Microsoft Foundry에서는 쓸 수 없다.
- 조직 정책(CMEK, HIPAA, Zero Data Retention)과 Slides 템플릿 설정이 막으면 막힌다.

## 확인하지 못한 것

- 데스크탑이 `/slides`를 얻는 방식. 환경변수 `CLAUDE_CODE_ENTRYPOINT`, 계정·조직 UUID, OAuth 범위, 데스크탑 버전 등을 하나씩 넣어도 재현되지 않았다. 공식 문서는 데스크탑 앱 1.13576.0 이상이 아티팩트를 지원한다고만 적는다.
- 2.1.308 외의 CLI 버전. 이 소스 읽기와 측정은 2.1.308과 2.1.309에서만 했다.
- 구버전 IDE(242)에서의 동작. 신버전 IDE(263)에서만 눈으로 확인했다.
