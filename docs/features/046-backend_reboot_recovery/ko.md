# 재부팅 없이 백엔드 되살리기

플러그인이 뜰 때 `Node.js backend failed to start` 화면이 뜨고, `Retry` 를 아무리 눌러도 같은 화면만 다시 나오는 경우가 있었어요.

IDE 를 껐다 켜도 그대로였고, 결국 **Windows 자체를 재부팅해야** 풀렸습니다.

## 왜 그랬나

플러그인은 실행에 필요한 파일들을 버전별 폴더에 한 번만 풀어놓고, 그 과정이 겹치지 않게 잠금 파일 하나로 순서를 맞춥니다.

그런데 이 잠금을 기다리는 데 제한 시간이 없었어요.

이전에 쓰던 백엔드 프로세스가 안 죽고 남아서 그 잠금을 쥐고 있으면, 새로 시작하는 쪽은 무한정 기다리다가 30초 뒤에 위 화면으로 떨어졌습니다.

Windows 는 실행 중인 프로세스가 붙잡고 있는 파일을 지우거나 덮어쓸 수 없고, 그 프로세스는 IDE 를 닫아도 살아있습니다. 재부팅 말고는 방법이 없었던 이유예요.

## 무엇이 바뀌었나

**첫째, 잠금 파일을 아예 없앴습니다.**

기다리는 시간을 줄이는 대신 잠금 자체를 걷어냈어요.

그 잠금이 막고 있던 건 정확히 하나였습니다. IDE 를 두 개 띄웠을 때 같은 파일을 두 번 푸는 낭비요.
결과가 깨지는 걸 막는 장치가 아니었어요. 그건 임시 폴더에 풀어서 검증한 다음 통째로 옮기는 방식이 이미 하고 있었거든요.

두 번 푸는 낭비를 아끼려고 사용자를 재부팅까지 몰고 갈 이유는 없다고 봤습니다.

이전 버전이 남겨둔 잠금 파일은 다음 실행 때 알아서 지웁니다.

**둘째, 막혔을 때 빠져나갈 버튼이 생겼습니다.**

이전 백엔드가 남아있는 게 감지되면 오류 화면에 설명이 한 줄 붙고, `Retry` 옆에 **`Reboot plugin backend`** 버튼이 함께 뜹니다.

남아있는 게 없으면 이 버튼은 나타나지 않아요. 평소에 보던 화면은 그대로입니다.

## 버튼을 누르면

남아있는 프로세스를 정리하고, 정말 종료됐는지 확인한 다음, 백엔드를 새로 띄웁니다.

**확인이 먼저인 게 중요해요.** 이전 프로세스가 아직 포트를 쥐고 있는데 새로 띄우면 둘이 부딪혀서 같은 문제가 반복되거든요.

그래서 정리에 실패하면 새로 띄우지 않고, 무엇이 남아있는지 화면에 알려줍니다. 이때는 해당 프로세스가 다른 사용자 권한으로 돌고 있거나 보안 프로그램이 막고 있는 경우예요.

## 알아두면 좋은 것

정리 대상은 **이 IDE 가 실제로 쓰던 포트를 붙잡고 있는 프로세스**로만 한정됩니다.

포트를 짐작해서 거기 응답하는 것을 지우지 않아요. 무관한 프로그램을 종료시킬 수 있기 때문입니다. 같은 이유로 이 IDE 자신은 어떤 경우에도 대상이 되지 않습니다.
