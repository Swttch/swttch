# 위로 올려 읽는 동안 화면이 바닥으로 끌려가지 않습니다

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#206](https://github.com/Swttch/swttch/issues/206)

## 제보

한 사용자가 짧게 알려주셨습니다.

> 대화가 실행 중이면 창이 위아래로 스크롤됩니다.

답변이 흘러나오는 동안 화면이 가만히 있지 않는다는 이야기였습니다. 재현 절차가 적혀
있지 않아 처음에는 무엇을 보신 것인지 좁히기 어려웠지만, 코드를 따라가 보니 서로 다른
두 가지 결함이 같은 증상으로 겹쳐 보이고 있었습니다.

## 실제로 벌어지던 일

### 첫째, 도구가 한 번 돌 때마다 화면이 바닥으로 끌려갔습니다

이 화면에는 "사용자가 새 메시지를 보내면 다시 아래를 따라간다"는 규칙이 있습니다. 위로
올려 읽던 중이라도 직접 메시지를 보냈다면 그 답변을 보고 싶은 게 자연스럽기 때문입니다.

문제는 "사용자가 보낸 메시지"를 가려내는 방법이었습니다. Claude Code는 대화 기록을
한 줄씩 쌓는데, **도구 실행 결과도 사용자가 보낸 것과 같은 종류로 기록합니다.** 사람이
읽기 위한 구분이 아니라 대화를 주고받는 형식상의 구분이기 때문입니다.

그래서 화면은 파일을 하나 읽을 때마다, 명령을 하나 실행할 때마다 "사용자가 방금 새
메시지를 보냈다"고 판단했습니다. 그때마다 아래로 따라가기가 다시 켜지면서 화면을 바닥으로
끌어내렸습니다.

실제 대화 기록 40개(엔트리 26,941건)를 세어 보니, 사람이 실제로 보낸 것은 384번인데
화면은 **5,031번** 끌려 내려가고 있었습니다. 92%가 불필요한 동작이었던 셈입니다.
파일을 여러 개 읽거나 명령을 연달아 실행하는 긴 작업일수록 심해졌고, 그래서 "실행 중일 때"
유독 눈에 띄었습니다.

### 둘째, 자동 스크롤이 꺼졌는데 아무 표시가 없었습니다

설정에는 **자동 스크롤 재개 거리**가 있습니다. 바닥에서 이 거리 안쪽이면 화면이 계속
따라가고, 벗어나면 멈춰서 편하게 읽을 수 있게 하는 값입니다.

그런데 이 설정값은 **다시 따라가기 시작하는 판단에만** 쓰이고 있었습니다. **멈추는**
판단은 설정과 무관하게 2픽셀이라는 별도 기준이 따로 쥐고 있었습니다.

두 기준이 다르다 보니 사이에 빈틈이 생겼습니다. 살짝만 위로 올려도 자동 스크롤은 이미
멈추는데, "맨 아래로 스크롤" 버튼은 설정한 거리를 벗어나야 나타나므로 아직 보이지 않았습니다.
자동 스크롤이 꺼졌다는 사실을 알려주는 것이 그 버튼인데, 아무 안내 없이 조용히 멈춰 있던
것입니다. 기본값 80을 쓰는 경우 바닥에서 0~80픽셀 구간 전체가 여기에 해당했습니다.

## 무엇이 바뀌었나

**도구 결과는 더 이상 새 메시지로 세지 않습니다.** 사람이 직접 입력한 것(글, 붙여넣은
이미지)만 전송으로 봅니다. 도구 결과, 대화 압축 요약처럼 Claude Code가 스스로 기록한
항목은 제외합니다. 이제 화면이 바닥으로 돌아가는 횟수는 실제로 메시지를 보낸 횟수와
정확히 같습니다.

**설정한 거리가 유일한 기준이 되었습니다.** 따로 숨어 있던 2픽셀 기준은 없앴습니다.

- 설정한 거리 **안쪽**이면 계속 따라갑니다. 살짝 올려도 다시 바닥으로 내려갑니다.
- 설정한 거리를 **벗어나면** 멈추고, 동시에 "맨 아래로 스크롤" 버튼이 나타납니다.

자동 스크롤이 꺼진 상태와 버튼이 보이는 상태가 항상 같아졌습니다. 화면이 왜 안 따라오는지
모르는 구간이 사라집니다.

설정을 200으로 올리면 200픽셀까지, 30으로 낮추면 30픽셀까지가 "따라가는 범위"가 됩니다.
설정한 값이 그대로 경계가 됩니다.

## 함께 정리한 것

설정 화면의 설명이 옛 동작을 그대로 적고 있었습니다. "위로 스크롤하면 **항상** 일시
정지됩니다"라고 되어 있었는데, 이제는 설정한 거리를 넘어야 멈춥니다. 지원하는 12개
언어 모두에서 문구를 실제 동작에 맞게 고쳤습니다.

## 바뀌지 않은 것

긴 답변이 한 번에 들어와 화면 높이가 갑자기 늘어나는 경우, 사용자는 아무것도 하지 않았는데
바닥이 멀어집니다. 이때는 **계속 따라갑니다**. 사용자가 직접 위로 올렸을 때만 멈춥니다.
이전부터 지켜지던 동작이며 그대로 유지됩니다.
