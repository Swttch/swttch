# 채팅의 파일 참조를 클릭해 해당 라인으로 이동

> Languages: [English](./en.md) · **한국어**
>
> 관련: [#183](https://github.com/Swttch/swttch/issues/183), [#209](https://github.com/Swttch/swttch/issues/209), [#210](https://github.com/Swttch/swttch/pull/210), [#708](https://github.com/Swttch/swttch/issues/708)

## 무엇이 달라졌나

Claude가 답변에서 파일을 가리킬 때 — 코드를 설명하거나, 변경을 리뷰하거나,
버그 위치를 짚어줄 때 — 그 참조를 이제 **클릭할 수 있다**. 클릭하면 JetBrains
에디터에서 해당 파일이 열리고, 참조된 **라인(그리고 컬럼이 있으면 컬럼)**으로
캐럿이 바로 이동한다.

이전에는 이 참조들이 동작하지 않았다. Markdown 파일 링크는 오히려 파일 대신
빈 `localhost:<포트>/…` 브라우저 탭을 여는 문제가 있었다(#209).

## 화면에서 보이는 것

두 종류의 참조가 클릭 가능해진다.

- **Claude가 작성한 Markdown 파일 링크**. 예:
  `[ExampleService.java:120-135](./src/main/java/.../ExampleService.java#L120-L135)`.
  클릭하면 120번째 줄에서 파일이 열린다. 일반 웹 링크(`https://…`)는 그대로
  링크로 남아 브라우저에서 열린다.
- **문장 안에 그대로 쓰인 평문 참조**. 예: `src/example/File.java:10`,
  `src/example/File.java:10:5`(라인 **과 컬럼**), `src/example/File.java#L10-L25`.
  이런 표기를 인식해 동일한 클릭 참조로 바꿔준다.
- **`@` 멘션 칩**(`@src/file.ts#L42`)도 이제 라인을 함께 전달한다. 클릭하면
  파일 최상단이 아니라 42번째 줄로 이동한다.

**"파일 열기 프로그램"** 설정(설정 → General)도 있다. 채팅이 JetBrains IDE에
연결돼 있으면 그 IDE로 고정되고 제품 배지가 표시된다 — 파일은 항상 에디터에서
열린다. IDE가 없는 단독 브라우저에서는 감지된 에디터(또는 직접 지정한 프로그램)를
고를 수 있고, 기본값은 운영체제 기본 열기 프로그램이다.

상대경로는 프로젝트 작업 디렉토리를 기준으로 해석되므로, `./src/x.ts`와
`src/x.ts` 모두 올바른 파일을 연다.

## 경로를 어떻게 써도 열린다

Claude나 CLI가 경로를 어떤 모양으로 쓰든 열린다.

| 쓰인 모양 | 예 |
|-----------|----|
| 문서의 제목을 가리키는 링크(그 제목 줄에서 열림) | `[색인](docs/README.md#3-색인)` |
| 윈도우 경로(구분자 둘 다) | `C:\proj\src\app.ts:2`, `src\app.ts` |
| Git Bash, Cygwin, WSL, WSL 공유 경로 | `/c/proj/a.ts`, `/mnt/c/proj/a.ts`, `\\wsl$\Ubuntu\home\me\a.ts` |
| 홈 경로, `file:` 주소, `vscode://file/…` 링크 | `~/notes/a.md` |
| 어느 언어의 폴더 이름이든 | `数据中心/说明.md`, `문서/설계.md` |
| 대괄호나 괄호를 쓰는 라우트 폴더 | `app/(group)/[id]/page.tsx` |
| 공백이 든 이름(링크 또는 `@"…"` 멘션) | `[메모](docs/my%20file.md)`, `@"docs/my file.md"` |
| 위치와 범위 | `a.ts:10`, `a.ts:10:5`, `a.ts:10-20`, `a.ts#L10C5` |

판정은 디스크에 실제로 있는 것이 한다. 파일 이름의 일부인 `#`이나 `:`은 잘라내지 않는다.

Claude가 방금 만든 파일도, IDE가 스스로 알아채기 전에 바로 IDE 에디터에서 열린다.

클릭한 참조가 디스크에 없는 경로(오래됐거나 잘못된 경로)를 가리키면, 이제
아무 반응 없이 실패하지 않고 "파일을 열 수 없다"는 짧은 토스트로 알려준다.

## 일부러 건드리지 않는 것

평문 인식은 일반 문장을 깨진 링크로 만들지 않도록 **의도적으로 보수적**이다.

- 참조에는 **경로 구분자**(`/` 또는 `\`)가 있고 확장자가 있는 파일 이름으로
  끝나야 한다. 구분자 없는 `App.java:10`이나 `example.com:8080` 같은 호스트는
  링크로 만들지 **않는다**.
- `DOMAIN\john.doe`처럼 역슬래시만 쓴 이름은, 경로처럼 시작하거나 라인이 적혀
  있을 때만 파일로 본다.
- **펜스 코드 블록 안**, **기존 링크 안**, **URL 안**의 내용은 절대 다시 쓰지
  않는다. 인라인 코드는 경로 하나만 담고 있을 때만 링크가 된다.

## 동작 방식

- 참조는 IDE 브릿지의 `openFile(path, line, column)`을 호출하는 클릭 요소로
  렌더링된다. 에디터 컨텍스트·`@` 멘션 기능이 이미 쓰는 바로 그 브릿지라서 새
  백엔드 프로토콜이 필요 없다. 라인·컬럼은 1-based이며, 라인이 없으면 파일
  최상단에서 열린다.
- 채팅을 **IDE 세션에서 브라우저 탭으로 열었을 때**도, 참조를 클릭하면 OS 기본
  앱이 아니라 그 **IDE**에서(해당 라인/컬럼으로) 파일이 열린다. 백엔드가 연결된
  IDE가 있으면 그쪽으로 열기를 라우팅하기 때문이다. IDE가 없는 단독 브라우저는
  기존대로 OS 기본 열기로 폴백한다.
- 평문 참조는 웹뷰 전용 전처리 단계에서 링크로 바뀐다. 스캔 전에 코드 스팬,
  기존 링크, URL을 가려낸 뒤 그 결과를 Markdown 링크 렌더러에 그대로 넘긴다.
  덕분에 두 종류의 참조가 하나의 코드 경로를 공유한다.
- Windows 드라이브 경로(`C:\proj\File.java`)는 Markdown 새니타이즈를 안전하게
  통과해 전달되고, 파일을 열 때 복원된다.

기존 사용자는 플러그인을 업데이트하면 이 기능을 얻는다.
