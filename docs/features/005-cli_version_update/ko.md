# Claude Code CLI 버전 확인 및 업데이트

> 언어: [English](./en.md) · **한국어**
>
> 관련: [PR #150](https://github.com/Swttch/swttch/pull/150)

## 새로운 기능

이제 Claude Code with GUI에서 **설치된 Claude Code CLI 버전**을 확인하고, **설정 → About에서 바로 업데이트**할 수 있습니다. 터미널로 나갈 필요가 없습니다.

핵심은, **설치한 방식 그대로** 업데이트한다는 점입니다. volta로 설치했으면 `volta install`, npm이면 `npm install -g`, 네이티브 설치면 `claude update`, Homebrew·WinGet이면 각자의 업그레이드 명령을 실행합니다. 그래서 **실제로 실행 중인 CLI가 그 자리에서 갱신**되며, 엉뚱한 패키지 매니저로 사본을 하나 더 까는 일이 없습니다.

## 어디에 있나요

- **설정 → About → Claude Code Version** — 현재 버전을 표시하고, 더 최신 버전이 있으면 왼쪽에 **Update** 컨트롤이 나타납니다.
- **슬래시 커맨드 패널 하단** — `Claude Code <버전>` 텍스트를 클릭하면 버전을 다시 조회합니다(About의 새로고침 버튼과 동일). 그 옆의 플러그인 버전은 무관하므로 일반 텍스트로 둡니다.

## 업데이트하기

더 최신 버전이 있으면 버전 옆에 **Update** 컨트롤이 나타납니다.

![Stable/Latest 채널과 상태 아이콘이 표시된 업데이트 드롭다운](../../img/screenshot-cli-update-dropdown.png)

모양은 설치 방식에 따라 달라집니다:

- **npm / pnpm / yarn / volta** → 채널을 고르는 **드롭다운**:
  - **Stable** — 약 일주일 정도 뒤처지며, 큰 회귀가 있는 릴리스는 건너뜁니다.
  - **Latest** — 최신 릴리스.
  - 각 항목은 대상 버전과 아이콘을 보여줍니다: 업그레이드면 **다운로드** 아이콘, 다운그레이드면 **되돌리기(undo)** 아이콘, 이미 설치된 버전이면 **초록 체크**(이 항목은 클릭되지 않습니다).
- **네이티브 설치 / Homebrew / WinGet** → 채널의 최신으로 올려주는 단일 **Update** 버튼(이 방식들은 특정 버전 지정을 받지 않습니다).

실행 전에 확인 창이 뜹니다 — **업데이트는 CLI를 교체하므로 진행 중인 Claude 세션이 중단될 수 있습니다.** 실행하는 동안에는 컨트롤에 스피너가 돕니다. 성공하면 토스트가 뜨고 표시된 버전이 자동으로 갱신됩니다.

![성공 토스트: Claude Code v2.1.197 Updated](../../img/screenshot-cli-update-toast.png)

최신 릴리스에 도달하면 버튼 대신 **Up to date** 표시가 나타납니다.

![Up to date 상태](../../img/screenshot-cli-up-to-date.png)

## Update 버튼이 없을 때

CLI가 **안전한 비대화형 업데이트 경로가 없는** 방식으로 설치된 경우 — 리눅스 시스템 패키지 매니저(`apt`/`dnf`/`apk`, `sudo` 필요)나, 알려진 설치기로 특정할 수 없는 위치 — **Update 컨트롤을 표시하지 않습니다.** 이는 의도된 동작으로, 잘못된 명령을 실행해 사본 설치를 남기느니 아무것도 안 보이는 편이 안전하기 때문입니다. 이런 경우는 설치한 방식대로 업데이트하세요.

## 백그라운드 자동 업데이트

Claude Code는 백그라운드에서 스스로 업데이트하지만, 터미널에서 대화형 `claude` 세션을 실행할 때만 그렇습니다. 플러그인은 CLI를 `claude -p`로 실행하는데, 이 모드에서는 자동 업데이트가 시작되지 않습니다. 그래서 플러그인으로만 쓰는 CLI는 직접 업데이트하기 전까지 같은 버전에 머물러 있었습니다.

이제 백엔드가 대화형 CLI와 같은 일을 하며, 그 방법은 위의 업데이트 버튼을 대신 누르는 것입니다. 백엔드는 업데이트 버튼을 누를 때 정보 화면이 보내는 두 요청을 똑같이 스스로에게 보냅니다. 먼저 설치된 버전과 안정·최신 릴리스를 읽는 요청을 보내고, 이어서 설치할 버전을 담은 업데이트 요청을 보냅니다. 두 요청 모두 클릭과 같은 입구로 들어가므로, 버튼이 업데이트할 수 있는 모든 설치 방식(네이티브 설치기, npm, pnpm, yarn, volta, Homebrew, WinGet)이 같은 명령으로 똑같이 업데이트됩니다.

다음을 모두 만족하면 업데이트합니다.

- Claude Code 자체의 자동 업데이트가 켜져 있을 것(아래 스위치 참고).
- 업데이트 채널의 릴리스가 설치된 버전보다 새로울 것. `stable` 채널보다 앞선 CLI를 뒤로 되돌리지는 않습니다.
- 이 설치 방식에서 업데이트 버튼이 표시될 것.

### 언제 확인하나요

대화형 CLI는 실행될 때 업데이트를 확인하고, 플러그인에서 `claude`가 실행되는 순간은 채팅이 `claude`를 시작할 때입니다. 그래서 백엔드는 시작 직후 한 번, 그리고 채팅이 `claude`를 시작할 때마다 확인하되 30분에 한 번을 넘지 않습니다. 타이머는 없습니다. 아무도 채팅하지 않는 백엔드는 스스로 레지스트리에 접속하거나 업데이트하지 않습니다. 확인은 채팅과 따로 실행되므로 채팅이 확인을 기다리지 않습니다.

### 진행 중인 세션은 중단되지 않습니다

업데이트는 이미 진행 중인 채팅을 멈추지 않습니다. 실행 중인 `claude`는 시작할 때의 버전을 계속 쓰고, 다음 채팅부터 새 버전으로 시작합니다. 열려 있는 탭은 설정 → 정보에 표시되는 버전을 새로 고칩니다.

모든 설치 방식이 `claude`를 실행 파일 하나로 배포하고, macOS와 리눅스에서는 업데이트가 그 파일을 덮어쓰지 않고 새 파일로 교체하기 때문에 이미 실행 중인 프로세스는 영향을 받지 않습니다. Windows는 실행 중인 실행 파일을 교체할 수 없습니다. 그래서 Windows에서 npm, pnpm, yarn, volta, WinGet으로 설치한 CLI는 어느 프로젝트나 터미널에서도 `claude.exe`가 실행되고 있지 않을 때까지 기다렸다가, 그 뒤 첫 확인 때 업데이트합니다. Windows의 네이티브 설치는 `claude update`가 버전마다 따로 설치하므로 기다리지 않습니다.

백엔드는 열린 프로젝트마다 하나씩 실행되므로 한 번에 하나의 백엔드만 업데이트하고, 나머지는 업데이트된 것을 확인하고 건너뜁니다.

### 켜고 끄기, 채널 고르기

설정 → 정보에 **Claude Code 자동 업데이트** 항목이 있고, 스위치와 그 옆의 업데이트 채널로 이루어져 있습니다. 둘 다 플러그인 설정이 아니라 Claude Code 자체의 설정이며, 항목에는 Claude Code 설정임을 나타내는 뱃지가 붙어 있습니다.

- 스위치를 끄면 사용자 설정 파일(`~/.claude/settings.json`, 또는 `CLAUDE_CONFIG_DIR` 아래의 파일)에 `"env": {"DISABLE_AUTOUPDATER": "1"}`을 기록합니다. 켜면 그 키만 지우고 파일의 나머지는 그대로 둡니다.
- 채널은 같은 파일의 `autoUpdatesChannel`입니다. **최신 버전**은 새 릴리스를 나오자마자 받으며, 아무것도 설정하지 않았을 때 Claude Code가 쓰는 값이므로 고르면 키를 지웁니다. **안정 버전**은 한동안 문제없이 쓰인 릴리스를 받습니다. `rc`는 설정에 이미 적혀 있을 때만 목록에 나옵니다. 채널은 자동 업데이트가 켜져 있을 때만 바꿀 수 있습니다.

같은 설정이므로 터미널의 `claude`가 스스로 업데이트하는 방식에도 적용되고, 파일을 직접 고치면 이 항목도 그 내용을 따라갑니다.

스위치가 다루지 않는 곳에서 자동 업데이트를 끄고 있으면, 스위치는 꺼진 채로 바꿀 수 없게 표시되고 마우스를 올리면 설정이 어디서 왔는지 알려줍니다. 셸 프로필 같은 환경 변수, `settings.json`의 `DISABLE_UPDATES`나 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 같은 다른 변수, 관리자가 관리하는 관리형 설정, `~/.claude.json`의 `"autoUpdates": false`가 그 경우입니다. 이 값들은 `claude doctor`와 같은 규칙으로 읽습니다.

`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`는 Claude Code가 답변에 꼭 필요한 통신만 하도록 제한하며, Claude Code의 자동 업데이트도 함께 끕니다. 이 값은 설정 → 일반의 "일반" 구역 맨 아래에 있는 **비필수 통신 차단** 스위치로 따로 다루므로 터미널 없이 끌 수 있습니다. 셸 프로필에서 export한 경우에도, 스위치가 `settings.json`에 빈 값을 기록하면 Claude Code가 그 값을 환경 변수보다 우선해 적용합니다. 자동 업데이트가 이 값 때문에 꺼져 있으면 이곳의 툴팁이 그 스위치를 알려줍니다. 플러그인에서 바꿀 수 없는 것은 관리형 설정뿐입니다.

하지 않는 것:

- 플러그인만의 설정을 따로 두지 않습니다. 셸 프로필에서만 export한 변수는 데스크톱에서 실행한 IDE에 전달되지 않을 수 있습니다. 스위치는 설정 파일에 기록하므로 IDE를 어떻게 실행했든 적용됩니다.
- 프로젝트의 `.claude/settings.json`은 확인하지 않습니다. CLI는 모든 프로젝트가 함께 쓰기 때문입니다.
- 확인이나 업데이트가 실패하면(예: 오프라인) 백엔드 로그에 남기고, 30분이 지난 뒤 채팅이 `claude`를 시작할 때 다시 시도합니다.

## 버전은 어떻게 확인하나요

사용 가능한 버전은 **npm 레지스트리**(`npm view @anthropic-ai/claude-code dist-tags`)에서 가져옵니다. 설치 방식과 무관하게 stable/latest 릴리스 번호의 표준 출처입니다. 이 조회는 About을 열 때 조용히 실행되고, 현재 버전은 `claude --version`으로 확인합니다.

## 참고

- macOS, Linux, WSL, Windows에서 동작하며, 플러그인이 이미 CLI를 실행할 때 쓰는 명령 해석 방식을 그대로 사용합니다.
- 버전은 앱 전체에서 공유되는 단일 값이라, 한 곳에서 새로고침하면 모든 곳에 반영됩니다.

## 설치된 의존성은 시작 시 자동 업데이트

백엔드는 시작할 때 **`@swttch/extend-kit` 의존성**의 설치 여부를 한 번 확인합니다.
설치된 버전보다 최신 릴리스가 있으면 백그라운드에서 업데이트합니다. 이 의존성은
사용량 배터리와 음성 입력 명령을 제공합니다. 플러그인을 자동으로 업데이트하는
기능은 아니며, Claude Code CLI는 위에서 설명한 백그라운드 자동 업데이트를 따릅니다.

한 번도 설치하지 않은 사용자라면 생략합니다. 해당 기능이 필요할 때 기존 사용량 또는
음성 입력 메뉴에서 먼저 설치하세요. 시작 시 확인 때문에 채팅 화면을 기다리게 하지 않습니다.

업데이트는 위에서 설명한 Claude CLI 업데이트의 패키지 관리자 명령 구성과 프로세스
실행 방식을 재사용합니다. 실제로 발견한 의존성의 설치 저장소를 대상으로 합니다.
npm은 해당 저장소의 prefix를 지정하고, pnpm과 Yarn은 보고된 전역 저장소가 일치하는지
확인합니다. 설치 위치가 모호하거나 지원하지 않는 방식이면 다른 위치에 설치하지 않고
자동 업데이트를 생략합니다.

레지스트리에 연결할 수 없거나, 설치 위치를 안전하게 판별할 수 없거나, 업데이트가
실패하면 백엔드 로그에 결과를 남기고 시작을 계속합니다. 자동 확인은 백엔드 시작당
한 번이며 기존 수동 의존성 관리 메뉴도 사용할 수 있습니다. 수동 설치·삭제는 이미
진행 중인 시작 시 업데이트가 끝날 때까지 기다립니다. 업데이트 성공 후 설치된 버전을
다시 읽고 공통 의존성 상태를 갱신하므로, 버전 표시도 실제 사용하는 복사본을 따릅니다.
