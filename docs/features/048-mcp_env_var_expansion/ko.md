# MCP 설정에 적은 `${VAR}`가 이제 실제 값으로 풀립니다

> 언어: [English](./en.md) · **한국어**

## 무엇이 문제였나

`.mcp.json`은 팀이 함께 쓰라고 만든 파일이라 커밋됩니다. 그래서 비밀번호나 접속 문자열을
거기에 직접 적을 수는 없고, 대신 자리표시자를 씁니다.

```json
{
  "mcpServers": {
    "postgres-dev": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "DATABASE_URI", "crystaldba/postgres-mcp:latest"],
      "env": { "DATABASE_URI": "${NEXUS_MCP_DB_URI}" }
    }
  }
}
```

실제 값은 커밋하지 않는 `.claude/settings.local.json`에 둡니다.

터미널에서 `claude`를 쓰면 이 설정은 잘 동작합니다. **그런데 같은 프로젝트를 패널에서 열면
서버가 `${NEXUS_MCP_DB_URI}`라는 글자 그대로를 접속 문자열로 받았습니다.**

더 나빴던 것은 **아무 말도 없었다는 점**입니다. 이런 값을 받아도 서버가 곧장 죽지는 않습니다.
경고 한 줄을 자기 로그에 남기고 그냥 뜨는 서버가 많습니다. 패널에서는 초록색
**Connected**로 보이는데 실제로는 아무 것도 못 하는 상태였고, 화면 어디에도 이유가 없었습니다.

이 문제는 [#364](https://github.com/Swttch/swttch/issues/364)로 제보되었습니다.

## 무엇을 했나

### 값을 18곳에서 찾습니다

자리표시자를 풀 때 아래 순서로 값을 찾습니다. 아래로 갈수록 우선순위가 높아서, 같은 이름이
여러 곳에 있으면 **아래쪽이 이깁니다.**

| | 어디 |
|---|---|
| 1 | 프로세스 환경 변수 |
| 2~9 | 홈의 여덟 곳 — `~/.claude.json`, `~/.claude/.claude.json`, `~/.claude/claude.json`, `~/.mcp.json`, `~/.claude/.mcp.json`, `~/.claude/mcp.json`, `~/.claude/settings.json`, `~/.claude/settings.local.json` |
| 10 | `~/.claude.json` 안의 `projects[<프로젝트 경로>].env` |
| 11~18 | 프로젝트의 여덟 곳 — 2~9와 똑같은 형태를 `<프로젝트>/` 기준으로 |

홈과 프로젝트가 **한 쌍씩 그대로 대칭**이라, 같은 모양의 파일에 값을 두면 어느 쪽에 두든
읽힙니다. 어느 파일에 적어야 하는지 외울 필요가 없습니다.

`CLAUDE_CONFIG_DIR`로 설정 폴더를 옮겨 쓰고 계시다면 그 경로를 따라갑니다.

`${VAR:-기본값}` 형태도 씁니다. 값이 없으면 기본값이 들어가고, 기본값도 없으면 원래 글자를
그대로 남깁니다. 빈 문자열로 바꾸지 않는 이유는, 빈 값은 "설정했는데 비어 있음"처럼 보여서
잘못된 설정을 오히려 감추기 때문입니다.

### 못 찾은 변수는 이름을 알려줍니다

값을 어디에서도 못 찾으면, MCP 서버 상세 화면 위쪽에 노란 띠로 알려줍니다.

```
Missing environment variables: NEXUS_MCP_DB_URI
```

빨간 오류가 아니라 **노란 경고**인 이유는, 그 서버가 대개 살아서 돌고 있기 때문입니다.
죽은 게 아니라 잘못 설정된 것이고, 화면의 상태 배지도 실제로 `Connected`인 경우가 많습니다.

이 확인은 서버 **목록을 불러올 때** 합니다. 변수가 없어서 망가진 서버는 아예 연결되지 못하는
경우가 많은데, 도구 목록은 연결된 서버에만 물어보기 때문입니다. 도구를 불러올 때 확인했다면
정작 알려줘야 할 상황에서 아무 말도 못 했을 것입니다.

### `type`을 안 적은 서버도 도구가 보입니다

`.mcp.json`에서 `type`은 적어도 되고 안 적어도 됩니다. 공식 예시도 `command`·`args`·`env`만
적고, 위에 있는 제보의 설정도 그렇습니다.

**그동안은 `type`을 안 적으면 도구 목록이 비어 있었습니다.** 오류도 없이 비어 있어서, 서버가
도구를 정말 안 가진 것인지 우리가 못 읽은 것인지 구분할 수 없었습니다. 이제 `command`가 있으면
`stdio` 서버로 봅니다.

### 설정 파일이 서로를 지우지 않습니다

`~/.claude/settings.local.json`에 `env` 항목을 하나라도 적으면, `~/.claude/settings.json`에
적어둔 **환경 변수 전체가 사라졌습니다.** 덮어쓰기가 항목 단위가 아니라 블록 단위였기
때문입니다. 이제 항목 단위로 합쳐지므로, 한쪽에 하나를 추가한다고 다른 쪽이 없어지지 않습니다.

설정 파일이 깨졌거나 비어 있을 때(`null` 한 글자만 있는 경우 등) **다른 파일의 설정까지 함께
날아가던 문제**도 함께 고쳤습니다.

## 확인 방법

MCP 서버 상세 화면을 열고 **View tools**를 펼치면 됩니다. 서버가 실제로 받은 설정으로 도구
목록을 가져오므로, 목록이 보이면 값이 제대로 전달된 것입니다.

값이 없으면 위쪽에 노란 경고가 뜨고 어떤 변수인지 이름이 적힙니다.
