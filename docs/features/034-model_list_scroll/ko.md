# 모델이 많아도 목록 끝까지 골라 쓸 수 있습니다

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#314](https://github.com/Swttch/swttch/issues/314)

## 제보

한 사용자가 이렇게 적어주셨습니다.

> 선택 가능한 모델이 16개를 넘으면, 넘치는 모델들이 보이지 않고 스크롤로 내려가
> 선택할 수도 없습니다. PC는 MacBook Pro M4입니다.

그리고 이렇게 요청해주셨습니다.

> 인터페이스 안에서 스크롤이 되게 해주세요.

## 무엇이 문제였나

입력창 아래 모델 이름을 누르면 모델 선택 패널이 뜹니다. 이 패널은 입력창 **위쪽으로**
자라납니다.

그런데 이 패널에는 **높이 제한이 없었습니다.** 모델이 네다섯 개일 때는 문제가 없지만,
직접 연결한 모델 카탈로그처럼 열여섯 개가 넘어가면 패널이 화면 위쪽을 뚫고 계속
자라났습니다.

화면 밖으로 나간 부분은 그릴 곳이 없으니 보이지 않습니다. 그리고 패널에 스크롤도 없어서,
**보이지 않는 모델에는 도달할 방법이 아예 없었습니다.** 목록에는 분명히 있는데 고를 수가
없는 상태였습니다.

## 어떻게 해결했나

패널 높이에 상한을 두고, 그 안에서 목록이 **스크롤되게** 했습니다.

이제 모델이 몇 개든 패널은 화면 안에 들어옵니다. 목록을 위아래로 굴려 마지막 모델까지
내려갈 수 있고, 물론 눌러서 선택도 됩니다.

### 화면이 작으면 패널도 같이 작아집니다

상한을 하나의 고정된 숫자로 박아두면, 창을 작게 쓰는 분들에게는 그 숫자가 여전히 너무
큽니다. 패널이 상단바 아래로 파고들어 자기 머리말을 스스로 가리게 됩니다.

그래서 상한을 **입력창 위에 실제로 남은 공간**에 맞춰 정합니다. 창이 넉넉하면 넉넉한
만큼 열리고, 창이 낮으면 그만큼 줄어들되 목록은 계속 스크롤됩니다. 창 크기를 바꾸면
그때마다 다시 맞춥니다.

### 머리말은 스크롤과 함께 떠내려가지 않습니다

패널 맨 위에는 "모델 선택"이라는 안내와 단축키 표시가 있습니다.

스크롤을 패널 전체에 걸면 목록을 내릴 때 이 머리말도 같이 위로 사라집니다. 그래서
**머리말은 제자리에 두고 목록만 굴러가도록** 나눴습니다. 목록 어디를 보고 있든 여기가
무엇을 고르는 자리인지 계속 보입니다.

### 지금 쓰는 모델이 아래쪽에 있어도 바로 보입니다

목록이 길어지면 새로운 문제가 하나 생깁니다. 지금 사용 중인 모델이 목록 아래쪽에 있으면,
패널을 열었을 때 맨 위만 보이고 **정작 어떤 모델이 켜져 있는지 알 수 없습니다.** 체크
표시가 화면 밖에 있기 때문입니다.

그래서 패널을 열면 **현재 모델이 있는 자리로 목록을 미리 내려둡니다.** 열자마자 체크
표시가 눈에 들어옵니다.

## 만들면서 알게 된 것들

### 옆에 있던 패널은 이미 답을 갖고 있었습니다

같은 자리에 뜨는 패널이 하나 더 있습니다. 슬래시 명령 패널입니다.

두 패널의 코드를 나란히 놓고 보니 **거의 글자 단위로 같았습니다.** 위치를 잡는 방식,
그림자, 테두리, 여백까지 전부 똑같았고 — 딱 두 줄, 높이 상한과 스크롤만 모델 쪽에
빠져 있었습니다.

그래서 새 숫자를 지어내지 않고 슬래시 패널이 쓰던 값(320픽셀)을 그대로 가져왔습니다. 두
패널이 같은 자리에서 같은 크기로 열리는 편이 쓰는 입장에서도 자연스럽습니다.

### 높이 상한만으로는 목록이 줄어들지 않습니다

패널에 높이 상한을 걸고 목록에 스크롤을 준 것만으로는 부족했습니다. 목록이 여전히 상한을
뚫고 나갔습니다.

세로로 쌓는 배치에서 각 칸은 **자기 내용물보다 작아지기를 기본적으로 거부합니다.** 목록은
"내 안에 모델 스무 개가 있으니 나는 이만큼 커야 한다"고 주장하고, 상한은 그 주장에
밀립니다. 줄어들어도 된다고 명시적으로 허락해줘야 비로소 상한 안으로 들어오고 스크롤이
생깁니다.

### 눈으로 보이는 것과 코드가 말하는 것이 달랐습니다

작은 창에서 확인하다가, 패널 머리말이 상단 배너에 가려지는 것을 발견했습니다.

처음에는 패널이 화면 위로 삐져나간 줄 알았습니다. 그런데 실제로 재보니 패널은 화면 안에
얌전히 들어와 있었습니다. 배너가 패널보다 **위에 그려지고** 있었던 것입니다.

패널 쪽 z-index 숫자가 배너보다 훨씬 큰데도 그렇습니다. 이 숫자는 같은 층 안에서만
비교되기 때문에, 서로 다른 층에 속하면 숫자가 커도 소용이 없습니다.

이건 이번 제보(스크롤 불가)와는 별개의 문제이고, 수정 전에도 목록이 길면 똑같이
일어나던 일입니다. **이번 변경에서는 건드리지 않았습니다.**

### 테스트가 무엇을 재고 있는지부터 확인해야 했습니다

스크롤이 걸렸는지 확인하는 테스트를 처음에는 "화면에 계산된 스타일"을 읽는 방식으로
썼습니다. 통과했습니다.

그런데 이 프로젝트의 테스트 환경은 **속도를 위해 스타일 파일을 대부분 비워둡니다.**
그래서 계산된 스타일은 고친 코드에서도, 고치기 전 코드에서도 똑같이 비어 있었습니다.
통과한 게 아니라 **아무것도 재지 않고 있었습니다.**

수정을 일부러 되돌려 테스트가 실제로 실패하는지 확인하고 나서야 이 사실이 드러났습니다.
지금은 계산된 스타일 대신 코드에 붙은 값을 직접 확인하며, 되돌리면 정확히 실패합니다.
