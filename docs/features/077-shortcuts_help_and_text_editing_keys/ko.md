# 단축키 도움말, Control 키 텍스트 편집, 프롬프트의 실행 취소

> 언어: [English](./en.md) · **한국어**

다음 릴리즈에서 키보드에 관한 세 가지가 달라집니다. 세 가지 모두 "채팅 입력창에서 어떤 키가 무슨 일을 하는가?"라는 같은 질문에서 나왔기 때문에 한 문서에 묶었습니다.

1. 지금 사용 중인 컴퓨터에서 실제로 통하는 단축키만 보여 주는 **도움말 창**.
2. macOS에서 **Control 키 텍스트 편집 키**(Ctrl+A, Ctrl+B, Ctrl+F, Ctrl+K 등 Mac의 모든 텍스트 입력란이 알아듣는 키). 지금까지 채팅 입력창에서는 아무 일도 하지 않았습니다([#506](https://github.com/Swttch/swttch/issues/506)).
3. IDE가 아니라 프롬프트에 적용되는 **실행 취소와 다시 실행**([#495](https://github.com/Swttch/swttch/issues/495)).

## 도움말 창

macOS에서는 **Cmd+/**, Windows와 Linux에서는 **Ctrl+/** 를 누르면 채팅 위에 도움말 창이 열립니다.

![macOS의 도움말 창. 닫기 버튼이 있는 "Help" 제목, "Shortcuts" 탭 하나, 그리고 첫 번째 그룹 "GENERAL"이 보입니다. "Open or close this help"(⌘ /), "Open a new chat tab"(⌘ N), "Open settings"(⌘ ,), "Choose the model"(⇧ ⌘ M), "Zoom in"(⌘ +) 같은 행이 있고, 아래쪽에서 다음 그룹 "CHAT INPUT"이 "Send the message" 행으로 시작합니다.](./assets/help-modal-shortcuts.png)

닫는 방법은 네 가지입니다.

- 열 때 누른 키(Cmd+/ 또는 Ctrl+/)를 다시 누릅니다.
- **Esc** 키를 누릅니다.
- 창 오른쪽 위의 **X** 를 누릅니다.
- 창 바깥을 클릭합니다.

명령 팔레트에도 **키보드 단축키** 항목이 있어서 다른 지원 항목 옆에서 열 수 있습니다. 팔레트에서 고르면 창을 열기만 합니다. 이미 열려 있을 때 같은 항목을 한 번 더 골라도 창이 닫히지 않습니다. 창은 단축키, Esc, X, 바깥 클릭으로만 닫힙니다.

창이 열리면 키보드 포커스가 입력란이 아니라 창 자체로 들어가므로, 실수로 누른 키가 프롬프트에 입력되지 않습니다. 창을 닫으면 포커스는 원래 있던 곳으로 돌아갑니다.

### 무엇이 나오는가

지금은 **Shortcuts** 탭 하나만 있습니다. 목록은 그룹으로 나뉘고, 각 행은 키가 하는 일을 설명하는 한 문장과 오른쪽의 키 모양으로 구성됩니다. 조합이 두 개인 행(예: "Move back or forward one character")은 두 조합을 슬래시로 나누어 모두 보여 줍니다.

| 그룹 | 들어 있는 것 |
| --- | --- |
| **General** | 도움말 열기/닫기, 새 채팅 탭 열기, 설정 열기, 모델 고르기, 다음 모델로 바꾸기, 대화 지우기, 열려 있는 동안 세션 목록 새로고침, 확대, 축소, 확대 초기화. JetBrains IDE 안에서는 **Ctrl+Shift+C**("Open Claude Code from the IDE")도 나옵니다. |
| **Chat input** | 메시지 보내기, 줄바꿈, 권한 모드 바꾸기(Shift+Tab), 첫 줄이나 마지막 줄에서 이전/다음 프롬프트 불러오기(위/아래 화살표), 음성 입력 시작과 중지. JetBrains IDE 안에서는 **Alt+K**("Send the editor's file and selected lines to the chat")도 나옵니다. |
| **Text editing** | 줄의 시작이나 끝으로 이동, 글 전체의 시작으로 이동, 글 전체의 끝으로 이동(이 셋은 macOS에서만), 한 단어 앞뒤로 이동. |
| **Edit with Control keys** | 아래에서 설명하는 Control 키 텍스트 편집 키 열네 개. macOS에서만 나옵니다. |

목록은 고정된 그림이 아닙니다. 내 컴퓨터와 내 설정으로 만들어지므로, 나에게 사실인 행만 나옵니다.

- **보내기와 줄바꿈 행에는 내가 정한 키가 나옵니다.** 설정에서 바꿨다면([보내는 키와 줄 바꾸는 키를 직접 고릅니다](../070-composer_send_and_newline_keys/ko.md) 참고) 기본값이 아니라 내가 고른 키가 나옵니다. 한 설정이 Ctrl+Enter와 Cmd+Enter를 함께 묶고 있으면, 내 플랫폼에 맞는 쪽의 이름을 보여 줍니다.
- **음성 입력 행은 음성 입력을 따릅니다.** 음성 입력이 꺼져 있거나 단축키가 없으면 행이 숨겨집니다.
- **IDE 전용 행(Alt+K, Ctrl+Shift+C)은 JetBrains IDE 안에서만 나옵니다.** 브라우저(standalone 모드)에는 해당 키가 없으므로, 아무 일도 하지 않는 키를 설명하는 대신 행을 뺍니다.
- **Windows와 Linux에서는 Text editing 그룹이 더 짧습니다.** 그곳에서는 단어 이동만 들어 있습니다. Home, End, Ctrl+화살표가 이미 모든 텍스트 입력란에서 나머지 일을 하기 때문입니다.
- **JetBrains IDE 안에서는 "Jump to the start of the text"(Cmd+위쪽 화살표)가 빠집니다.** IDE가 페이지보다 먼저 Cmd+위쪽 화살표를 자기 탐색 막대에 쓰기 때문에, 그 환경에서는 약속하지 않습니다.
- **"Edit with Control keys" 그룹은 macOS에서만 나옵니다.**

### 키는 어떻게 그려지는가

macOS에서 보조키는 Mac 키보드에 인쇄된 기호이며 Apple의 순서를 따릅니다. **⌃** Control, **⌥** Option, **⇧** Shift, **⌘** Command 순입니다. Windows와 Linux에서는 **Ctrl**, **Alt** 같은 단어로 나옵니다. 몇몇 키는 모든 플랫폼에서 기호입니다. 화살표(**↑ ↓ ← →**), Shift의 **⇧**, Tab의 **⇥**, 그리고 Enter 화살표입니다. Enter 화살표는 macOS(Return)에서는 **↩**, 다른 플랫폼에서는 **↵** 입니다.

## macOS의 Control 키 텍스트 편집

Mac의 모든 텍스트 입력란은 macOS 자체의 텍스트 키 바인딩에서 온 Control 키 조합들을 알아듣습니다. Ctrl+A는 줄의 시작으로 가고, Ctrl+K는 줄의 끝까지 지우고, Ctrl+Y는 지운 것을 되돌려 놓습니다. 많은 Mac 사용자가 메모 앱, Safari, 터미널에서 생각 없이 누르는 키입니다.

채팅 입력창에서는 이 키들이 아무 일도 하지 않았습니다. JetBrains IDE 안의 채팅은 내장 브라우저에서 돌아가는데, 이 내장 브라우저에는 macOS의 이 바인딩이 전달되지 않습니다. 게다가 IDE가 같은 키 몇 개(Ctrl+T, Ctrl+V 등)를 자기 동작에 묶어 두고 먼저 가로챘습니다. 이것이 [#506](https://github.com/Swttch/swttch/issues/506)입니다.

이제 다른 Mac 텍스트 입력란과 같은 의미로 동작합니다.

![마지막 그룹까지 스크롤한 도움말 창. "EDIT WITH CONTROL KEYS" 그룹에 "The same keys work in every Mac text field." 안내 문구가 있고, "Jump to the start or end of the paragraph"(⌃ A / ⌃ E), "Move back or forward one character"(⌃ B / ⌃ F), "Move up or down one line"(⌃ P / ⌃ N), "Delete the character after or before the caret"(⌃ D / ⌃ H), "Delete to the end of the paragraph"(⌃ K), "Paste what Ctrl+K deleted"(⌃ Y), "Swap the two characters around the caret"(⌃ T), "Open a new line after the caret"(⌃ O), "Move down one screen"(⌃ V), "Scroll to put the caret in the middle"(⌃ L) 행이 있습니다. 그룹 위에는 "Move back or forward one word" 행이 ⌥ ← / ⌥ → 와 함께 보입니다.](./assets/help-modal-control-keys.png)

### 열네 개의 키

| 키 | 하는 일 |
| --- | --- |
| **Ctrl+A** / **Ctrl+E** | 문단의 시작이나 끝으로 이동합니다. 여기서 문단은 줄바꿈과 줄바꿈 사이의 글입니다. |
| **Ctrl+B** / **Ctrl+F** | 한 글자 뒤나 앞으로 이동합니다. 이모지는 한 글자로 셉니다. |
| **Ctrl+P** / **Ctrl+N** | 같은 칸 위치를 유지하며 한 줄 위나 아래로 이동합니다. 채팅 입력창에서 한 줄은 화면에 그려진 한 행이므로, 길어서 접힌 문장은 여러 줄로 셉니다. |
| **Ctrl+V** | 한 화면 아래로 이동합니다. 입력란이 한 번에 보여 주는 행 수만큼(최소 한 행) 캐럿이 내려가고, 입력란은 캐럿이 보이는 데 필요한 만큼만 스크롤됩니다. 한 줄짜리 입력란에서는 끝으로 갑니다. |
| **Ctrl+D** | 캐럿 뒤의 글자를 지웁니다. 글을 선택했다면 선택한 글을 지웁니다. |
| **Ctrl+H** | 캐럿 앞의 글자를 지웁니다. 글을 선택했다면 선택한 글을 지웁니다. |
| **Ctrl+K** | 캐럿에서 문단 끝까지 지우고, 지운 글을 기억해 둡니다(아래 참고). 캐럿이 이미 문단 끝에 있으면 줄바꿈을 지우므로 다음 줄이 이어 붙습니다. 글을 선택했다면 선택한 글만 정확히 지웁니다. 글의 맨 끝에서는 아무 일도 일어나지 않습니다. |
| **Ctrl+Y** | Ctrl+K로 지운 글을 붙여 넣습니다. 선택한 글이 있으면 그 글을 대체합니다. 아직 지운 글이 없으면 아무 일도 일어나지 않습니다. |
| **Ctrl+T** | 캐럿 앞의 글자와 뒤의 글자를 맞바꾸고, 캐럿은 바꾼 두 글자 뒤에 둡니다. 문단 끝에서는 캐럿 앞의 두 글자를 맞바꾸므로, 줄 끝에서 계속 누르면 마지막 오타를 계속 고칠 수 있습니다. 글을 선택했을 때, 문단 시작 근처라서 바꿀 글자가 두 개 없을 때, 바꿀 두 글자 사이에 줄바꿈이 끼어 있을 때는 아무 일도 일어나지 않습니다. |
| **Ctrl+O** | 캐럿 뒤에 새 줄을 엽니다. 줄바꿈이 들어가고 캐럿은 그 앞에 머물므로, 캐럿 뒤의 글이 아래로 내려가는 동안 현재 줄에서 계속 입력할 수 있습니다. 한 줄짜리 입력란에서는 아무 일도 하지 않습니다. |
| **Ctrl+L** | 보이는 영역의 한가운데에 캐럿이 오도록 스크롤합니다. 글은 바꾸지 않습니다. 입력란이 스크롤 영역보다 높지 않으면 아무 일도 하지 않고, 한 줄짜리 입력란에서도 아무 일도 하지 않습니다. |

**Shift를 함께 누르면 선택이 넓어집니다.** Ctrl+A, B, E, F, N, P, V와 Shift를 함께 누르면, 캐럿만 움직이는 대신 캐럿이 있던 자리부터 도착한 자리까지가 선택됩니다. 화살표 키와 Shift를 함께 누를 때와 같습니다. macOS가 선택 확장 변형을 주는 키가 바로 이 일곱 개이고, 나머지 일곱 개에는 주지 않습니다. 그래서 Ctrl+D, H, K, L, O, T, Y와 Shift를 함께 누르면 아무 일도 일어나지 않습니다.

**모든 편집은 실행 취소할 수 있습니다.** 이 키들로 바뀐 글은 입력란의 일반 실행 취소 기록에 들어가므로 Cmd+Z로 되돌릴 수 있습니다(아래 [프롬프트에 적용되는 실행 취소와 다시 실행](#프롬프트에-적용되는-실행-취소와-다시-실행) 참고).

### 킬 링: Ctrl+K가 저장하고 Ctrl+Y가 붙여 넣는다

Ctrl+K로 지운 글은 사라지지 않습니다. **킬 링(kill ring)** 이라는 작은 기억 공간에 들어가고, Ctrl+Y가 그 글을 캐럿 자리에, 또는 선택한 글 위에 다시 붙여 넣습니다.

- **클립보드와는 별개입니다.** Ctrl+K는 마지막으로 Cmd+C로 복사한 내용을 덮어쓰지 않고, Ctrl+Y는 클립보드를 붙여 넣지 않습니다.
- **글 한 덩어리만 담습니다.** 새 삭제를 시작하는 다음 Ctrl+K가 이 덩어리를 대체합니다.
- **앱의 모든 텍스트 입력란이 함께 씁니다.** 채팅 입력창에서 Ctrl+K로 지운 글을 앱의 다른 텍스트 입력란에 Ctrl+Y로 붙여 넣을 수 있습니다. 채팅을 닫거나 새로고침하면 사라집니다.
- **연속한 Ctrl+K는 쌓입니다.** 줄의 시작에서 Ctrl+K를 세 번 누르면, 첫 번째는 그 줄을, 두 번째는 줄바꿈을, 세 번째는 다음 줄을 가져가고, Ctrl+Y 한 번이 셋을 한꺼번에 되돌려 놓습니다. Ctrl+K가 앞의 Ctrl+K를 이어 가는 조건은 그 사이에 아무 일도 없었을 때뿐입니다. 캐럿이 같은 입력란의 같은 자리에 있고, 글이 앞의 삭제가 남긴 그대로이며, 다른 Control 키 텍스트 편집 키를 누르지 않았어야 합니다. 입력하거나, 다른 곳을 클릭하거나, 다른 편집을 하면 다음 Ctrl+K는 새 덩어리로 시작합니다.

### 어디서 동작하는가

macOS에서, 채팅 입력창만이 아니라 앱의 모든 텍스트 입력란에서 동작합니다. 프롬프트와 앱 안의 다른 모든 텍스트 입력란이 대상입니다. 앱이 실행되는 두 환경 모두에서 동작합니다.

- **JetBrains IDE 안에서는** 어떤 입력 소스에서든, 한글 입력기를 포함해서 동작합니다. IDE가 키 입력을 읽어 어떤 키였는지 채팅에 알려 주고, 채팅이 그 동작을 수행합니다.
- **브라우저(standalone 모드)에서 라틴 키보드 배열이면** 브라우저가 다른 웹페이지에서와 똑같이 직접 처리합니다. 비라틴 배열(제보된 경우는 한글 두벌식)에서는 브라우저가 스스로는 아무것도 하지 않으므로, 앱이 어느 물리 키를 눌렀는지 읽어서 대신 수행합니다. 브라우저가 이미 처리했을 키에서는 앱이 비켜서므로 같은 동작이 두 번 적용되지 않습니다.

텍스트 입력란에 포커스가 없으면 아무 일도 하지 않습니다. 브라우저에서 입력기가 글자를 조합하는 중(예: 완성되지 않은 한글 음절)일 때 누른 키는 무시됩니다.

### 하지 않는 것과 달라지는 것

- **macOS 전용입니다.** Windows와 Linux에서 Ctrl+A, Ctrl+B 등은 원래 그 환경에서 하던 일(모두 선택, 굵게 등)을 그대로 하며, 바뀐 것은 없습니다.
- **일반 텍스트 상자에서 "줄"은 줄바꿈으로 나뉜 줄입니다.** 채팅 입력창에서 Ctrl+P와 Ctrl+N은 화면에 그려진 행 단위로 움직입니다. 여러 줄짜리 일반 텍스트 상자(`textarea`)에서는 긴 줄이 어디서 접히는지 앱이 읽을 수 없으므로, 그곳의 "줄"은 줄바꿈과 줄바꿈 사이이고 Ctrl+P와 Ctrl+N은 그 줄들 사이를 움직입니다. Ctrl+V의 "한 화면"도 같고, Ctrl+L도 줄바꿈 기준으로 가운데를 맞추므로 위쪽 글이 접혀 있으면 캐럿보다 조금 위에 맞춰질 수 있습니다.
- **IDE에서는 채팅에 포커스가 있는 동안 이 키들에 묶인 IDE 자체 동작이 실행되지 않습니다.** IntelliJ의 macOS 키맵은 Ctrl+T를 "Refactor This"에, Ctrl+V를 VCS 팝업에 씁니다. Claude Code 패널에 포커스가 있는 동안 이 키 입력은 채팅의 것이 되며, Shift를 함께 누른 경우까지 같은 열네 글자가 해당됩니다. 텍스트 입력란에 포커스가 없어도 마찬가지로, 키는 가져가진 채 무시됩니다. 에디터나 다른 IDE 패널을 먼저 클릭하면 IDE 자체 키는 전과 같이 동작합니다.
- **macOS에서 Ctrl+N은 더 이상 새 채팅 탭을 열지 않습니다.** macOS에서 새 채팅 탭은 **Cmd+N** 이며 IDE에서도 브라우저에서도 그대로 동작합니다. Windows와 Linux에서는 **Ctrl+N** 이 전과 같이 새 채팅 탭을 엽니다.

## 프롬프트에 적용되는 실행 취소와 다시 실행

[#495](https://github.com/Swttch/swttch/issues/495): JetBrains IDE에서 프롬프트를 입력하다가 Cmd+Z(macOS)나 Ctrl+Z(Windows, Linux)를 누르면 엉뚱한 것이 취소될 수 있었습니다. IDE에는 자체 실행 취소 기록이 있고, 프로젝트 뷰에서 방금 옮긴 파일처럼 IDE 자신의 변경이 기록에 있으면 키가 먼저 IDE로 가서 파일 이동을 취소하겠냐고 물었습니다. 프롬프트는 키를 받지 못했습니다.

이제 **채팅 입력창에 포커스가 있는 동안 실행 취소는 그 입력란의 마지막 글 변경을 취소합니다.**

| | macOS | Windows, Linux |
| --- | --- | --- |
| **실행 취소** | Cmd+Z | Ctrl+Z |
| **다시 실행** | Cmd+Shift+Z | Ctrl+Shift+Z 또는 Ctrl+Y |

실행 취소와 다시 실행은 입력란이 내가 입력한 글에 대해 쌓아 두는 기록과 같은 기록을 따라가므로, Control 키 텍스트 편집 키로 한 편집과 자동완성이 넣은 멘션이나 명령도 함께 되돌립니다.

알아 둘 점입니다.

- **텍스트 입력란에 포커스가 없으면 키는 아무 일도 하지 않습니다.** Claude Code 패널에 포커스가 있어도 커서가 텍스트 입력란에 있지 않으면(예: 메시지 위를 클릭했을 때) Cmd+Z는 채팅에서도 IDE에서도 아무것도 취소하지 않습니다.
- **채팅에 포커스가 있는 동안에는 이 키로 IDE 자체의 실행 취소에 닿을 수 없습니다.** 이것이 이번 변경의 목적이자 대가입니다. 파일 이동이나 에디터 변경을 취소하려면 먼저 에디터나 다른 IDE 패널로 포커스를 옮긴 뒤 그곳에서 키를 누르세요.
- **Ctrl+Y는 Windows와 Linux에서만 다시 실행입니다.** macOS에서 Ctrl+Y는 위에서 설명한 "Ctrl+K로 지운 글 붙여 넣기" 키이고, macOS 키맵에서 Cmd+Y는 다시 실행이 아닙니다.
- **브라우저(standalone 모드)에서는 바뀐 것이 없습니다.** 그곳에서는 브라우저가 실행 취소와 다시 실행을 직접 처리합니다.
- **도움말 창에는 실행 취소와 다시 실행이 나오지 않습니다.** 이 앱만의 단축키가 아니라 모든 텍스트 입력란의 표준 키이기 때문입니다.

## 한눈에 보기

| 하고 싶은 일 | macOS | Windows, Linux |
| --- | --- | --- |
| 모든 단축키 보기 | Cmd+/ | Ctrl+/ |
| 단축키 목록 닫기 | Cmd+/, Esc, X, 바깥 클릭 | Ctrl+/, Esc, X, 바깥 클릭 |
| 새 채팅 탭 열기 | Cmd+N | Ctrl+N |
| 프롬프트에서 실행 취소 | Cmd+Z | Ctrl+Z |
| 프롬프트에서 다시 실행 | Cmd+Shift+Z | Ctrl+Shift+Z, Ctrl+Y |
| Control 키로 이동하고 편집하기 | Ctrl+A B D E F H K L N O P T V Y (이동 키는 Shift로 선택 확장) | 없음 |
