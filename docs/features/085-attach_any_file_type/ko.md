# 어떤 파일이든 첨부하기: 끌어다 놓기, 붙여넣기, 고르기, 미리보기, 순서 바꾸기

> 언어: [English](./en.md) · **한국어**
>
> 관련: [컨텍스트 뱃지와 + 메뉴](../083-context_badge_and_add_menu/ko.md)

## 새로워진 점

첨부에는 불편한 점이 여럿 있었습니다. 브라우저에서는 그림만 끌어다 놓거나 붙여넣을 수 있었고, **+** 메뉴에서 파일을 고르는 데 30초가 넘게 걸리면 아무 안내 없이 첨부가 사라졌으며, 모든 첨부가 똑같이 생겼습니다. 이번 릴리즈에서 이것들이 모두 바뀝니다.

- 끌어다 놓기, 붙여넣기, 고르기 어느 쪽으로든 **어떤 종류의 파일이든** 첨부할 수 있습니다. 브라우저에서도, IDE에서도 같습니다.
- 브라우저에도 **폴더**를 끌어다 놓을 수 있습니다.
- 파일이 앱으로 올라가는 동안 칩이 **얼마나 갔는지** 보여 줍니다.
- 칩마다 **파일 종류의 아이콘**이 붙고, 카드에는 텍스트, 그림, 영상의 **미리보기**가 나옵니다.
- 이름에 마우스를 올리면 툴팁에 **전체 이름, 크기, 경로**가 나옵니다. 글자를 골라 복사할 수 있습니다.
- 칩을 **끌어서** 첨부의 순서를 바꿀 수 있습니다.

## 첨부하는 세 가지 방법

| 방법 | 브라우저 | JetBrains IDE |
|------|----------|---------------|
| **+ 메뉴 → 파일 또는 사진 추가 / 폴더 추가** | 시스템 선택창이 열립니다. **시간 제한이 없으니** 언제 골라도 됩니다. | 같습니다. |
| **파일 관리자에서 끌어다 놓기** | 어떤 파일이든, 어떤 폴더든 됩니다. | 어떤 파일이든, 어떤 폴더든 됩니다. IDE가 실제 경로를 넘겨줍니다. |
| **붙여넣기** (파일 관리자에서 파일을 복사한 뒤 붙여넣기) | 어떤 파일이든 됩니다. | 그림만 됩니다. 그 밖의 파일은 IDE가 붙여넣기를 가져갑니다. |

**png, jpeg, gif, webp** 그림을 끌어다 놓거나 붙여넣으면 지금까지처럼 **10 MB까지는 인라인**으로 첨부됩니다. Claude가 그림 자체를 받습니다. 10 MB를 넘으면 "파일이 너무 큽니다"가 뜨고, 그 밖의 종류(svg, heic, bmp 등)는 보통 파일 칩이 됩니다.

### 브라우저가 사본을 만드는 이유

브라우저는 끌어다 놓은 파일이 디스크 어디에 있는지 웹 페이지에 절대 알려 주지 않습니다. 그래서 앱이 "그 경로의 파일"을 첨부할 수 없습니다. 대신 파일을 조각으로 나눠 앱에 보내고, 아래 위치에 **사본으로 저장**합니다.

```
~/.claude-code-gui/uploads/<무작위 id>/<파일 이름>
```

폴더를 놓으면 모양이 그대로 유지됩니다: `…/<무작위 id>/<폴더>/<하위 폴더>/<파일>`. `CCG_HOME`을 지정해 두었다면 사본은 `$CCG_HOME/uploads`에 저장됩니다.

칩은 사본을 가리키므로 Claude도 사본을 읽습니다. 그래서 다음과 같습니다.

- **원본은 건드리지 않고**, 이후에 원본을 고쳐도 사본에는 **반영되지 않습니다.** 고쳤다면 다시 끌어다 놓으세요.
- **크기 제한은 없습니다.** 다만 큰 파일은 보내는 데 시간이 걸립니다.
- **7일이 지난 사본은 지워집니다.** 다음에 업로드가 시작될 때 지우고, 폴더의 나이는 마지막으로 바뀐 시각을 기준으로 합니다. 칩을 지워도 사본이 바로 지워지지는 않고, 이 정리 때 지워집니다.
- JetBrains IDE에서는 사본을 만들지 않습니다. IDE가 이미 실제 경로를 알기 때문입니다.

## 파일이 올라가는 동안

아직 보내는 중인 파일은 자기만의 칩이 있고, 칩 **아래 가장자리에 막대**가 차오르며 이름 옆에 **퍼센트**가 나옵니다.

![칩 두 개가 있는 입력창. 첫 번째 "release-notes.md"는 첨부가 끝난 상태이고, 두 번째 "project-backup.zip 47%"는 아래 가장자리의 절반쯤을 파란 막대가 채우고 있다. 보내기 버튼은 흐리게 보인다.](./assets/attachment-uploading.png)

- 폴더는 **하나의 전송**으로 세고, 안에 있는 모든 파일의 합계 크기를 기준으로 합니다.
- 올라가는 중인 칩의 **×**는 **업로드를 멈추고** 칩을 지웁니다. 직접 고르신 일이라 오류로 알리지 않습니다.
- 모든 업로드가 끝날 때까지 **보내기 버튼이 흐려지고 Enter가 동작하지 않습니다.** 아직 경로가 없는 파일은 메시지에서 빠지기 때문입니다.
- 업로드가 실패하면 칩 아래 짧은 한 줄이 어느 파일인지 알려 줍니다.

## 칩의 모양

### 좁은 칩

줄에 그림이 없으면 첨부는 **좁은 칩**입니다. 칩마다 **파일 종류의 아이콘**이 있어서, 여러 종류가 섞여 있어도 한눈에 구분됩니다.

![좁은 칩 여섯 개가 있는 입력창: release-notes.md, build.gradle.kts, q3-report.pdf, budget.xlsx, archive.zip, gradlew. 칩마다 자기 아이콘이 붙어 있다.](./assets/attachment-chips.png)

### 카드

줄에 **그림** 하나가 들어오면 줄의 높이가 썸네일만큼 커지고, 그 옆의 얇은 칩은 어색해 보입니다. 그래서 폴더와 올라가는 중인 업로드를 포함한 나머지 첨부가 모두 **같은 정사각 모양**이 됩니다.

![문장 아래에 정사각 카드 여덟 개가 있는 입력창. 첫 번째는 그림이다. 다음 세 개는 텍스트 미리보기, 영상의 한 장면, 로그 미리보기를 보여 준다. 나머지는 아이콘만 있다: PDF, 스프레드시트, 코틀린 빌드 파일, 확장자 없는 스크립트.](./assets/attachment-cards.png)

카드에는 파일의 **아이콘 또는 미리보기**가 나옵니다.

| 파일의 종류 | 카드에 나오는 것 |
|-------------|------------------|
| 아래 목록의 텍스트 | **앞 12줄**(줄마다 40자까지)을 작은 종이처럼 보여 줍니다 |
| 브라우저가 그릴 수 있는 그림: svg, bmp, ico, avif, 그리고 경로로 첨부한 png, jpeg, gif, webp | 그림. **2 MB**까지 |
| 영상: mov, mp4, m4v, webm | **처음 부분의 한 장면**. **32 MB**까지, 그리고 브라우저가 그 영상을 재생할 수 있을 때만 |
| 그 밖의 모든 것, 위 크기를 넘는 것 | 파일 종류의 아이콘 |

텍스트 미리보기는 아래 목록에 있는 이름에만 나옵니다: `txt md markdown mdx log json jsonc csv tsv patch diff xml html htm css scss yml yaml toml ini conf env properties sql js mjs cjs jsx ts tsx py rb go rs java kt swift c h cc cpp hpp cs php sh bash zsh`. 목록에 있는 이름인데 내용이 텍스트가 아니면 아이콘이 나옵니다. **`build.gradle.kts`, `gradlew`(확장자 없음), `.bat` 같은 파일은 텍스트이지만 일부러 아이콘으로 둡니다.** 파인더가 미리보기를 모르는 종류에는 아이콘을 보여 주는 것과 같습니다. 64픽셀 크기에서는 그 파일들의 첫 줄이 정보가 아니라 잡음이기 때문입니다.

미리보기가 나오는 카드는 **왼쪽 위**에 파일의 작은 아이콘이, **오른쪽 아래**에 **확장자**가 붙습니다.

카드 아래 이름은 썸네일처럼 잘려 보입니다. 전체 이름은 마우스를 올리면 나옵니다.

### 어떤 아이콘이 나오나

아이콘은 파일의 **확장자**를 따릅니다.

- **직접 그린 아이콘**은 어디서나 같습니다. 쪽지 위에 종류를 말해 주는 기호가 있고(영상은 재생 삼각형, 오디오는 음표, 코드는 `</>`, 스프레드시트는 표, 압축은 지퍼, 그림은 산, 문서와 텍스트는 줄), 종류마다 색이 다릅니다. 종류를 모르는 파일은 기호 없는 쪽지입니다.
- **시스템의 진짜 아이콘**은 운영체제가 줄 수 있을 때 대신 쓰입니다. 그러면 칩이 컴퓨터 어디서나 보는 그 파일의 모습과 같아집니다.

| 시스템 | 아이콘을 얻는 곳 |
|--------|------------------|
| macOS | 파인더가 그 종류에 쓰는 아이콘(`NSWorkspace`) |
| Windows | 탐색기가 그 종류에 쓰는 아이콘(`SHGetFileInfo`, 32픽셀) |
| Linux | 공유 MIME 데이터베이스가 종류를 정하고, 종류가 아이콘 이름을 정하고, **아이콘 테마**가 그림을 가지고 있습니다. MIME 데이터베이스나 테마가 없는 컴퓨터는 직접 그린 아이콘을 유지합니다. |

한 확장자를 처음 볼 때는 아이콘이 도착하는 데 **1초 남짓** 걸릴 수 있고(시험에서 macOS는 약 0.5~1.6초, Windows는 약 0.4~1초), 그동안은 직접 그린 아이콘이 보입니다. 한 번 받은 아이콘은 앱이 실행되는 동안 기억합니다. 아이콘은 **시스템이 그 종류를 어떤 앱으로 여는지**에 따라 달라서, 같은 `.kts`가 한 컴퓨터에서는 IntelliJ 아이콘이고 다른 컴퓨터에서는 그냥 쪽지일 수 있습니다.

## 툴팁

칩의 이름에 마우스를 올리면 툴팁에 **전체 이름**이 나오고, 같은 줄의 **오른쪽 끝에 크기**가, 그 아래에 **경로**가 나옵니다.

![그림 카드의 이름 위에 마우스가 있다. 그 위에 뜬 툴팁에 "dashboard-mockup.png"와 오른쪽 끝의 "43.9KB"가 보인다.](./assets/attachment-tooltip.png)

- 크기는 파인더가 쓰는 방식으로 적습니다. 1000 단위, 유효숫자 세 자리, 단위 앞에 공백 없음입니다(**25KB**, **12.7MB**, **1.46GB**).
- **폴더는 크기를 말하지 않습니다.** 안의 모든 것을 읽어야 하기 때문입니다.
- 인라인으로 첨부한 그림은 **경로가 없어서** 툴팁에 이름과 크기만 나옵니다.
- **글자를 골라 복사할 수 있습니다.** 위에서 마우스를 누른 채 끌면 됩니다. 버튼을 누르고 있는 동안에는 마우스가 툴팁 밖으로 나가도 툴팁이 열려 있고, 툴팁 밖에서 버튼을 놓으면 닫힙니다.

## 첨부 순서 바꾸기

**칩이나 카드를 끌어서** 줄의 다른 자리에 놓으세요. 다른 것들이 비켜나고 새 순서가 유지됩니다.

![끌고 있는 도중의 입력창. 텍스트 미리보기가 있는 "release-notes" 카드를 들어서 다섯 번째 자리로 옮겼고, 지나온 카드들은 왼쪽으로 밀려 있다.](./assets/attachment-reorder.png)

- **×**를 누르는 것은 절대 드래그가 시작되지 않고, 거의 움직이지 않은 클릭은 그대로 클릭이어서, 칩 지우기와 그림 열어 보기는 예전처럼 동작합니다.
- **아직 올라가는 중인** 칩은 옮길 수 없습니다. 아직 첨부가 아니기 때문입니다.
- 첨부가 하나뿐이면 옮길 곳이 없어서 드래그할 수 있다는 표시가 나오지 않습니다.

### 순서가 메시지에 미치는 영향

Claude는 **파일과 폴더의 경로를 정하신 순서대로** 받고, **그림도 정하신 순서대로** 받습니다. 그림과 파일 사이의 순서는 정할 수 없습니다. 줄에서의 자리와 관계없이 그림은 문장 뒤에, 경로는 문장 앞에 놓이기 때문입니다.

## 한계

- 브라우저에서 만든 사본은 **그 시점의 모습**입니다. 원본을 고쳤다면 다시 첨부해야 합니다.
- **빈 폴더**를 브라우저에 놓으면 복사할 것이 없어서 실패하고, 칩 아래 한 줄이 그 폴더를 알려 줍니다. 폴더 안의 빈 하위 폴더는 유지되지 않습니다.
- **아주 큰 폴더**(예를 들어 `node_modules`)는 파일을 하나씩 보내므로 그만큼 오래 걸립니다. 칩의 **×**로 멈출 수 있습니다.
- **폴더** 붙여넣기는 브라우저가 폴더를 넘겨주는 환경에서만 됩니다. 넘겨주지 않으면 칩 아래 한 줄이 그 폴더를 알려 줍니다.
- 브라우저가 재생하지 못하는 영상, 2 MB를 넘는 그림, 32 MB를 넘는 영상은 아이콘으로 남습니다. 첨부는 되고 미리보기만 없는 것입니다.
- Linux에서 시스템 아이콘은 컴퓨터에 공유 MIME 데이터베이스와 아이콘 테마가 있을 때만 쓰입니다. 어떤 데스크톱은 `.ts`를 Qt 번역 파일로 알고 있어서 그 아이콘이 일반 텍스트 아이콘일 수 있습니다.
- Windows의 시스템 아이콘은 32픽셀이어서 고해상도 화면에서는 조금 흐릿하게 보일 수 있습니다.
- 파일의 종류는 **이름**으로만 판단하고 파일을 열어 보지 않습니다. `.txt`로 이름을 바꾼 PDF는 텍스트 아이콘이 나오고, 내용이 텍스트가 아니라서 미리보기는 없습니다.

## 자주 묻는 질문

**+ 메뉴에서 파일을 골랐는데 아무것도 안 생겼어요.** 이번 릴리즈 전에는 선택창이 30초 뒤에 포기했습니다. 이제는 그렇지 않습니다. 지금도 아무것도 안 생겼다면, 선택창이 열려 있는 동안 백엔드와의 연결이 끊긴 것입니다. 그 뒤에는 선택창의 답이 도착할 수 없으니 다시 첨부해 주세요.

**파일을 첨부하고 1초쯤 뒤에 아이콘이 바뀌었어요.** 시스템의 진짜 아이콘이 도착한 것입니다. 그때까지는 직접 그린 아이콘이 대신 보입니다.

**제 `.kts` / `.gradle` 파일은 왜 미리보기가 없나요?** 위의 텍스트 미리보기 목록을 보세요. 이 파일들은 일부러 아이콘으로 보여 줍니다.

**보내기 버튼이 흐려요.** 파일이 아직 올라가는 중입니다. 기다리거나 그 칩의 **×**를 누르세요.

**끌어다 놓은 파일은 어디에 있나요?** `~/.claude-code-gui/uploads/` 아래에 놓을 때마다 폴더 하나씩 있습니다. 7일 뒤 다음 업로드가 시작될 때 정리됩니다.
