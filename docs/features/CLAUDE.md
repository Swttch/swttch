# 기능 문서 색인 (Feature Docs Index)

이 폴더는 사용자를 독자로 한 **기능 설명서**들을 모아둔다. 작성 규칙은 [docs/CLAUDE.md](../CLAUDE.md)를 따른다.

각 기능은 `NNN-feature_name/` 폴더로 관리하며, 폴더 안에 언어별 번역본(`en.md`, `ko.md`, …)을 둔다.

Markdown 파일 링크, 문장 속 평문 `path:line`/`:line:col`/`#L…` 표기, `@` 멘션 칩의 라인 이동을 포함. 코드/기존 링크/URL·슬래시 없는 토큰·라인 없는 언급은 보수적으로 제외 ([#183](https://github.com/Swttch/swttch/issues/183), [#209](https://github.com/Swttch/swttch/issues/209), [#210](https://github.com/Swttch/swttch/pull/210))

GitHub Desktop 방식을 참고해 macOS 번들 ID(Spotlight 꺼져도 동작)·Windows 레지스트리·Linux PATH로 감지하고, 시스템 기본·직접 지정(경로+`%TARGET_PATH%` 인자)을 지원. 설정을 CLI 탭으로 이동, 터미널 감지도 같은 엔진으로 통합 리팩토링, 설정 저장을 원자화 ([#213](https://github.com/Swttch/swttch/issues/213), [#214](https://github.com/Swttch/swttch/pull/214))

Scheduled Messages 엔진 위에 만들어져 리셋 시각에 "continue"를 예약하고, 백엔드 게이트가 전송 직전 사용량을 재확인(5초 폴링·최대 10분, 네트워크 오류 시 사람이 읽을 수 있는 사유로 중단)해 실제 충전된 뒤에만 발사한다. 한도 배너의 예약/즉시 재개 버튼, 설정 → General의 기본값 토글(세션별 오버라이드 가능)을 제공하며, 리셋 시각은 CLI 한도 안내 문구에서 직접 파싱(공식/미문서 API 비의존) (`feat/auto-resume-on-limit-reset` 브랜치)
- [Models you connect yourself now show by their own name](./021-custom_model_catalog_display/en.md) — Opus/Sonnet/Haiku 자리에 직접 연결한 모델(`ANTHROPIC_DEFAULT_*_MODEL`)을 쓸 때, 대화를 시작하면 입력창 아래 표시와 모델 선택 패널이 **Default** 로 되돌아가고 그 자리에 들어간 긴 문장이 줄을 두 줄로 무너뜨리던 문제를 수정. 근본 원인은 이름을 못 알아본 것이 아니라 **"못 알아봤다"를 "기본값이다"로 단정**해 사용자 선택을 버린 것 — 이제 식별에 실패하면 폴백하지 않고 **기존 선택을 그대로 유지**한다(다음 요청도 그 모델로 나감). 이름 형태에 의존하지 않는 규칙이라 GLM 외 임의 커스텀 모델에도 대응. 부수적으로 식별 성공률도 높임(설명의 `Custom Haiku model` 활용, 접미사·대소문자 흡수)하고, 끝내 모르는 모델은 Default 인 척하지 않고 원본 값 그대로 표시. 입력창 아래 줄은 좁은 폭에서도 한 줄 유지 + 말줄임(권한·사용량 표시 포함) ([#217](https://github.com/Swttch/swttch/issues/217), [#202](https://github.com/Swttch/swttch/issues/202))
- [@ file mentions now work inside slash commands](./020-mention_inside_slash_command/en.md) — 슬래시 명령을 입력하는 중에 `@` 를 쳐도 파일 선택 목록이 뜨지 않던 문제를 수정. 슬래시 패널과 파일 목록이 입력창 위 같은 자리를 공유하는데 판단 기준이 "줄이 `/` 로 시작하나"뿐이라, 검색이 끝난 목록이 패널에 계속 가려져 있었다(바깥을 클릭하면 잠깐 보였다가 다음 글자에 다시 가려짐). 기준을 "커서가 `@토큰` 안에 있나"로 바꿔 두 기능이 자리를 나눠 쓰게 했고, 파일 선택 후 슬래시 패널 복귀·커서 되돌림 시 목록 재표시·이메일 주소 오작동 방지를 함께 정리. 스킬 전용 문제가 아니라 모든 슬래시 명령에 해당 ([#236](https://github.com/Swttch/swttch/issues/236))

- [The view stays where you put it while you read](./023-auto_scroll_stays_put/en.md) — 답변이 흘러나오는 동안 위로 올려 읽고 있어도 화면이 자꾸 바닥으로 끌려 내려가던 문제를 수정. 원인은 두 가지였다. 첫째, "사용자가 새 메시지를 보냈나"를 대화 기록의 종류만으로 판단했는데 **도구 실행 결과도 사용자 메시지와 같은 종류로 기록**되기 때문에 파일을 읽거나 명령을 실행할 때마다 아래 따라가기가 다시 켜졌다(실제 대화 40개·26,941건 기준 384번 보냈는데 5,031번 끌려 내려감 — 92%가 불필요). 이제 사람이 직접 입력한 것(글·붙여넣은 이미지)만 전송으로 세고, 도구 결과·압축 요약 등 CLI가 스스로 기록한 항목은 제외한다. 둘째, **자동 스크롤 재개 거리** 설정이 "다시 따라가기" 판단에만 쓰이고 "멈추기"는 설정과 무관한 2픽셀 기준이 따로 쥐고 있어, 살짝만 올려도 자동 스크롤은 꺼졌는데 "맨 아래로 스크롤" 버튼은 안 뜨는 구간(기본값에서 0~80px)이 있었다. 이제 설정값 하나가 멈춤·재개 양쪽의 유일한 경계이며, 자동 스크롤이 꺼진 상태와 버튼이 보이는 상태가 항상 일치한다. 옛 동작을 적고 있던 설정 설명 문구도 12개 언어 전부 수정 ([#206](https://github.com/Swttch/swttch/issues/206))

CLI가 같은 일을 하는 요청은 직접 받아주므로, 이미 CLI를 제어하는 데 쓰던 통로로 그 요청을 보내 터미널과 같은 동작을 하게 했다(전달 실패 시 평문 전송으로 폴백해 CLI의 설명이라도 받게 함). `/reload-plugins` 는 활성 플러그인·실패 개수를 보고하고 명령 목록을 새로 읽어 새 명령·에이전트를 곧바로 쓸 수 있게 하며, `/btw` 는 대화를 건드리지 않고 곁가지 질문에 답한다.
