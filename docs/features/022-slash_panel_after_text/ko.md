# 문장을 쓰다가 `/` 를 쳐도 명령 패널이 열립니다

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#244](https://github.com/yhk1038/claude-code-gui-jetbrains/issues/244)

## 제보

한 사용자가 두 가지를 나란히 알려주셨습니다. 하나는 "이건 잘 된다", 다른 하나는
"이건 다르다"였습니다.

> 아무것도 입력하지 않은 상태에서 바로 `/` 를 치면 스킬을 부를 수 있습니다. 다만
> 스킬을 고르면 그대로 전송되더군요. 이건 VS Code 확장과 동일합니다.
>
> 그런데 내용을 입력한 뒤에 `/` 를 치면, 스킬을 직접 지정하거나 Claude Code 본래
> 기능을 부르는 창이 아예 뜨지 않습니다. 이건 VS Code 확장과 다릅니다.

앞의 것은 확인이었고, 뒤의 것이 제보였습니다. 그리고 두 관찰은 사실 같은 코드의
양면이었습니다.

## 실제로 벌어지던 일

명령 패널은 자기가 열려야 할지를 딱 한 가지로 판단했습니다.
**"입력창 전체가 `/` 로 시작하나?"**

빈 입력창에서 `/` 를 치면 이 조건이 참이니 패널이 열립니다. 하지만 `설명해줘 /` 처럼
앞에 글자가 하나라도 있으면 조건이 거짓이 되고, 패널은 열리지 않았습니다. 슬래시를
몇 글자 더 쳐도 마찬가지였습니다. 이미 문장을 쓰기 시작한 뒤에는 스킬이든 CLI
명령이든 목록으로 꺼내 볼 방법이 없었던 셈입니다.

제보자가 "잘 된다"고 한 쪽도 같은 판단에서 나옵니다. 입력창 전체가 명령이라면 그
명령이 곧 메시지 전부이므로, 항목을 고르는 순간 실행하고 전송하는 것이 맞습니다.
문제는 이 동작이 앞에 글자가 있을 때 어떻게 되어야 하는지가 정해져 있지 않았다는
점입니다. 애초에 패널이 열리지 않으니 마주칠 일이 없던 상황이었습니다.

## 무엇이 바뀌었나

판단 기준을 `@` 파일 멘션과 똑같이 맞췄습니다. 두 기능은 입력창 위 같은 자리를
쓰는 짝이므로, 여는 규칙도 같아야 자연스럽습니다.

- `/` 가 **줄 맨 앞이거나 공백 뒤**에 오고, **커서가 아직 그 토큰 안**에 있으면
  패널이 열립니다. 앞에 무슨 글자가 있든 상관없습니다.
- 토큰 안에 `/` 가 또 나오면 경로로 봅니다. `src/utils` 를 쓰는 중에 패널이
  튀어나오지 않습니다.

여기에 더해, 항목을 골랐을 때 무슨 일이 일어날지를 위치에 따라 나눴습니다.

- **빈 입력창에서 고르면 지금까지처럼 바로 실행**됩니다. 그 명령이 메시지 전부이기
  때문입니다.
- **쓰던 문장 뒤에서 고르면 실행하지 않고 이름만 채워 넣습니다.** 아직 쓰는 중인
  문장의 일부이니까요. 여기서 실행해 버리면 앞서 쓴 문장을 통째로 버리고 절반만
  쓴 메시지를 보내게 됩니다.

## 달라진 점

- **문장을 쓰다가 `/` 를 쳐도 목록이 뜹니다.** `설명해줘 /rev` 까지 치면 `/review`
  같은 항목이 걸러져 보입니다. 스킬, CLI 명령, 직접 만든 명령 모두 해당합니다.
- **쓰던 문장이 사라지지 않습니다.** 항목을 고르면 `설명해줘 /rev` 가
  `설명해줘 /review ` 로 채워지고, 커서는 이름 뒤 공백 다음에 놓입니다. 이어서
  인자를 바로 칠 수 있습니다.
- **고른다고 전송되지 않습니다.** 문장 중간에서 고르는 것은 글을 쓰는 행동이지
  보내는 행동이 아닙니다. 보낼 준비가 되면 평소처럼 전송하면 됩니다.
- **빈 입력창에서의 동작은 그대로입니다.** `/model` 처럼 명령만 친 경우에는 예전과
  똑같이 곧바로 실행됩니다.
- **경로를 오해하지 않습니다.** `src/utils` 나 `see src/utils` 에서는 패널이 뜨지
  않습니다.
- **`@` 파일 멘션과 부딪히지 않습니다.** 커서가 `@토큰` 안에 있으면 파일 목록이
  자리를 가져가고 명령 패널은 물러납니다. [#236](https://github.com/yhk1038/claude-code-gui-jetbrains/issues/236)
  에서 정리한 동작이 그대로 유지됩니다.

## 두 제보가 하나였던 이유

제보자는 "고르면 바로 전송된다"와 "패널이 안 뜬다"를 별개로 적었지만, 둘 다
"입력창 전체가 `/` 로 시작하나"라는 하나의 기준에서 나온 결과였습니다. 그 기준은
명령이 메시지 전부인 경우만 상정하고 있었고, 그래서 앞에 글자가 있는 경우를 여는
쪽에서는 막고 실행하는 쪽에서는 정의하지 않았습니다. 기준을 커서 위치로 바꾸면서
두 가지를 함께 정리했습니다.
