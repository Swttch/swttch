# 채팅에서 글자 고르기와 리눅스 선택 버퍼

> Language: [English](./en.md) · **한국어**

채팅에서 글자를 고르는 동작이 이제 매번 제대로 되고, 리눅스에서는 채팅에서 고른 글자를 다른 프로그램과 똑같이 마우스 가운데 버튼으로 붙여넣을 수 있다. 둘 다 이전에는 고장 나 있었다 ([#513](https://github.com/Swttch/swttch/issues/513)).

## 더블클릭과 드래그로 고르는 동작이 더 이상 실패하지 않는다

이전에는 채팅 화면의 어디에서든 마우스 버튼을 누르는 순간 커서가 입력창으로 돌아갔다. 누르는 순간에 포커스가 클릭한 글자에서 떠나 버리면 고르려던 단어나 범위가 취소된다. 그래서 이미 고른 글자가 있는 상태에서 다른 곳을 클릭한 다음 단어를 더블클릭하거나 글자 위를 드래그하면, 아무것도 고르지 못하는 일이 잦았다.

이제는 버튼을 **뗄 때** 커서가 입력창으로 돌아가고, 그것도 방해가 되지 않는 경우에만 돌아간다.

- 클릭한 곳이 채팅의 빈 공간이다. 버튼, 링크, 입력란, 메뉴, 대화상자는 해당하지 않는다.
- 그 순간 고른 글자가 없다.
- 다른 요소가 포커스를 잡고 있지 않다.

그래서 누르기, 더블클릭, 드래그는 일반 웹페이지와 똑같이 동작하고, 빈 공간을 한 번 클릭하면 계속 입력할 수 있도록 커서가 입력창에 들어가는 것도 그대로다.

![채팅 입력창에 "Why does the retry logic wait twice?" 문장이 입력되어 있다. 더블클릭한 단어 "retry"가 파란색으로 강조되어 있다.](./assets/text-selection-input.png)

## 탭으로 돌아왔을 때

다른 탭이나 창으로 갔다가 돌아오면, 창이 포커스를 되찾는 순간에 커서가 입력창으로 한 번 돌아간다. TanStack Query의 "창 포커스 시 다시 가져오기" 설정과 같은 발상이다. 창이 포커스를 얻는 일에 반응하고, 포커스가 바뀌지 않았을 때는 동작하지 않는다. 탭을 잠깐 떠날 때 창이 순간적으로 숨김과 보임을 오가도, 입력창에 커서가 깜빡 들어왔다 사라지지 않는다.

## 리눅스: 고른 글자를 가운데 버튼으로 붙여넣기

리눅스에서는 모든 프로그램이 글자를 고르는 즉시 두 번째 클립보드인 **선택 버퍼**(PRIMARY)를 채우고, 마우스 가운데 버튼이 그것을 붙여넣는다. IDE 2026.2부터는 내장 브라우저가 별도 프로세스로 돌면서 이 버퍼를 채우지 않게 되어, 채팅 메시지나 입력창에서 고른 글자를 가운데 버튼으로 붙여넣을 수 없었다.

이제 채팅이 고른 글자를 IDE에 알리고, IDE가 그 글자를 선택 버퍼에 넣는다.

- 고르기를 마쳤을 때(버튼을 뗐을 때)와, Shift+Home처럼 키보드로 고른 범위가 바뀔 때 갱신된다.
- 아무것도 고르지 않은 상태가 되거나 클릭으로 고른 글자를 풀어도 버퍼는 그대로 남으므로, 앞서 고른 글자를 여전히 붙여넣을 수 있다.
- 비밀번호 입력란의 글자는 절대 보내지 않는다.
- X11과 웨이랜드(IDE 자체 웨이랜드 툴킷, 그리고 Xwayland 위의 X11 툴킷) 모두에서 동작한다.
- 고른 글자 자체는 로그에 남지 않는다. 글자 수만 남는다.

## 하지 않는 것

- **JetBrains IDE 전용이다.** 독립 실행(standalone) 모드에서는 브라우저가 버퍼를 직접 채우므로 더할 것이 없다.
- **macOS와 Windows에는 선택 버퍼가 없어서** 아무 일도 일어나지 않는다. Cmd/Ctrl+C 복사는 그대로다.
- 고른 글자는 같은 기기 안에서, 플러그인이 이미 쓰는 연결을 통해 채팅에서 IDE로 전달된다.
