# 채팅 화면이 IDE 테마의 색을 그대로 씁니다

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#267](https://github.com/yhk1038/claude-code-gui-jetbrains/issues/267)

## 제보

한 사용자가 채팅 화면의 배경색이 IDE 테마와 어울리지 않는다고 알려주셨습니다. 지금 적용된
테마의 배경색을 따라가면 화면이 하나로 이어져 보일 것 같다는 제안이었습니다.

지적이 정확했습니다. 채팅 화면은 다크 모드에서 `#1A1A1A`를 칠하고 있었는데, IntelliJ Dark의
에디터 배경은 `#1E1F22`입니다. 두 색이 미묘하게 달라서, 채팅 화면과 그 주변 IDE 화면이 맞닿는
경계에서 색이 한 번 튀었습니다.

## 왜 그동안 맞추지 못했나

색을 맞추려면 "지금 어떤 테마가 켜져 있는지"를 알아야 하는데, JetBrains의 테마는 **개수를 셀 수
없습니다.** IDE에 기본 포함된 테마가 있고, 마켓플레이스에서 내려받는 테마가 있고, 사용자가
직접 `.theme.json` 파일을 써서 만드는 테마도 있습니다.

그래서 "테마 이름을 하나씩 알아내서 색을 대응시키는" 방식은 처음부터 성립하지 않았습니다.
새 테마가 나올 때마다 플러그인을 고쳐야 하고, 사용자가 어제 만든 테마는 영원히 대응할 수
없습니다.

## 어떻게 해결했나

**테마의 이름을 묻지 않기로 했습니다.**

플러그인은 지금 켜져 있는 테마가 무엇인지 모릅니다. 대신 IDE에게 "지금 에디터 배경색이 무슨
색이냐"고 물어서 그 값을 그대로 받아옵니다. 테마를 바꾸면 다시 물어봅니다.

이 방식이면 기본 테마든, 마켓플레이스에서 받은 테마든, 사용자가 방금 만든 테마든 **똑같이
동작합니다.** 플러그인 안에 테마 이름을 아는 코드가 한 줄도 없기 때문입니다.

받아오는 색은 배경만이 아닙니다. 글자색, 테두리, 강조색, 입력창 배경, 툴팁 색까지 함께
가져옵니다. 테마가 그중 일부를 정해두지 않았다면 그 항목만 플러그인 자체 색을 씁니다.

## 쓰는 방법

**설정 → Appearance → Color Theme** 오른쪽에 **"Sync with IDE"** 체크박스가 생겼습니다.

체크박스는 **기본적으로 꺼져 있습니다.** 켜기 전까지는 이전과 똑같이 플러그인 자체 테마를
씁니다. 색을 IDE에 맞추고 싶을 때만 켜시면 됩니다.

체크박스를 켜면 Color Theme 드롭다운이 **"Managed by IDE"** 표시로 바뀝니다. 그 상태에서는
IDE가 색을 정하므로, 드롭다운으로 고르는 것이 의미가 없기 때문입니다. 체크박스를 다시 끄면
드롭다운이 돌아오고 색도 원래대로 돌아옵니다.

IDE 테마를 바꾸면 채팅 화면의 색도 **바로 따라옵니다.** IDE를 다시 시작하지 않아도 됩니다.

## 몇 가지 알아두실 점

**체크박스는 IDE 안에서만 보입니다.** 브라우저로 접속해서 쓰는 경우에는 맞출 IDE 테마가 없으므로
체크박스가 나타나지 않습니다. IDE가 띄운 백엔드에 브라우저로 접속하는 경우도 마찬가지입니다 —
색을 브라우저 쪽으로 전달할 통로가 아직 없습니다.

**테마 이름은 표시하지 않습니다.** "Managed by IDE"라고만 적고 실제 테마 이름(예: Dracula)을
보여주지 않는 이유가 있습니다. JetBrains에서 테마 이름을 읽으려면 아직 실험 단계로 표시된
API를 거쳐야 하는데, 그런 API를 쓰면 마켓플레이스 배포 검사에서 경고가 발생합니다. 이름 하나를
보여주려고 배포를 위태롭게 할 이유가 없다고 판단했습니다.

**마우스를 올렸을 때의 강조색은 IDE 값을 그대로 쓰지 않습니다.** IDE가 알려주는 강조색은
다크 테마에서도 거의 흰색에 가까운 값이라, 그대로 칠하면 목록의 한 줄만 하얗게 튑니다. 대신
IDE의 패널 색에서 일정한 만큼 밝기를 옮겨 계산합니다. 어두운 테마에서는 밝아지고 밝은
테마에서는 어두워지므로, 어떤 테마에서도 구분이 됩니다.
