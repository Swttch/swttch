# 프록시 뒤에서도 사용량 통계가 보입니다

> 언어: [English](./en.md) · **한국어**

## 무엇이 문제였나

프록시를 거쳐야만 인터넷에 나가는 환경에서는 사용량 패널이 뜨지 않았습니다. 채팅은 됐습니다. `/usage`도 됐습니다. 배터리 수치와 계정 목록만 실패했고, 에러는 프록시에 대해 아무 말도 하지 않았습니다.

이 차이가 원인을 알려줍니다. 채팅은 `claude` CLI를 거쳐 나가고, 그 CLI는 `settings.json`을 읽어 거기 적힌 프록시를 씁니다. 반면 사용량 수치는 `claude`가 아니라 `ccb`에서 옵니다. `ccb`는 사용자 머신에 따로 설치되는 작은 도우미 CLI인데, Claude Code 로그인을 읽는 일을 JetBrains 플러그인이 할 수 없어서 밖으로 뺀 것입니다.

`ccb`는 Claude CLI가 아니라서 `settings.json`을 읽지 않았습니다. 그래서 거기 설정한 프록시가 보이지 않았고, 모든 사용량 조회가 직접 연결로 나갔습니다. 직접 연결을 받아주지 않는 망으로 말입니다.

[#181](https://github.com/Swttch/swttch/issues/181)로 제보되었고, 그 환경을 직접 겪는 분이 수정을 기여해 주셨습니다.

## 무엇을 했나

Claude Code에 설정한 프록시가 사용량 조회에도 적용됩니다.

새로 설정할 것은 없습니다. `claude`가 이미 쓰고 있는 그 설정을 그대로 읽습니다.

```json
{
  "env": {
    "HTTPS_PROXY": "http://사용자:비밀번호@proxy.example.com:8080"
  }
}
```

`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`, `NO_PROXY`를 모두 읽으며 대문자와 소문자를 가리지 않습니다. 셸에서 export한 프록시도 전과 같이 동작합니다.

### 프로젝트별 프록시

프로젝트의 `.claude/settings.json`이 전역과 다른 프록시를 지정하면 프로젝트 것이 이깁니다. `claude` 자신이 쓰는 우선순위와 같습니다.

프록시를 설정하지 않은 프로젝트로 옮기면 이전 프로젝트의 프록시가 남지 않고, 셸이 export한 값으로 되돌아갑니다.

### SSH 터널

`ssh -D`로 연 터널은 HTTP 프록시가 아니라 SOCKS 프록시인데, 이제 HTTP 프록시와 함께 지원합니다.

```json
{
  "env": {
    "ALL_PROXY": "socks5://127.0.0.1:1080"
  }
}
```

음성 입력도 같은 프록시를 지납니다. 똑같은 이유로 똑같이 막혀 있었습니다.

## 동반 도구는 알아서 올라갑니다

프록시 지원은 `ccb` 쪽에도 만들어야 했지 이쪽만으로는 되지 않아서, **`ccb` 0.6.0 이상**이 필요합니다. 그 아래 버전은 프록시 설정을 받기는 해도 쓰지 않습니다.

이 부분은 따로 하실 일이 없습니다. 백엔드가 시작할 때마다 동반 도구의 새 버전을 확인해 백그라운드에서 올려두므로, 이미 설치된 것은 스스로 0.6.0이 됩니다. 설치된 버전을 직접 보시려면 **설정 → 일반 → 음성 입력**에 표시됩니다.

## 동작하는지 어떻게 아나

프록시는 URL에 드러나지 않아서, 전에는 실패가 그냥 네트워크 오류로 보였습니다. 이제는 프록시를 거쳐 나가다 실패하면 그 사실과 관련 환경변수를 함께 알려줍니다. 프록시 탓인지 토큰 탓인지 망 탓인지 짐작하지 않아도 됩니다.
