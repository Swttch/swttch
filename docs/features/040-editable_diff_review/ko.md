# 제안된 코드를 그 자리에서 고쳐서 적용하기

Claude가 파일 수정을 제안했는데 한 글자만 다르게 하고 싶을 때가 있습니다. 상수 값이 조금 크다거나, 변수 이름이 우리 컨벤션과 안 맞는다거나.

지금까지는 그걸 말로 설명해야 했습니다. "그건 좋은데 20000 말고 15000으로 해줘" 하고 한 턴을 더 쓰는 거죠. 설명할 가치도 없는 사소한 수정인데도요.

이번 릴리즈부터 **제안된 쪽을 그 자리에서 직접 고칠 수 있습니다.** 고친 그대로 파일에 쓰입니다.

## IDE에서

Claude가 파일을 고치겠다고 하면 열리는 diff 창에서, 오른쪽 **Proposed** 쪽에 그냥 타이핑하면 됩니다.

IDE의 에디터가 그대로 동작하므로 자동완성, 괄호 짝 맞추기, `Cmd+Z`, 키맵이 평소 코드 쓸 때와 똑같습니다. 새 에디터를 배울 필요가 없습니다.

왼쪽 **Original** 은 계속 읽기 전용입니다. 그쪽은 지금 디스크에 있는 파일이라, 거기 타이핑해봐야 아무것도 안 바뀌면서 바뀐 것처럼 보이기만 합니다.

**Apply** 를 누르면 화면에 보이는 그대로 쓰입니다. 아무것도 안 고쳤다면 예전과 완전히 같습니다 — Claude가 제안한 그대로 적용됩니다.

**Reject** 는 고친 내용까지 함께 버립니다. 거절은 "다른 걸 쓰겠다"가 아니라 "안 쓰겠다"이기 때문입니다.

체크박스로 일부만 고르던 것([#109](https://github.com/Swttch/swttch/issues/109))도 그대로 쓸 수 있습니다. 체크를 풀어 범위를 줄이고, 남긴 부분을 다시 손보는 것도 됩니다.

## 브라우저에서도 됩니다

이번 릴리즈 전까지, IDE 밖에서 쓰면 승인 화면이 파일 이름만 알려주고 **안에 뭐가 들었는지는 보여주지 못했습니다.** 열 IDE 창이 없었으니까요. 내용을 못 본 채로 승인하거나 거절해야 했습니다.

이제 그 자리에 diff가 직접 그려집니다.

![승인 화면 안에 그려진 diff. 파일 이름과 Apply·Reject 버튼이 위에 있고, 아래에 문법 강조된 변경 내용이 보인다](./assets/editing-the-proposal.png)

*제안된 값 `20000` 을 `15000` 으로 직접 고친 상태. Apply를 누르면 이 화면 그대로 저장됩니다.*

문법 강조, 안 바뀐 줄 접기, 그리고 **편집** 까지 IDE 쪽과 동일하게 동작합니다. 화면이 좁으면 한 칼럼으로, 넓으면 좌우로 나란히 보여줍니다.

## IDE 안에서도 이 화면을 쓰고 싶다면

**설정 → IDE → Claude의 편집을 IDE diff 뷰어에 표시** 를 끄면 됩니다.

이 설정은 원래 "diff를 볼지 말지"였는데, 이제 **"어디서 볼지"** 가 됐습니다. 켜면 IDE의 diff 탭에서, 끄면 채팅 안에서 봅니다. 어느 쪽이든 변경 내용을 못 보는 경우는 없어집니다.

![IDE 설정 화면. diff 뷰어 항목이 목록에 보인다](./assets/ide-settings.png)

*IDE 밖에서 실행 중이면 이 항목은 비활성입니다 — 열 IDE 창이 없어서, 채팅 안 diff가 유일한 경로이기 때문입니다.*

## 알아두면 좋은 것

**고친 내용은 Claude에게도 전달됩니다.** 자기가 제안한 값이 아니라 실제로 쓰인 값을 기준으로 대화가 이어집니다.

**제안을 원래대로 되돌려놓고 Apply 하면**, Claude의 원래 호출이 그대로 나갑니다. 타이핑했다가 `Cmd+Z` 로 되돌린 경우가 여기 해당합니다.

**제안을 통째로 원본과 같게 고쳐놓고 Apply 하면** 거절로 처리됩니다. 쓸 것이 없는데 성공했다고 알리면 안 되기 때문입니다.
