# 백그라운드 작업을 실제로 멈출 수 있게 됐습니다

Background tasks 패널에서 `running` 옆의 `✕`를 누르면 그 작업이 **취소됩니다.**
전에는 목록에서 감추기만 했고, 작업은 뒤에서 계속 돌고 있었습니다.

그리고 `Escape`는 이제 **화면에서 답변하고 있는 것만** 멈춥니다.
백그라운드 작업은 그대로 둡니다 — CLI와 같습니다.

## 무엇이 달라졌나

| | 이전 | 지금 |
| --- | --- | --- |
| 실행 중인 작업의 `✕` | 목록에서 감추기만 함 (작업은 계속 돎) | 작업을 취소 |
| 끝난 작업의 `✕` | 목록에서 감춤 | 그대로 |
| `Escape` | 답변 중단 + 백그라운드 작업을 전부 `stopped`로 표시 | 답변만 중단 |
| `Escape` 3연타 (답변이 멈춘 뒤) | — | 백그라운드 작업 전부 중지 (확인 후) |

## 왜 이렇게 바꿨나

제보를 받고 코드를 열어보니 `✕`는 화면 목록에서 id 하나를 빼는 게 전부였습니다.
백엔드로 나가는 요청이 없었습니다.

`Escape`도 비슷했습니다. CLI에 중단 신호를 보내면서, 동시에 그 세션의 백그라운드
작업을 전부 `stopped`로 칠하고 있었습니다. 그런데 칠하기만 한 것이라
**작업은 계속 돌고 있었습니다.** 화면과 실제가 어긋나 있던 겁니다.

재보니 그랬습니다. `Escape`를 누르면 CLI는 턴을 끝내지만, 백그라운드 작업에는
아무 신호도 가지 않고 그대로 돕니다. 그러니 `stopped`는 사실이 아니었습니다.

이제 `Escape`는 답변만 멈춥니다. 백그라운드 작업이 `running`으로 남아 있으면
그건 정말 돌고 있다는 뜻입니다.

## 3연타로 전부 멈추기

`Escape` 한 번으로는 백그라운드가 안 멈추니, 전부 멈추는 방법이 따로 필요했습니다.

답변이 멈춘 상태에서 `Escape`를 빠르게 세 번 누르면 확인 창이 뜨고, 확인하면
실행 중인 작업이 전부 취소됩니다.

세는 기준은 **답변이 멈춘 다음부터**입니다.
그래서 답변 중에 네 번을 누르면 첫 번째가 답변을 멈추고, 나머지 세 번이 확인 창을
띄웁니다. 실행 중인 작업이 없으면 아무 일도 일어나지 않습니다.

`Ctrl+F`나 `Ctrl+T` 같은 키는 쓰지 않았습니다.
CLI에서는 그 키들이 백그라운드 작업을 다루지만, IDE 안에서는 `Ctrl+F`가 찾기이고
`Ctrl+T`가 VCS 업데이트입니다. 우리가 그 키를 잡으면 IDE 단축키를 삼킵니다.
전에 `F12`로 같은 일을 겪었습니다.

## 취소가 전달되는 방법

먼저 CLI에 취소 요청을 직접 보냅니다. 즉시 멈춥니다.

그게 안 되면 — 작업 id를 모르거나 요청이 전달되지 않으면 — 모델에게 대신
멈춰달라고 요청합니다. 이 메시지는 대화에 보이지 않습니다.

두 번째 방법을 남겨둔 이유가 있습니다. 첫 번째는 Claude CLI의 방식이라 다른
CLI에는 그대로 옮겨가지 않습니다. 두 번째는 "모델이 있고 멈추는 도구가 있다"만
있으면 성립합니다. 나중에 다른 CLI를 붙일 때 남는 건 두 번째입니다.
