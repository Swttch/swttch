# 마이크가 왜 녹음을 못 하는지 알려줍니다

> 언어: [English](./en.md) · **한국어**

## 무엇이 잘못됐나

녹음 버튼을 누르면 채팅 입력창에 자바스크립트 오류가 떴습니다.

```
Cannot read properties of undefined (reading 'accessToken')
```

코드를 짠 사람에게나 의미 있는 한 줄입니다. 무엇이 잘못됐는지도, 다음에 무엇을 해야 하는지도 알려주지 않습니다.

제보자는 이게 무슨 뜻인지 채팅에서 Claude에게 물어본 뒤 [#355](https://github.com/Swttch/swttch/issues/355)를 올렸고, 요청은 한 줄이었습니다.

> plugin should check somehow.. or deliver a better error message.
> (플러그인이 어떻게든 확인을 하거나, 더 나은 오류 메시지를 주면 좋겠습니다.)

플러그인 0.29.1부터 0.30.0까지 해당됩니다.

## 왜 그랬나

음성 입력에는 **Claude 계정 로그인**이 필요합니다.

받아쓰기 스트림은 로그인이 기기에 남겨두는 OAuth 액세스 토큰으로 열립니다. `ANTHROPIC_API_KEY`로만 인증한 기기에는 그 토큰이 아예 없습니다.

제보자는 API 키를 쓰고 있었습니다. 그래서 코드가 없는 토큰을 찾아 들어갔다가 빈 값을 만나 그 자리에서 터졌습니다.

그 실패를 다루는 방식에서 두 가지가 어긋나 있었습니다.

**아무것도 미리 확인하지 않았습니다.** 백엔드에는 "이 기기가 받아쓰기를 할 수 있나?"를 묻는 코드가 이미 쓰여 있었습니다. 화면이 그걸 한 번도 물어보지 않았습니다. 그래서 알아내는 방법은 버튼을 눌러 실패하는 것뿐이었습니다.

**실패를 날것으로 그대로 내보냈습니다.** `@swttch/extend-kit` 미설치가 아닌 것은 전부 "unknown"으로 묶여, 예외가 들고 있던 문자열이 그대로 화면에 찍혔습니다. 프로퍼티 접근 오류가 안내 배너에 오른 경위가 그것입니다.

조용한 문제가 하나 더 있었습니다. 그 가용성 질문을 **실제로 물었을 때**, 킷이 멀쩡히 설치돼 있고 최신인데도 모든 실패가 **"킷이 설치되지 않았다"**로 돌아왔습니다. 화면이 그 답을 썼다면 API 키 사용자에게 이미 갖고 있는 것을 설치하라고 안내할 뻔했습니다.

## 무엇이 바뀌었나

**이제 누르기 전에 마이크가 흐리게 보입니다.** 기기가 받아쓰기를 할 수 없으면 버튼이 흐려지고 툴팁이 이유를 말합니다.

숨기지 않고, 비활성화하지도 않고, 흐리게 둡니다. 숨기면 왜 못 쓰는지 들어야 할 바로 그 사람들에게서 기능이 화면에서 사라집니다. 비활성화하면 누름이 삼켜져서, 이유가 아무도 굳이 올려볼 필요 없는 툴팁에만 남습니다.

**누르면 사용하는 언어로 설명합니다.**

> 음성 입력은 Claude 계정 로그인이 필요합니다. API 키만으로는 받아쓰기를 이용할 수 없습니다.

옆에는 상단 배너가 쓰는 것과 같은 로그인 화면으로 가는 **로그인** 버튼이 있습니다. 이 문구는 인터페이스 12개 언어 전부에 번역돼 있습니다.

**인증을 확인하기 전에는 아무것도 열지 않습니다.** 마이크도 켜지 않고 소켓도 열지 않으므로, 한 글자도 받아쓸 수 없는 상태에서 녹음 표시등이 켜지는 일이 없습니다.

**설정 → 일반 → 음성 입력에서도 알려줍니다.** 이 섹션은 킷이 없을 때는 원래 알려줬습니다. 이제 킷은 멀쩡한데 로그인이 없을 때도 알려주고, 아래 항목들을 흐리게 만듭니다. 켜기/끄기 토글은 그대로 쓸 수 있습니다. 음성 입력을 꺼둔 사람에게는 그 토글이 돌아오는 길이기 때문입니다.

**킷 없음과 로그인 없음을 더는 혼동하지 않습니다.** 정말로 킷이 없을 때만 킷 문제라고 말합니다.

## API 키를 그냥 쓰지 않는 이유

어떤 공식 Claude Code 클라이언트도 그렇게 하지 않기 때문입니다.

공식 CLI에는 바로 이 상황을 위한 전용 실패 문구가 들어 있습니다.

```
[voice_stream] No OAuth token available
```

다른 엔드포인트에는 얼마든지 보낼 수 있는 API 키가 있는데도, 연결하기 전에 물러섭니다. 이 플러그인은 CLI를 우회해 발명하는 대신 CLI를 따르므로, 같은 자리에서 물러서되 이유를 더 잘 설명하기만 합니다.

받아쓰기 서비스가 API 키를 **받아줄지**는 측정된 적이 없습니다. 어떤 클라이언트도 물어보지 않기 때문입니다. 그래서 "API 키로는 받아쓰기를 못 한다"는 서비스 자체에 대한 주장이 아니라, 사용자가 실제로 겪는 **모든 Claude Code 클라이언트에 대한 사실**입니다.

## 음성 입력을 쓰고 싶다면

배너의 **로그인** 버튼이나 계정 메뉴에서 Claude 계정으로 로그인하세요. 다음 누름부터 받아쓰기가 동작합니다.
