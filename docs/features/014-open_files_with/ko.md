# "파일 열기 프로그램": 원하는 에디터를 감지해 실행

> Languages: [English](./en.md) · **한국어**
>
> 관련: [#213](https://github.com/Swttch/swttch/issues/213), [#214](https://github.com/Swttch/swttch/pull/214)

## 새로운 점

**"파일 열기 프로그램"** 설정이 이제 제대로 동작합니다. 컴퓨터에 설치된 에디터·IDE를
감지하고, 채팅에서 클릭한 파일 참조를 사용자가 고른 프로그램으로 엽니다. 그리고 그
에디터를 macOS·Windows·Linux에서 올바르게 실행합니다.

이전에는 picker에 에디터가 몇 개만 나오고 JetBrains IDE는 아예 목록에 없었으며, 직접
지정(custom) 항목은 동작하지 않았고, Windows/Linux에서는 선택한 에디터가 실행되지
않았습니다. 이제 JetBrains 제품군, VS Code, Cursor, Xcode, Zed 등을 감지하고 실제로
엽니다.

같은 개선을 **터미널 감지**("터미널 앱" 설정)에도 적용했습니다. 이전에는 낡고 빈약한
탐색 로직을 중복 구현하고 있어 macOS 기본 Terminal.app조차 찾지 못했습니다.

## 화면

설정은 **설정 → CLI** 탭 맨 위에 있습니다.

- **JetBrains IDE가 연결된 경우**(JCEF 웹뷰이거나 IDE 세션에서 연 브라우저 탭): 값이
  그 IDE로 고정되며 변경할 수 없습니다 — 클릭한 참조는 이미 연결된 IDE에서
  해당 라인·컬럼으로 열리기 때문입니다.
- **standalone 브라우저**(IDE 미연결): 컴퓨터에서 감지된 에디터 드롭다운과 함께
  **시스템 기본**(OS 기본 프로그램), **직접 지정…**이 표시됩니다. 직접 지정을 고르면
  **경로** 입력란(파일 선택 버튼 포함)과 **인자** 입력란이 나타나며, 인자의
  `%TARGET_PATH%` 토큰이 실제 파일 경로로 치환됩니다 — GitHub Desktop의 외부 에디터
  UI와 같은 형태입니다.

같은 탭의 터미널 앱 picker도 이제 실제로 감지된 터미널(예: Terminal, iTerm2)을 같은
방식으로 나열합니다.

## 동작 방식

감지는 GitHub Desktop의 오픈소스 외부 에디터·셸 방식을 따릅니다 — 미공개 API를
쓰지 않으며, 프로젝트의 CLI 동등성 원칙과 일치합니다:

- **macOS**는 각 앱의 `Info.plist`에서 번들 ID를 읽어 설치된 앱 인벤토리를 만듭니다.
  Spotlight 색인이 꺼져 있어(개발 환경에서 흔합니다) `mdfind`/`mdls`가 아무것도
  반환하지 않는 경우에도 동작합니다. `/Applications`, `~/Applications`와 시스템 앱
  폴더까지 훑어서 JetBrains Toolbox 설치본과 Terminal.app을 모두 찾습니다.
- **Windows**는 언인스톨 레지스트리(생성된 JetBrains 버전 키와 JetBrains Toolbox
  항목 포함)를 `reg`로 조회하며, 네이티브 모듈 의존이 없습니다.
- **Linux**는 `PATH`를 탐색합니다.

선택한 에디터의 이름이 저장됩니다. 파일을 열 때 그 이름을 설치 경로로 확인해
실행합니다 — macOS는 `open -a`, 그 외에는 분리된(detached) 프로세스로 실행합니다.
직접 지정 에디터는 경로와 확장된 인자로 실행됩니다.

에디터와 터미널은 **하나의 감지 엔진과 카탈로그를 공유**하므로 두 설정이 일관되게
동작하고 OS별 탐색 로직이 중복되지 않습니다.

설정 저장도 **원자적·직렬화**되도록 만들었습니다. 이전에는 빠르게 두 번 변경하면 설정
파일에 대한 읽기-수정-쓰기가 서로 얽혀 파일이 깨질 수 있었는데, 이제 각 쓰기가 다음
쓰기 전에 완료되며 임시 파일 + 이름 변경(rename)으로 기록됩니다.
