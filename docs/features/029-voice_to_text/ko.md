# 타이핑 대신 말로 입력하기

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#235](https://github.com/Swttch/swttch/issues/235)

## 제보

한 사용자가 자기가 쓰던 우회 방법을 설명했습니다. 긴 내용을 넣어야 할 때는 Claude Desktop 앱에 대고 말한 뒤, 그 텍스트를 복사해서 플러그인에 붙여넣는다는 것이었습니다. 녹음을 여기서 바로 할 수 없겠냐고 물었고, 자신은 영어가 아니라 독일어를 쓴다고 덧붙였습니다. 영어가 아니면 정확도가 떨어지지만 그래도 쓸 만하고, 타이핑보다는 훨씬 빠르다는 이야기였습니다.

## 왜 돌아가야 했나

가장 먼저 떠오르는 길은 브라우저 내장 음성 API였습니다. 그런데 JetBrains IDE가 쓰는 WebView에는 그 API가 없어서, 시작하기도 전에 막혔습니다.

다음 질문은 "다른 Claude Code 클라이언트들은 어떻게 하고 있나"였습니다. 데스크탑 앱도 VS Code 확장도 Anthropic의 비공개 엔드포인트를 호출하고 있었고, 그 호출에는 **계정 자격증명 전송이 따라옵니다.**

이것이 벽이었습니다. JetBrains 플러그인은 자격증명을 다룰 수 없으므로, UI를 어떻게 구성하든 이 기능을 플러그인 안에 넣을 수는 없었습니다.

## 어떻게 해결했나

**자격증명을 만지는 부분을 플러그인 바깥으로 뺐습니다.**

전사 코드는 [`@swttch/extend-kit`](https://www.npmjs.com/package/@swttch/extend-kit)에 있습니다. 사용자 머신에 따로 설치되는 패키지이며, 사용량 패널이 이미 `ccb`에 쓰고 있는 것과 같은 방식입니다. 플러그인은 자격증명을 다루는 코드를 전혀 담지 않고, 그 일을 kit에 맡깁니다. kit은 머신에 이미 있는 Claude Code 로그인을 사용합니다.

이 선택이 실제로 의미하는 것은 이렇습니다.

- **별도 API 키도, 별도 요금도 없습니다.** 이미 로그인된 계정으로 인증하므로, Claude Code를 쓰면서 내던 것 외에 추가 비용이 들지 않습니다.
- **다른 클라이언트와 같은 품질입니다.** 대체재가 아니라 같은 서비스이기 때문입니다.
- **전제 조건이 하나 있습니다.** kit이 설치되어 있어야 합니다. 없으면 조용히 실패하지 않고 그렇다고 알려줍니다.

## 사용법

입력창 우측 상단에 마이크 버튼이 있습니다. 키보드로는 `⌥D`(Windows·Linux는 `Alt+D`)입니다.

![입력창 오른쪽 끝에 있는 마이크 버튼](./assets/composer-mic.png)

Cmd·Ctrl이 아니라 Alt를 쓰는 이유가 있습니다. `⌘D`는 모든 브라우저에서 북마크 추가이고 `Ctrl+D`는 터미널의 입력 종료라, 둘 다 이미 임자가 있습니다.

이 키는 **설정 → 일반 → 음성 입력 → 단축키**에서 바꿀 수 있습니다. 칸을 누르고 원하는 조합을 그대로 누르면 됩니다. Esc를 누르면 바꾸지 않고 빠져나옵니다.

![단축키 칸을 누른 뒤 "키를 누르세요…"로 바뀐 상태](./assets/shortcut-recording.png)

이름을 적어 넣는 대신 실제로 눌러 지정하게 한 이유는, 눌러서 만든 조합은 오타가 날 수 없기 때문입니다.

Ctrl·Alt·Cmd 중 하나는 반드시 함께 눌러야 합니다. 글자 하나만 단축키로 두면 입력창에서 그 글자를 칠 수 없게 되기 때문입니다.

**눌렀다 떼면** 녹음이 시작되어 계속됩니다. 다시 누르면 끝납니다. 긴 내용을 부를 때 편합니다.

**누른 채로 있으면** 누르고 있는 동안만 녹음되고, 손을 떼면 끝납니다. 한두 문장에 편합니다.

둘 중 무엇을 쓸지 고르실 필요는 없습니다. 버튼이 누른 시간으로 알아서 구분합니다.

말하는 동안 **입력창 안에** 텍스트가 기울임꼴로 흐리게 나타납니다. 인식기가 아직 판단 중이라 계속 고쳐지는 부분입니다. 문장이 확정되면 그 자리에서 보통 글자로 바뀝니다.

받아쓰기는 **커서 자리에 끼워 넣습니다.** 문장 중간에 커서를 두고 말하면 거기에 들어가며, 이미 타이핑해둔 내용은 지워지지 않습니다. 말하는 도중에 직접 타이핑하시면 받아쓰기가 멈춥니다 — 사용자가 친 글자를 덮어쓰지 않기 위해서입니다.

녹음 중에는 마이크 왼쪽에 **막대 세 개**가 나타나 목소리 크기에 따라 오르내립니다. 이건 의도한 것입니다. 마이크가 음소거되어 있거나 입력 장치가 잘못 잡혀 있어도 겉보기에는 정상 녹음과 똑같아서, 텍스트가 안 나올 때까지 알 수 없기 때문입니다.

## 터미널에서 끈 것은 여기서도 꺼집니다

![설정의 음성 입력 섹션 — 사용 토글, 말하는 언어, 대기 시간, 단축키. 제목 오른쪽에 설치된 kit 버전이 보인다](./assets/settings-section.png)

CLI에서 `/voice off`로 끄면 GUI에서도 마이크 버튼과 단축키가 사라집니다. 같은 머신에서 한쪽만 켜져 있으면 설정이 두 벌인 셈이기 때문입니다. **설정 → 일반 → 음성 입력 사용**에서 끄면 반대로 CLI에서도 꺼집니다. 같은 값을 함께 쓰기 때문입니다.

한 가지는 공식 동작과 다르게 두었습니다. Claude Code는 이 값이 없으면 **꺼진 것으로** 봅니다. 터미널에서는 `/voice`로 먼저 켜야 하기 때문입니다. 우리는 반대로 **켜진 것으로** 봅니다. GUI에는 그 명령이 없고 마이크 버튼이 눈에 보이므로, 없는 명령을 먼저 찾아 실행해야 하는 상태로 두면 기능이 그냥 사라진 것처럼 보이기 때문입니다.

`/voice hold`·`/voice tap`으로 정하는 모드와 자동 전송 설정은 건드리지 않습니다. 둘 다 "스페이스를 누르고 있는다"는 터미널 조작을 전제한 것이라 마이크 버튼을 누르는 화면에서는 뜻이 성립하지 않습니다. 값은 그대로 보존하므로 터미널 쪽 설정이 망가지지 않습니다.

## 말하는 언어

인식기에는 어떤 언어로 말하는지 미리 알려줘야 합니다. 알려주지 않으면 영어로 가정하고, 한국어를 영어 소리로 받아 적습니다 — "안녕하세요"가 "ah ñomaseu"로 나오는 식입니다.

![말하는 언어 드롭다운 — 위에 검색창, 첫 항목은 Claude 설정 따름](./assets/language-picker.png)

그래서 **설정 → 일반 → 음성 입력 언어**를 두었습니다. 기본값은 **인터페이스 언어 따름**이라, 대부분은 따로 건드릴 일이 없습니다. 화면을 한국어로 쓰는 사람은 한국어로 말할 가능성이 높기 때문입니다.

이 설정이 인터페이스 언어와 별개로 존재하는 이유는, 둘이 어긋나는 경우가 실제로 있기 때문입니다. 화면은 영어로 쓰면서 한국어로 말하는 사람이 그렇습니다. 그럴 때만 여기서 말하는 언어를 직접 고르면 됩니다.

Claude의 응답 언어를 쓰지 않은 이유도 있습니다. 그쪽은 자유 입력 칸이라 "한국어"라고 적을 수도, "간결하게"라고 적을 수도 있는데, 인식기는 `ko` 같은 표준 코드만 받습니다.

목록에는 **언어 코드가 있는 언어를 전부** 넣었습니다. 화면 번역과 달리 이건 그저 넘겨주는 값이라, 우리가 골라둔 몇 개로 줄일 이유가 없습니다. 대신 실제로 인식되는 20개를 위쪽에 모으고, 나머지는 그렇다고 적어둡니다.

![검색으로 찾은 스와힐리어에 "아직 인식 안 됨"이 붙어 있다](./assets/language-unsupported.png)

숨기지 않은 이유는, 목록에서 빼면 왜 없는지 알 길이 없기 때문입니다. 그렇다고 아무 표시 없이 두면 말해보고 나서야 영어로 나오는 걸 알게 됩니다.

**말이 없으면 녹음이 알아서 끝납니다.** 기본은 15초이고, **설정 → 일반 → 음성 입력 → 대기 시간**에서 더 짧게 바꿀 수 있습니다.

여기서 재는 것은 녹음한 총 시간이 아니라 조용했던 시간입니다. 말을 계속하는 동안에는 끊기지 않고, 잠시 멈출 때마다 시계가 처음으로 돌아갑니다. 녹음 하나의 총 길이는 2분까지입니다.

15초보다 길게는 설정할 수 없습니다. 인식 서비스가 15초 침묵이면 스스로 연결을 끊기 때문에, 그보다 긴 값을 넣어도 지킬 수 없는 약속이 됩니다. 같은 이유로 "자동으로 끄지 않음" 같은 선택지도 두지 않았습니다.

끝날 때는 그냥 멈추는 것이 아니라, 아직 전송되지 않은 소리를 마저 보내 텍스트로 받고 그 결과까지 입력창에 넣은 뒤에 끝납니다. 말한 마지막 한마디가 사라지지 않게 하기 위해서입니다.

이 장치가 필요한 이유는 마이크를 켜둔 채 자리를 뜨거나 그냥 잊어버리는 경우 때문입니다. 그대로 두면 녹음 표시등이 계속 켜져 있고, 받아 적을 것도 없는 연결만 열린 채로 남습니다.

## IDE 안에서 마이크 열기

IDE 안의 WebView(JCEF)는 마이크 요청에 아무도 응답하지 않으면 그냥 거절합니다. 브라우저와 달리 사용자에게 물어보는 창도 뜨지 않아서, **아무것도 안 하면 마이크가 조용히 안 열립니다.** 실패했다는 표시조차 없이 텍스트만 안 나옵니다.

그래서 플러그인이 그 요청에 직접 응답합니다. 다만 **마이크 하나만 허용합니다.** 요청은 카메라와 화면 캡처까지 함께 물어볼 수 있는 형태로 오는데, 응답할 때 마이크 비트만 남기고 나머지는 잘라냅니다. 다른 것을 요구하는 요청은 거절합니다.

따로 확인 창을 띄우지 않는 이유는, 여기서 열리는 화면이 외부 웹페이지가 아니라 우리가 직접 띄우는 채팅 화면이기 때문입니다. 진짜 결정은 OS가 합니다 — 처음 녹음할 때 macOS가 IDE에 마이크를 허용할지 묻고, 거기서 거절하면 플러그인이 무슨 응답을 하든 마이크는 열리지 않습니다.

## 시작하지 못할 때

실패하면 입력창 바로 위에 **안내 배너**가 뜹니다. 호버해야 보이는 툴팁이 아니라 배너인 이유는, 사용자가 무언가 해야 하는 안내이기 때문입니다.

세 가지 실패는 해결 방법이 각각 달라서 문구도 다릅니다. 그중 **extend-kit 미설치는 우리가 대신 해결해 드릴 수 있어서, 배너 오른쪽에 설치 버튼이 함께 뜹니다.** 누르면 그 자리에서 설치되고 배너가 사라집니다.

### "어느 패키지 매니저냐"는 사실 세 가지 질문입니다

한 단어로 답할 수 있을 것 같지만 아닙니다. 실제로는 서로 독립된 세 축입니다.

| 축 | 무엇을 관리하나 | 예 |
|---|---|---|
| **런타임 매니저** | Node **버전**을 깔고 전환 | volta, nvm, fnm, asdf, mise, nodenv, brew의 node |
| **라이브러리 매니저** | npm **패키지**를 전역 설치 | npm, pnpm, yarn, bun, volta의 자체 store |
| **앱 배포 채널** | `claude` **앱 자체**를 배포 | 공식 설치 스크립트, Homebrew cask, WinGet |

volta는 런타임과 라이브러리 **양쪽에 모두** 있습니다. Node 버전도 바꾸고 자체 패키지 store도 갖기 때문입니다.

이 셋을 한 값으로 뭉치면 표현할 수 없는 조합이 생깁니다. 예를 들어 **"brew로 깐 Node 위에서 npm으로 전역 설치"**는 흔한 구성인데, 한 단어로는 brew인지 npm인지 고를 수 없습니다.

더 중요한 건 **"volta의 자체 store"와 "volta가 관리하는 Node의 npm 전역"이 서로 다른 곳**이라는 점입니다. 둘 다 `~/.volta/` 아래라 같아 보이지만, 한쪽에서 지운 패키지가 다른 쪽에 그대로 남습니다.

### 설치는 그 머신을 관리하는 매니저로 나갑니다

설치 방법은 세 자리(이 배너의 설치 버튼, 설정의 설치 버튼, 설정의 업데이트 버튼)가 모두 같으며, **어떤 패키지 매니저로 설치할지는 터미널에서 쓰는 `claude`를 기준으로 정합니다.**

터미널에서 `claude`가 volta로 관리되고 있으면 kit도 volta로 설치합니다. pnpm이면 pnpm, yarn이면 yarn입니다. 사용자가 터미널에서 이미 선택해 둔 도구가 곧 답이기 때문입니다 — 이 프로젝트의 "CLI에서 되는 것은 GUI에서도 된다"는 기준을 설치에 적용한 것입니다.

`claude`를 찾을 수 없을 때만 백엔드를 실행 중인 Node를 기준으로 삼습니다. 나중에 kit을 불러올 Node가 그 Node이므로, 물어볼 대상이 하나뿐일 때는 그쪽이 맞습니다.

Homebrew·공식 설치 스크립트·WinGet으로 `claude`를 설치한 경우처럼 **npm 패키지를 설치할 수 없는 매니저**라면 npm으로 넘어갑니다. 이때 쓰는 npm은 PATH에서 아무거나 찾은 npm이 아니라 **백엔드 Node 옆에 있는 npm**입니다. 이 구분이 없으면 설치는 다른 Node의 전역 폴더에 성공적으로 들어가고, 성공했다고 보고되고, 정작 음성 입력은 kit을 찾지 못합니다 ([#298](https://github.com/Swttch/swttch/issues/298)).

kit이 설치되어 있지 않아 **직접 터미널에서 설치하려는 경우 안내되는 명령도 같은 기준으로 만들어집니다.** 화면이 알려주는 명령과 버튼이 실행하는 명령이 서로 다르면 안 되기 때문입니다.

### 설치한 kit은 같은 자리에서 지울 수 있습니다

설치된 상태에서는 버전 오른쪽에 **휴지통 버튼**이 있습니다. 버전을 말해주는 줄에서 그 버전을 없앨 수 있어야 하기 때문에 같은 줄에 둡니다.

평소에는 버전 글자와 같은 크기·거의 같은 색이라 눈에 띄지 않고, 마우스를 올리면 빨갛게 바뀝니다. 지우는 버튼이 설치·업데이트 버튼과 시선을 다투면 안 되지만, 누르려는 순간에는 위험하다는 것이 분명해야 하기 때문입니다.

**누르면 먼저 물어봅니다.** 지우고 나면 다시 설치하기 전까지 이 기기에서 음성 입력을 쓸 수 없고, 다시 설치하는 것은 내려받기라 한 번에 되돌릴 수 없기 때문입니다. 사용량 패널도 같은 패키지를 쓰므로 그 사실도 함께 알려줍니다.

**삭제는 설치와 달리 한 곳만 보지 않습니다.** 설치는 한 곳에 하지만, 한 머신에 같은 패키지가 **두 벌 이상 있을 수 있기 때문**입니다.

실제로 그런 경우가 있었습니다. volta의 자체 store에 0.4.0이, 그 volta가 관리하는 Node의 npm 전역에 0.3.0이 동시에 있었습니다. 설치할 때 쓰는 매니저로만 지우면 한 벌만 사라지고, 화면은 남은 쪽을 정직하게 표시합니다 — 사용자 입장에서는 **"삭제를 눌렀는데 그대로 있다"**가 됩니다.

그래서 삭제는 알고 있는 **모든 저장소를 훑습니다.** 대부분은 아무것도 없어서 실패하는데, 그건 정상이라 보고하지 않습니다.

**성공 여부는 명령의 종료 코드가 아니라 디스크로 판정합니다.** 다섯 개 도구의 종료 코드는 서로 비교할 수 없고, 실제로 "성공했다면서 아무것도 안 지우는" 경우가 있었기 때문입니다(아래 참고). 지운 뒤 kit을 다시 찾아봐서 남아 있으면 실패로 보고합니다.

끝나면 토스트로 알리고 버전 줄이 새로 고쳐집니다.

### npm은 "성공했습니다"라고 말하며 아무것도 안 할 수 있습니다

npm은 전역 폴더 위치를 설정에서 읽는데, `npm_config_prefix` 환경변수가 있으면 **그것이 모든 것을 덮어씁니다.** 어느 npm을 실행했는지와 무관합니다.

IDE나 셸 프로필, 다른 프로젝트의 도구가 이 변수를 남겨두면 백엔드가 그것을 물려받습니다. 그러면 `npm uninstall -g`가 엉뚱한 폴더를 상대로 실행되어 **`up to date`를 출력하고 정상 종료하면서 아무것도 지우지 않습니다.**

그래서 npm 명령에는 `--prefix`로 대상 폴더를 못 박습니다. 실측으로 확인했습니다 — 그 변수가 있을 때 `--prefix` 없이는 패키지가 살아남았고, 붙이자 지워졌습니다.

이건 이 기능의 설치 문제와 **같은 모양의 결함**입니다. 명령이 성공하는데 엉뚱한 곳을 상대로 성공하는 것입니다.

### 지워지지 않던 사본 하나는 패키지가 아니라 소스 파일이었습니다

삭제를 아무리 눌러도 같은 버전이 계속 표시되는 증상이 있었습니다. 원인은 **저장소에 kit 사본이 커밋되어 있었던 것**입니다.

음성 입력을 처음 만들 때 `npm i -g --prefix backend`류의 명령이 실행되어 `backend/lib/node_modules/`에 패키지가 깔렸고, `.gitignore`가 `backend/node_modules/`만 막고 있어서 74개 파일이 그대로 커밋됐습니다.

그 뒤 `npm_config_prefix`가 그 폴더를 가리키는 환경에서는 백엔드가 거기서 kit을 찾아 "설치됨"으로 보고했습니다. **삭제 버튼은 이걸 절대 못 지웁니다** — 어떤 패키지 매니저의 저장소도 아니고 git이 관리하는 소스 파일이기 때문입니다.

커밋된 사본을 제거하고, `.gitignore`가 위치에 상관없이 `node_modules/`를 막도록 고쳤습니다.

### 버전을 누르면 다시 확인합니다

kit은 이 화면 밖에서도 바뀝니다. 터미널에서 직접 설치하거나 업데이트하거나 지울 수 있기 때문입니다. 그래서 **버전 글자 자체가 "다시 확인" 버튼**입니다. 틀렸을 수 있는 값이 바로 그 버전이므로, 다시 물어보는 자리도 그 자리입니다.

kit이 어디 설치되어 있는지 알아내려면 패키지 매니저를 실제로 실행해야 해서 결과를 캐시해 둡니다. 화면을 열 때마다 매번 확인하면 느리기 때문입니다. 다만 **이 버튼을 누를 때만은 그 캐시를 무시하고 처음부터 다시 찾습니다.** 캐시를 존중하면 정작 눌렀을 때 아무 일도 일어나지 않아, 이 버튼이 존재하는 이유가 사라집니다.

| 표시되는 문구 | 실제 상황 |
| --- | --- |
| 마이크가 차단되어 있습니다 | 마이크 사용이 막혀 있음 (푸는 곳은 아래 참고) |
| 마이크를 찾을 수 없습니다 | 입력 장치가 연결되어 있지 않음 |
| 음성 입력에는 @swttch/extend-kit이 필요합니다 | 이 머신에 kit이 설치되어 있지 않음 |

**마이크가 차단된 경우, 푸는 곳은 어디서 쓰고 있느냐에 따라 다릅니다.** 그래서 안내 문구도 환경에 맞춰 달라집니다.

브라우저에서는 **주소창의 자물쇠**에서 허용한 뒤 새로고침하면 됩니다. 시스템 설정이 아닙니다. 브라우저는 한 번 거부한 사이트를 기억하고, 그 뒤로는 권한 창을 다시 띄우지 않습니다. 사이트가 창을 다시 부르는 방법은 없으며, 이건 웹 표준이 그렇게 막아둔 것입니다.

IDE 안에서는 플러그인이 마이크 요청을 직접 허용하므로 그 단계에서 막히지 않습니다. 여기서 차단되었다면 OS 차원이라, 시스템 설정에서 IDE에 마이크를 허용해야 합니다.

- **macOS**: 시스템 설정 → 개인정보 보호 및 보안 → 마이크
- **Windows**: 설정 → 개인 정보 및 보안 → 마이크 (데스크톱 앱의 마이크 접근도 켜져 있어야 합니다)

이 머신에 Claude Code가 로그인되어 있지 않으면 받아쓰기를 쓸 수 없습니다. 사용량 패널이 안 되는 것과 같은 이유로, 인증할 계정이 없기 때문입니다.

## 안정성에 대한 참고

이 기능은 Anthropic이 문서화하지 않은 엔드포인트를 사용합니다. 다른 클라이언트들이 쓰는 것과 같은 엔드포인트이며, 예고 없이 바뀔 수 있습니다. 클라이언트는 모르는 응답을 만나도 깨지지 않고 무시하도록 만들었지만, 저쪽에서 더 큰 변경이 일어나면 우리가 따라잡을 때까지 받아쓰기가 동작하지 않을 수 있습니다.
