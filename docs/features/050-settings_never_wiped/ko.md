# 설정 파일이 통째로 지워지지 않습니다

> 언어: [English](./en.md) · **한국어**

## 무엇이 문제였나

어느 사용자의 `~/.claude/settings.json`이 스무 개 키를 담고 있다가 세 개만 남았습니다.

```json
{
  "effortLevel": "high",
  "permissions": { "defaultMode": "bypassPermissions" },
  "model": "claude-fable-5[1m]"
}
```

함께 사라진 것들입니다.

`includeCoAuthoredBy`, `env`, `statusLine`, `enabledPlugins`, `mcpServers`, `disabledMcpServers`,
`disabledMcpjsonServers`, `theme`, `language`, `uiLanguage`, `alwaysThinkingEnabled`,
`preferFastMode`, `switchModelsOnFlag`, `skipDangerousModePermissionPrompt`,
`respectGitignoreForContext`, `focusInputOnEditorContext`, `useCtrlEnterToSend`.

**이 파일은 사용자의 것이지 저희 것이 아닙니다.** MCP 서버 목록, 상태줄, 플러그인 목록, CLI
설정이 전부 여기 들어 있고, 저희가 만드는 어떤 파일로도 되살릴 수 없습니다.

사라진 것을 곧바로 알아채기도 어렵습니다. 저 사용자도 나중에 커밋에 공동 작성자 줄이 붙는
것을 보고서야 알았습니다. `includeCoAuthoredBy: false`가 사라진 키 중 하나였기 때문입니다.

이 문제는 [#386](https://github.com/Swttch/swttch/issues/386)으로 제보되었습니다.

## 왜 벌어졌나

설정 하나를 저장할 때 저희는 파일 전체를 읽고, 요청받은 키만 갈아끼우고, 파일을 다시 씁니다.
JSON 파일은 가운데 몇 글자만 고쳐 쓸 수 없어서 그렇습니다.

그런데 이 파일을 쓰는 프로그램이 하나가 아닙니다. IDE에 띄운 패널, 터미널에서 실행한 `ccg`,
터미널의 `claude` 자신이 모두 같은 파일을 씁니다.

두 프로그램이 같은 순간에 쓰면 짧은 내용이 긴 내용을 다 덮지 못하고, **앞부분만 새 내용이고
뒷부분에 옛 내용의 꼬리가 남은 파일**이 됩니다. 이렇게 되면 JSON으로 읽히지 않습니다.

여기까지는 드문 사고입니다. 진짜 문제는 그 다음이었습니다.

읽기 코드가 **읽지 못한 파일을 "빈 파일"이라고 답했습니다.** 그래서 다음 저장이 그 빈 내용
위에 키 하나를 얹어 파일 전체를 갈아치웠습니다. 스무 개짜리 파일이 한 개짜리 파일로 다시
태어난 것입니다. 남아 있던 세 개는 파일이 다시 태어난 뒤에 저장된 것들입니다.

**드문 사고 하나가 확정적인 전체 삭제로 커졌습니다.**

## 무엇을 했나

### 저장이 중간에 끊기지 않습니다

이제 같은 폴더에 임시 파일을 먼저 완성한 뒤 그 파일을 원래 이름으로 바꿔 답니다. 파일을 읽는
쪽에서는 **바뀌기 전 내용이거나 바뀐 뒤 내용이지, 중간 상태는 보이지 않습니다.**

원래 파일의 권한도 그대로 이어받습니다. 사용자가 본인만 읽도록 잠가둔 파일이 저장 후에 열리지
않습니다.

### 읽지 못한 파일에는 저장하지 않습니다

파일이 있는데 읽히지 않으면, 저장을 **거부하고 파일을 건드리지 않습니다.**

파일은 저희 말고도 깨질 수 있습니다. 디스크가 가득 차거나, 프로그램이 강제 종료되거나, 다른
도구가 쓰다 말 수도 있습니다. 원인이 무엇이든 **저희가 그 파일을 지우는 쪽이 되지 않습니다.**

### 저희 안에서는 순서대로 씁니다

한 백엔드 안에서 여러 저장 요청이 겹쳐도, 하나가 끝난 뒤 다음이 시작되도록 줄을 세웠습니다.
패널 여러 개를 열어두고 동시에 설정을 바꿔도 서로의 변경을 밀어내지 않습니다.

### 적용 범위

같은 위험이 있던 파일 전부에 적용했습니다.

| 파일 | 들어 있는 것 |
|---|---|
| `~/.claude/settings.json`, `settings.local.json` | Claude Code 전역 설정 |
| `~/.claude.json` | MCP 서버 설정, 프로젝트 기록 |
| `<프로젝트>/.claude/settings.json`, `settings.local.json` | 프로젝트별 Claude Code 설정 |
| `<프로젝트>/.claude-code-gui/settings.json` | 프로젝트별 패널 설정 |
| 세션 제목 파일 | 직접 붙인 대화 제목 |
| `~/.claude-code-gui/profile.json`, `license.json` | 설치 정보, 후원 라이선스 |

## 얼마나 나아졌나

프로그램 네 개가 같은 설정 파일에 동시에 쓰는 상황을 다섯 번씩 재현해 비교했습니다.

| | 원래 있던 키가 살아남은 횟수 |
|---|---|
| 고치기 전 | **0 / 5** (매번 전부 사라짐) |
| 고친 뒤 | **5 / 5** (매번 전부 보존) |

## 아직 남은 것

서로 다른 프로그램이 **1000분의 1초 단위로 정확히 겹쳐서** 저장하면, 그 순간 상대가 새로
추가한 설정 하나가 반영되지 않을 수 있습니다.

파일이 깨지지도 않고 원래 있던 설정이 사라지지도 않습니다. 다시 저장하면 반영됩니다.

터미널의 `claude` 자신도 같은 방식으로 저장하므로 원래부터 있던 성질이며, 없애려면 한 프로그램이
저장하는 동안 다른 프로그램을 완전히 막아야 해서 이번에는 넣지 않았습니다.
