# diff 창이 저절로 뜨지 않게 하기

Claude가 파일을 고치겠다고 물어볼 때마다 diff 창이 같이 열렸습니다. 끌 방법이 없었습니다.

설정에 diff 관련 항목이 있긴 했지만, 그건 전부 **어디에 열지**를 정하는 것이었습니다. IDE의 diff 뷰어냐 우리 diff 페이지냐, 새 탭이냐 오버레이냐. 어느 값을 골라도 창은 떴습니다.

diff를 보고 판단하는 사람에겐 편한 동작이지만, 승인 패널의 내용만 읽고 넘기는 사람에겐 매번 닫아야 하는 창이 하나 더 생기는 셈이었습니다.

이번 릴리즈부터 **자동으로 열지 말지를 직접 정할 수 있습니다.**

## 어디서 끄나

**설정 → General → Diff View → diff 자동으로 열기** 를 끄면 됩니다.

Diff View 섹션의 맨 위에 있습니다. 아래 두 항목이 "어디에 열지"를 정하는 것이라, 그보다 먼저 "열지 말지"를 정하는 자리입니다.

![Diff View 설정 섹션. 맨 위에 diff 자동으로 열기 토글이 있고, 아래에 편집 검토 위치와 자체 뷰어를 여는 방식이 있다](./assets/diff-view-settings.png)

## 끄면 어떻게 되나

승인 패널만 뜨고 거기서 멈춥니다. diff 창은 열리지 않습니다.

![승인 패널만 떠 있는 화면. Write to cart.js? 라는 질문과 Yes·No 선택지가 있고, diff 창은 없다](./assets/prompt-without-diff.png)

*파일 이름 `cart.js` 는 링크로 남아 있습니다. 누르면 그때 diff가 열립니다.*

**변경 내용을 못 보게 되는 건 아닙니다.** 승인 패널의 파일 이름은 그대로 링크로 남아 있고, 그걸 누르면 diff가 열립니다. 자동으로 오지 않을 뿐, 보고 싶을 때 보면 됩니다.

제안된 변경은 어느 쪽이든 보관됩니다. 그래서 패널을 한참 놔뒀다가 나중에 눌러도 똑같이 열립니다.

## 기본값은 켜져 있습니다

지금까지 쓰던 동작이 기본값입니다. 업데이트했다고 해서 diff가 갑자기 안 뜨는 일은 없습니다.

## 이 설정이 적용되는 순간

Claude가 **파일 편집 권한을 물어볼 때**입니다.

`Ask before edits` 가 아니라 `Auto edit` 이나 `Bypass permissions` 로 쓰고 있다면 Claude가 애초에 물어보지 않으므로, 원래부터 diff가 뜨지 않았고 이 설정과도 무관합니다.

파일을 고치지 않는 작업(명령 실행, 파일 읽기 등)도 마찬가지입니다. 보여줄 변경 자체가 없으니 예전에도 지금도 승인 패널만 뜹니다.
