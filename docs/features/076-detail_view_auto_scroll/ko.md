# 백그라운드 작업 상세 화면도 채팅처럼 스크롤됩니다

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#511](https://github.com/Swttch/swttch/issues/511) · 이어지는 문서: [위로 올려 읽는 동안 화면이 바닥으로 끌려가지 않습니다](../023-auto_scroll_stays_put/ko.md)

## 제보

한 사용자가 이렇게 알려주셨습니다.

> 백그라운드 작업으로 가서 실행 중인 에이전트나 워크플로우를 열고 스크롤바 위치를 옮기면, 다음 도구 호출이 일어날 때마다 맨 위나 맨 아래, 혹은 엉뚱한 곳으로 이동합니다. 전혀 움직이면 안 됩니다.

실행 중인 에이전트의 상세 창에서 지난 내용을 읽으려고 스크롤을 위로 올렸는데, 에이전트가 다음 도구를 호출하는 순간 창이 저절로 움직였다는 이야기입니다.

## 실제로 벌어지던 일

**백그라운드 작업** 패널은 작업마다 상세 창을 엽니다. 워크플로우 에이전트, 백그라운드 에이전트, 일반 백그라운드 명령, 이렇게 세 종류입니다. 이 세 창은 각자 "가장 새 출력을 따라가는" 로직을 따로 복사해서 들고 있었습니다. 그사이 메인 채팅은 훨씬 꼼꼼한 방식으로 발전했는데, 세 복사본은 그 변화를 따라가지 못했습니다.

제보된 증상의 원인은 **워크플로우 에이전트** 창이었습니다. 이 창은 에이전트의 수치(토큰, 도구 호출 수, 경과 시간)가 바뀔 때마다 대화 기록을 다시 불러옵니다. 다시 불러오는 동안 창은 대화 기록을 로딩 스피너로 바꿔치기했다가, 새 스크롤 영역을 처음부터 다시 그렸습니다. 새로 그려진 스크롤 영역은 맨 위에서 시작하기 때문에, 위로 올려 읽던 사람은 도구가 호출될 때마다 처음으로 돌아가게 됐습니다.

그 밖의 차이는 눈에 덜 띄는 것들이었습니다.

- 상세 창은 "그 순간의 위치"만 보고 따라갈지 정했습니다(바닥에서 24픽셀 이내인지). 그래서 긴 출력이 한꺼번에 들어오면 따라가기를 포기했습니다. 메인 채팅은 사용자가 무엇을 했는지로 정합니다. 위로 스크롤했을 때만 멈춥니다.
- "맨 아래로 스크롤" 버튼은 위로 올렸을 때가 아니라 새 출력이 도착한 뒤에야 나타났습니다. 문구도 "Jump to bottom"이었고, 부드럽게 내려가지 않고 순간이동했습니다.
- "계속 따라가는 범위"가 **자동 스크롤 재개 거리** 설정을 무시하고 24픽셀로 고정되어 있었습니다.
- 따라가기는 새 데이터가 도착할 때만 다시 확인했습니다. 데이터는 그대로인데 블록이 길어지는 경우(코드 블록의 레이아웃이 끝나는 경우 등)는 놓쳤습니다.
- 창에서 에이전트에게 메시지를 보내도 바닥으로 돌아오지 않았습니다.
- 워크플로우에서 다른 에이전트를 고르면 앞 에이전트의 스크롤 상태가 그대로 이어졌습니다.
- 일반 백그라운드 명령의 로그는 20만 자를 넘으면 앞부분이 잘립니다. 잘릴 때마다 읽고 있던 줄이 한 줄씩 위로 밀려 올라갔습니다.

## 무엇이 바뀌었나

세 상세 창이 이제 메인 채팅과 같은 자동 스크롤을 씁니다. 복사본 세 벌이 아니라 하나의 공용 코드이므로, 다시 서로 어긋날 수 없습니다.

- **스크롤 위치는 사용자의 것입니다.** 위로 올리면 에이전트가 계속 일해도 창이 그 자리에 머뭅니다. 이미 화면에 떠 있는 대화 기록은 스피너로 바뀌지도, 다시 그려지지도 않습니다.
- **따라가기는 사용자가 한 행동을 따릅니다.** 바닥 근처에서는 새 출력을 따라가고, 작업이 실행 중이면 부드럽게 내려갑니다. 자동 스크롤 재개 거리를 넘어 위로 올리면 멈추고, 그 거리 안으로 돌아오면 다시 따라갑니다.
- **"맨 아래로 스크롤" 버튼**은 바닥에서 벗어나는 순간 나타납니다. 메인 채팅과 같은 버튼이고 문구도 같습니다. 부드럽게 바닥으로 내려가고 따라가기를 다시 켭니다.
- **에이전트에게 메시지를 보내면** 바로 바닥으로 내려갑니다. 보낸 메시지는 에이전트가 받아 간 뒤 몇 초 지나서야 기록에 나타나는데, 그 사이에도 기다리지 않습니다.
- **워크플로우의 에이전트마다** 스크롤 상태를 따로 가집니다.
- **명령 로그는 앞부분이 잘려도 읽던 자리를 지킵니다.** 읽고 있던 줄이 제자리에 있습니다. 얼마나 잘렸는지 알아낼 수 없는 경우(똑같은 줄만 반복되는 로그 등)에는 짐작해서 움직이지 않고 위치를 그대로 둡니다.
- **새로고침 실패는 드러냅니다.** 읽는 도중 에이전트의 대화 기록을 다시 불러오는 데 실패하면, 마지막으로 불러온 기록이 화면에 남고 그 아래에 "기록을 새로 불러오지 못했습니다. 마지막으로 불러온 내용을 보여주고 있습니다." 한 줄이 나옵니다. 다시 성공하면 사라집니다.

## 바뀌지 않은 것

- 상세 창은 닫았다가 다시 열 때 **예전 위치를 기억하지 않습니다.** 열 때마다 가장 새 출력에서 시작합니다. 여기서는 기억한 위치가 금방 낡아 버립니다. 창이 닫혀 있는 동안에도 실행 중인 작업은 출력을 계속 쌓으므로, 기억한 위치로 열면 중간에서 시작하고 따라가기도 꺼져 있게 됩니다. 메인 채팅은 이전처럼 세션별로 위치를 기억합니다.
- 메인 채팅은 이전과 똑같이 동작합니다. 자동 스크롤을 공용 코드로 옮겼을 뿐 동작은 바꾸지 않았습니다.
- 자동 스크롤 재개 거리 설정(설정 → 모양 → 스크롤)은 이제 상세 창에도 적용됩니다. 범위와 기본값(80픽셀)은 그대로입니다.

## 이상하다 싶을 때

- **실행 중인 작업을 창이 따라가지 않습니다.** 위로 스크롤하지 않았는지 확인해 보세요. "맨 아래로 스크롤" 버튼이 보이는 때가 정확히 따라가기가 꺼진 때입니다. 버튼을 누르거나 바닥 근처로 다시 스크롤하면 됩니다.
- **대화 기록이 오래된 것 같습니다.** 기록 아래에 "기록을 새로 불러오지 못했습니다" 줄이 있는지 보세요. 마지막 새로고침이 실패해서 이전 기록을 보여주고 있다는 뜻입니다.
