# Docker로 도는 MCP 서버가 더 이상 컨테이너를 쌓지 않습니다

> 언어: [English](./en.md) · **한국어**

## 무엇이 문제였나

MCP 서버를 Docker로 띄우는 설정은 흔합니다.

```json
{
  "mcpServers": {
    "postgres-dev": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "crystaldba/postgres-mcp:latest"]
    }
  }
}
```

`--rm`이 붙어 있으니 끝나면 알아서 지워질 것처럼 보입니다. 그런데 **MCP 패널을 새로고침할
때마다 컨테이너가 두 개씩 늘어나고, 하나도 지워지지 않았습니다.** 제보자는 반나절 만에 67개가
쌓여 4.2GB를 물고 있는 것을 발견했습니다.

이 컨테이너들은 흔한 정리 스크립트에도 걸리지 않습니다. `exited`도 아니고 오래되지도 않은,
멀쩡히 `Up` 상태인 컨테이너라서 상태나 나이로 거르는 필터를 전부 통과합니다.

## 왜 `--rm`이 동작하지 않았나

`docker run`으로 띄운 서버에서 **우리가 붙잡고 있는 것은 컨테이너가 아니라 `docker`
클라이언트**입니다. 컨테이너는 데몬이 들고 있고, 클라이언트는 그 스트림에 붙어 있을 뿐입니다.

서버를 정리할 때는 stdin을 닫고, 안 죽으면 SIGTERM, 그래도 안 죽으면 SIGKILL을 보냅니다. 이
세 단계가 **전부 클라이언트에게** 갑니다. 컨테이너 안의 PID 1이 EOF로 종료하지도 않고 SIGTERM을
처리하지도 않으면 세 단계를 전부 살아남고, `--rm`은 **컨테이너가 끝나기를** 기다리는 옵션이라
영영 발동하지 않습니다.

Docker는 누가 그 컨테이너를 띄웠는지도 기록해두지 않습니다. 클라이언트를 죽이기 전과 후의
`docker inspect`를 비교하면 **바뀌는 필드가 하나도 없고** 라벨도 비어 있습니다. 그래서 나중에
"이건 고아다"라고 알아볼 방법이 없습니다.

## 무엇이 달라졌나

### 새로고침이 서버를 다시 띄우지 않습니다

이전에는 패널이 상태를 알아내려고 `claude mcp list`와 `claude mcp get`을 **매번 새로
실행**했습니다. 그 명령들은 각자 CLI를 부팅해 모든 서버에 접속해보기 때문에, 상태를 물어보는
행위 자체가 서버를 두 번 더 띄우는 일이었습니다.

이제는 **이미 떠 있는 CLI에게 물어봅니다.** 사용자의 채팅이 붙어 있는 그 프로세스가 이미 서버
연결을 들고 있으므로, 아무것도 새로 띄우지 않고 답을 받습니다.

덤으로 정확해졌습니다. 예전에는 **다른 프로세스가 방금 찔러본 결과**를 보여줬기 때문에, 채팅이
실제로 붙어 있는 상태와 화면이 어긋날 수 있었습니다. 지금은 같은 프로세스에게 묻습니다.

도구 목록도 같은 답변에 함께 옵니다. 서버 상세를 열 때 목록을 받으려고 **다시 접속하던 것**이
사라졌습니다.

물어볼 CLI가 없을 때(채팅을 아직 시작하지 않은 상태)는 예전처럼 공식 명령으로 답합니다. 그
경로는 그대로 살아 있습니다.

### 필요 없는 곳에서는 아예 안 띄웁니다

Fable 모델을 쓸 수 있는지 확인하는 내부 점검은 모델에게 한 마디 물어보고 끝나는 것이라 MCP
서버가 전혀 필요 없는데도, 워크스페이스의 서버를 전부 띄우고 컨테이너를 하나씩 남겼습니다.
이제 서버를 하나도 읽지 않도록 바꿨습니다.

### 남는 것은 회수합니다

채팅 세션과 `mcp` 명령은 서버가 정말로 필요하므로, 그쪽은 끝난 뒤에 치우는 수밖에 없습니다.

CLI를 띄우기 직전에 그 이미지의 컨테이너 목록을 찍어두고, **그 CLI가 종료할 때** 다시 찍어
차이를 봅니다. 그 사이에 새로 생겼고 **설정에 적힌 이미지와 실행 인자가 정확히 일치하는**
컨테이너만 제거합니다. 둘 중 하나만으로는 건드리지 않습니다. 사용자가 직접 같은 이미지를 띄운
컨테이너를 지우지 않기 위해서입니다.

기준을 **"세션이 끝났을 때"가 아니라 "CLI 프로세스가 끝났을 때"**로 잡았습니다. 하나의 채팅
세션은 여러 CLI 프로세스보다 오래 삽니다. 파이프가 끊기거나, `--resume`으로 이어받거나, 권한
모드를 바꾸면 프로세스가 새로 뜨고 **그때마다 컨테이너가 하나씩 더 생깁니다.** 세션 종료를
기다렸다면 그 사이의 것들이 전부 쌓였을 것입니다.

### 플러그인이 강제로 종료돼도 남지 않습니다

백엔드가 정상 종료가 아니라 강제로 끝나면 위의 회수 코드가 돌 기회조차 없습니다. 그래서 각
채팅 CLI는 자기가 띄운 컨테이너의 id를 **미리 기록해둡니다.** 다음번에 플러그인이 켜질 때 그
기록을 보고 남은 것을 치웁니다.

이때 다른 창에서 돌고 있는 세션의 컨테이너는 건드리지 않습니다. 정리 대상은 **주인이 이미
사라진 기록**뿐입니다.

## Docker를 쓰지 않는다면

설정에 `docker`로 실행되는 MCP 서버가 하나도 없으면 이 기능은 **코드가 실행되지도
않습니다.** 설정을 먼저 확인하고 거기서 멈춥니다. Docker가 설치돼 있지 않은 경우에도
마찬가지로 조용히 넘어가며, 어떤 경우에도 "확신이 없으면 지우지 않는" 쪽으로 실패합니다.
