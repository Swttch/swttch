# 검토하는 동안 파일이 바뀌면 알려줍니다

Claude가 파일 수정을 제안하면, 그 시점의 파일 내용을 읽어서 diff를 만들어 보여줍니다.

그런데 승인 버튼을 누르기까지는 시간이 걸립니다. 그 사이에 파일이 계속 바뀔 수 있습니다 — IDE에서 직접 고치고 계셨거나, 다른 세션이 같은 파일을 만졌거나, 브랜치를 옮겼거나.

지금까지는 승인할 때 **파일을 다시 읽지 않았습니다.** 처음 읽어둔 내용을 그대로 썼습니다.

그래서 그 사이 생긴 변경은 확인 없이 사라졌습니다. 실제로 1,090줄짜리 파일이 1줄이 된 제보가 있었고, 커밋하지 않은 작업이 함께 날아갔습니다 ([#359](https://github.com/Swttch/swttch/issues/359)).

이번 릴리즈부터 **파일이 바뀌면 알려드리고, 바뀐 채로는 승인이 진행되지 않습니다.**

## 검토하는 중에 알려줍니다

승인 대기 중인 파일을 IDE에서 저장하면, diff 화면 위에 안내가 뜹니다.

승인 버튼을 누르기 전에 뜨기 때문에, 헛수고를 하지 않아도 됩니다.

## 승인할 때 한 번 더 막습니다

안내를 못 보고 승인하셨거나, 감지가 늦었을 수도 있습니다.

그래서 승인 버튼을 누르는 순간에도 파일을 다시 읽어서 확인합니다. 처음과 다르면 **아무것도 쓰지 않고 멈춥니다.**

이때 요청은 사라지지 않습니다. 그대로 살아있어서, 정리한 다음 다시 승인하시면 됩니다.

## 최신화 버튼

안내에 있는 **최신화** 를 누르면, 지금 디스크에 있는 파일을 기준으로 제안을 다시 만들어 보여줍니다.

그 다음 승인하시면 현재 파일 위에 적용되므로, 편집 중이던 내용이 사라지지 않습니다.

다만 **헝크별로 골라두신 선택은 초기화됩니다.** 그 선택은 바뀌기 전 파일의 줄 번호를 가리키고 있어서, 그대로 옮기면 엉뚱한 줄을 가리키게 됩니다. 다시 골라주세요.

## 같은 줄이 겹칠 때

Claude가 고치려는 부분과, 그 사이 바뀐 부분이 서로 다른 곳이면 최신화로 깔끔하게 해결됩니다.

문제는 **같은 줄을 양쪽에서 다르게 고친 경우**입니다.

이때는 저희가 알아서 합치지 않습니다. 어느 쪽이 맞는지 저희는 알 수 없고, 잘못 합치면 지금 고친 것과 똑같은 사고가 조용히 다시 나기 때문입니다. git 도 이 지점에서는 사람에게 넘깁니다.

대신 겹쳤다는 사실을 그대로 알려드립니다. 최신 파일을 보시고 직접 판단해주세요.

## 파일이 사라진 경우

승인 대기 중에 파일이 지워졌다면 적용할 대상이 없습니다.

이때는 최신화 버튼도 뜨지 않습니다. 되돌릴 방법을 알려드릴 수 없어서, 상황만 알려드립니다.

## 브라우저에서 쓰실 때

저장을 감지하는 것은 IDE 가 알려주기 때문에 가능합니다. 브라우저로 접속해 쓰실 때는 그 안내가 뜨지 않습니다.

다만 **승인할 때 막는 것은 어느 환경에서나 동작합니다.** 파일이 사라지는 일은 브라우저에서도 일어나지 않습니다.
