# /btw 곁가지 질문 창

> 언어: [English](./en.md) · **한국어**
>
> 관련: [GUI에서 쓰는 /reload-plugins 와 /btw](../028-cli_only_slash_commands/ko.md) · [#543](https://github.com/Swttch/swttch/issues/543)

## 새로워진 점

`/btw` 곁가지 질문이 더 이상 채팅에 들어가지 않습니다. **채팅 위에 떠 있는 별도 창**이 열리고, 창의 제목은 `/btw`를 풀어 쓴 **By the way**입니다. 이 창은 채팅을 어둡게 가리거나 막지 않으므로, 창이 열려 있어도 채팅에서 계속 작업할 수 있습니다. 질문과 답은 그 창에 머물고, **메인 채팅에는 아무것도 echo되지 않으며**, 메인 에이전트는 하던 일을 계속합니다. 그래서 곁가지 답이 메인 응답 한가운데에 끼어드는 일이 없습니다.

## 곁가지 질문 하기

입력창에 `/btw` 뒤에 질문을 적습니다.

```
/btw 이 플래그는 무슨 뜻이야?
```

창이 열리고 질문과 "생각 중…" 줄이 보이다가 답이 나옵니다. 메인 대화는 그대로 두며, 중단되지도 않고 질문이 대화에 추가되지도 않습니다.

![메인 에이전트의 저장소 설명이 뒤에 그대로 보이는 채팅 위에 열린 "Side question" 창. 오른쪽에 "What does the --resume flag do?" 질문이 있고, 그 아래 점이 깜빡이며 "Thinking…"이 표시된다.](./assets/side-question-pending.png)

![답이 도착한 같은 창. `claude --resume <session-id>`, ID 없는 `claude --resume`, `--continue`(`-c`), `--fork-session`을 정리한 답이 서식대로 보이고, 창 뒤의 메인 대화는 그대로다.](./assets/side-question-answered.png)

**`/btw`만** 입력하면 창만 빈 채로 열리고 "진행 중인 작업에 대해 무엇이든 물어보세요 — 메인 에이전트는 계속 작업합니다." 안내가 나옵니다. 빈 곁가지 질문에 CLI는 사용법 한 줄만 답하기 때문에 아무것도 보내지 않습니다.

![빈 채팅 위에 열린 "Side question" 창. 부제는 "Answered without interrupting the main conversation, and not added to it."이고, 목록은 비어 있으며 "Ask anything about what is going on — the main agent keeps working."라는 안내가 보인다. 아래에는 "Ask a quick side question…"이라고 적힌 창 자체의 입력창이 있다.](./assets/side-question-window-empty.png)

창에는 **자체 입력창**이 있습니다. 거기에 쓴 것은 모두 곁가지 질문으로 보내지므로 `/btw`를 다시 쓸 필요가 없습니다. 거기서 슬래시 명령어를 치면 그 명령어가 실행되는 것이 아니라 **그 명령어에 대한** 질문이 됩니다.

## 열고 닫기

| 동작 | 방법 |
|------|------|
| 열기 | `/btw` 입력(질문이 있든 없든), 또는 ⋮ 메뉴의 **By the way** 선택. ⋮ 메뉴 행의 눈 모양 토글로 다른 도크 항목처럼 헤더 도크에 꺼내 둘 수 있습니다 |
| 어디서든 토글 | macOS는 **Cmd+Shift+B**, Windows·Linux는 **Ctrl+Shift+B**. 단축키 도움말에도 있습니다. 구석의 버튼으로 접어 둔 상태에서는 닫지 않고 창을 되살립니다 |
| 닫기 | **닫기** 버튼, 또는 창에 포커스가 있을 때의 **Escape**. 창 밖에서 누른 Escape는 계속 채팅의 것입니다 |
| 최소화 | **빼기(−)** 버튼이 창을 화면 우측 하단, 채팅 입력창 바로 위의 작고 둥근 말풍선 버튼으로 접습니다. 버튼에 마우스를 올리면 "By the way" 툴팁이 뜨고 버튼 우상단에 작은 **X**가 나타나며, X를 누르면 창이 완전히 닫힙니다. 버튼을 누르면 창이 접기 전 자리 그대로 다시 열립니다. 버튼의 깜빡이는 점은 질문에 답하는 중이라는 뜻이고, 색이 있는 점은 접어 둔 사이 답이 도착했다는 뜻입니다(마우스를 올리는 동안에는 점 자리에 X가 나옵니다) |
| 최대화 | **확대** 버튼(또는 제목줄 더블클릭)이 창의 상하좌우에 1rem씩만 남기고 화면을 채웁니다. 같은 버튼이나 다시 더블클릭하면 이전 크기와 위치로 돌아갑니다 |
| 이동 | **제목줄**을 끕니다 |
| 크기 조절 | **네 변과 네 모서리** 어디든 끕니다 |
| 비우기 | 헤더의 **휴지통** 버튼이 목록을 비웁니다 |

최소화와 최대화는 튀지 않고 부드럽게 이어지며, 창을 끄는 동안에는 인터페이스를 확대한 상태에서도 창이 포인터 바로 아래에 붙어 따라옵니다. 창을 닫아도 질문은 잃지 않습니다. 다시 열면 질문이 그대로 있습니다(창 자체는 기본 크기와 위치로 다시 열립니다).

## 무엇이 얼마나 보관되나

- 곁가지 질문은 **세션별**로 보관됩니다. 다른 세션으로 옮기면 그 세션의 곁가지 질문이 보입니다.
- **메모리에만** 보관됩니다. GUI를 새로고침하거나 IDE를 재시작하거나 탭을 닫으면 사라집니다. CLI도 곁가지 질문을 세션 기록에 쓰지 않으므로 되살릴 곳이 없습니다.
- 휴지통 버튼으로 비우면 완전히 지워집니다.

## 질문이 Claude에 닿지 못했을 때

요청이 CLI에 닿지 못하거나, CLI가 답하기 전에 멈추면(비정상 종료, 시작 실패) 질문은 **창 안에서 실패로 표시**됩니다. 화면에는 "Couldn't get an answer from Claude for this side question. Try again."이 뜹니다. Claude가 다시 실행된 뒤 질문을 다시 보내세요.

질문은 **대신 메인 채팅으로 보내지지 않습니다**. `/btw …`를 그곳에 일반 텍스트로 보내면 곁가지 질문이 정작 끼어들지 않아야 할 대화에 들어가고, CLI도 그 자리에서는 거절합니다([#270](https://github.com/Swttch/swttch/issues/270)).

곁가지 질문은 **메인 에이전트를 재시작하지도 않습니다**. 세션에 CLI가 있지만 그 순간 입력을 받을 수 없으면(예: 아직 시작 중), GUI가 그 아래에서 Claude를 다시 띄우는 대신 질문이 실패합니다.

### 이전 세션을 열고 가장 먼저 물을 때

기록에서 연 세션에서 `/btw`가 첫 동작이면, GUI가 답하기 위해 **그 세션의 CLI를 띄웁니다**. 전에는 실행 중인 CLI가 아직 없어서 질문이 메인 채팅의 텍스트로 넘어갔습니다. 첫 메시지로 `/btw`를 쓰는 새 채팅도 같습니다.

## 한계

- 곁가지 질문은 저장되지 않아 GUI를 새로고침하면 사라집니다.
- 대화에 추가되지 않으므로 Claude의 메인 흐름은 곁가지 질문을 알지 못합니다.
- 창에서 친 슬래시 명령어는 실행되지 않고 질문의 대상이 될 뿐입니다.
