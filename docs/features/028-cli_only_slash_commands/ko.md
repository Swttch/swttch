# `/reload-plugins` 와 `/btw` 를 GUI에서도 쓸 수 있습니다

터미널에서는 되는 슬래시 명령 두 개가 여기서는 아무 일도 하지 않았습니다.
`/reload-plugins` 를 입력하면 이렇게 답했습니다.

> /reload-plugins isn't available in this environment.

그마저도 입력하는 동안 명령 목록에 뜨지 않아, 그런 명령이 있다는 것조차 알 수
없었습니다. `/btw` 도 같은 이유로 목록에 없었습니다.

이제 둘 다 GUI에서 실행되고, 명령 목록에 뜨며, 결과를 채팅에 보여줍니다.

## 무엇을 하는 명령인가

| 명령 | 하는 일 |
| --- | --- |
| `/reload-plugins` | 현재 세션에 반영 대기 중인 Claude Code 플러그인 변경을 활성화합니다 — 플러그인을 설치·업데이트·수정한 뒤 재시작 없이 반영합니다 |
| `/btw <질문>` | 진행 중인 대화를 건드리지 않고 짧은 곁가지 질문을 합니다 |

`/reload-plugins` 는 실행 후 어떤 플러그인이 활성화돼 있는지 알려주고, 불러오지
못한 플러그인이 있으면 그것도 함께 알려줍니다. 동시에 명령 목록도 새로 읽어오므로,
다시 불러온 플러그인이 가져온 명령과 에이전트를 곧바로 쓸 수 있습니다.

`/btw` 는 질문을 인자로 받아(`/btw 이 플래그는 무슨 뜻이야?`) 채팅에 답하며, 진행
중이던 대화는 그대로 둡니다.

## 왜 없었나

이 플러그인이 걸러낸 것이 아닙니다. 애초에 오지 않았습니다.

GUI는 Claude Code CLI를 **비대화형** 세션으로 실행하는데, CLI는 일부 내장 명령을
터미널 전용으로 표시해 둡니다. 그런 명령에 대해 CLI는 두 가지를 합니다. 우리에게
보내는 명령 목록에서 빼고, 그래도 텍스트로 보내면 "isn't available in this
environment" 로 거절합니다. 제보에 찍힌 문구가 바로 그것입니다.

한편 CLI는 같은 일을 하는 요청을 직접 받아줍니다. CLI의 다른 비터미널 클라이언트들도
그 방식으로 이 명령들을 실행합니다. 이제 GUI는 이미 CLI를 제어하는 데 쓰던 통로로
그 요청을 보내, 터미널에서와 같은 동작을 하게 합니다.

그 요청을 전달하지 못하면 명령을 평문으로 대신 보냅니다. 그러면 적어도 CLI가 직접
설명하는 답을 받게 되고, 아무 반응 없이 끝나지 않습니다.

## 바뀌지 않은 것

`/context` 와 `/usage` 는 그대로입니다. 이 둘은 CLI가 GUI에도 원래 제공하는
명령이고, 각각 이 플러그인 고유의 표시 방식을 갖고 있습니다 — `/context` 는 컨텍스트
사용량 카드로, `/usage` 는 계정 사용량 모달로 열립니다. 지금까지와 똑같이 동작합니다.
