# 이미 적어둔 설정이 이제 전부에 닿습니다

> 언어: [English](./en.md) · **한국어**

## 무엇이 문제였나

Claude Code는 `settings.json`에 환경변수를 적을 수 있게 해줍니다.

```json
{
  "env": {
    "HTTPS_PROXY": "http://proxy.example.com:8080",
    "CLAUDE_CODE_OAUTH_TOKEN": "sk-ant-oat01-..."
  }
}
```

`claude` CLI는 그 파일을 읽어 블록을 먼저 적용합니다. 그런데 머신의 다른 어떤 프로그램도 그러지 않습니다. 거기 적은 값은 진짜 환경변수가 아닙니다. 어떤 셸도 export하지 않았고, 다른 프로그램은 그 파일을 찾아보지 않습니다.

그래서 이 플러그인이 값을 직접 날라야 했는데, 여덟 개의 이름 목록을 들고 날랐습니다. `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, 그리고 같은 넷의 소문자 표기입니다. 그 블록에 적은 다른 것은 아무 데도 가지 못했습니다.

이 목록은 두 번 늘어났고, 두 번 다 누군가 벽에 부딪힌 뒤였습니다.

- `settings.json`에만 적은 프록시가 사용량 패널에 닿지 않았습니다([#181](https://github.com/Swttch/swttch/issues/181)). 이름 네 개를 더했습니다.
- 같은 변수의 소문자 표기는 여전히 닿지 않았습니다([#432](https://github.com/Swttch/swttch/pull/432)). 네 개를 또 더했습니다.
- `claude login` 대신 `CLAUDE_CODE_OAUTH_TOKEN`으로 인증한 분에게 음성 입력이 `401`로 실패했습니다([#457](https://github.com/Swttch/swttch/issues/457)). 이것이 아홉 번째 이름이 될 차례였습니다.

제보는 셋이지만 벽은 하나였습니다. 그리고 그것과 별개로, 플러그인이 스스로 보내는 요청(후원 라이선스 확인, 업데이트 알림, 공지)은 목록에 어떤 이름이 있든 프록시를 아예 무시했습니다.

## 무엇을 했나

### 목록을 없앴습니다

`env` 블록을 통째로 읽습니다. 거기 적은 것은 무엇이든 적용되며, `claude` 자신이 쓰는 것과 같은 규칙을 따릅니다.

| 이렇게 적으면 | 이렇게 적용됩니다 |
| --- | --- |
| `"HTTPS_PROXY": "http://proxy:8080"` | 적은 문자열 그대로 |
| `"PORT": 8080` | `"8080"` — 숫자는 문자열이 됩니다 |
| `"DEBUG": true` | `"true"` — 참거짓도 마찬가지입니다 |
| `"EMPTY": ""` | 빈 값. 지우는 것과는 다릅니다 |
| `"PATHISH": "${HOME}/x"` | `${HOME}/x` 글자 그대로. `claude`도 치환하지 않습니다 |

전역 `~/.claude/settings.json`과 프로젝트의 `.claude/settings.json`을 모두 읽고, 각각 옆에 있는 `settings.local.json`도 그 순서로 읽습니다. 뒤에 오는 파일이 자기가 언급한 이름을 이기고, 나머지는 건드리지 않습니다.

설정 파일에 적은 값은 셸에 export한 값을 이깁니다. `claude`가 그렇게 동작하며, 파일 하나가 한 가지를 뜻하게 하려는 것입니다.

### 음성 입력이 이미 쓰던 토큰을 받아들입니다

`claude setup-token`으로 인증하고 토큰을 `settings.json`에 넣어두셨다면 음성 입력이 동작합니다. 전에는 안 됐고, 그때 나온 `401`은 계정이나 구독의 문제가 아니었습니다. 아무도 그 토큰을 읽지 않았던 것입니다.

저장된 로그인이 만료됐을 때 "사용 가능"이라고 답하던 것도 고쳤습니다. 준비됐다고 해놓고 말하는 순간 실패하곤 했습니다.

### 프록시가 플러그인 자신의 통신도 나릅니다

플러그인이 스스로 가져오는 다섯 가지가 이제 프록시를 거칩니다. 후원 라이선스 확인, 플러그인 업데이트 확인, 공지, MCP 서버 레지스트리, 사용량 텔레메트리입니다.

이 중 후원 라이선스가 가장 중요합니다. 회사 프록시 뒤에서 후원해 주신 경우 확인 요청이 저희에게 닿지 못했고, 플러그인은 키가 정상이라는 것을 알 방법이 없었습니다([#256](https://github.com/Swttch/swttch/issues/256)).

`NO_PROXY`도 존중합니다. 자기 머신을 가리키는 주소(`localhost`, `127.0.0.1`)는 프록시를 건너뜁니다. 머신을 떠나지도 않는 요청이 프록시를 돌아갈 이유가 없기 때문입니다.

### 모든 동작이 맞는 프로젝트의 로그인을 씁니다

`CLAUDE_CONFIG_DIR`로 프로젝트마다 다른 Claude 데이터 디렉토리를 지정하셨다면, 이제 모든 동작이 그 프로젝트의 디렉토리를 씁니다. 전에는 몇 가지가 그러지 않았고, 가장 최근에 연 프로젝트의 디렉토리를 썼습니다.

로그인이 그중 하나였습니다. `claude auth login`은 자격증명을 **쓰는** 명령이라, 잘못된 맥락에서 로그인하면 다른 프로젝트의 디렉토리에 저장되었습니다. 로그인은 성공했는데 플러그인은 로그아웃 상태로 보여주게 됩니다.

## 하실 일

`ccb`를 **0.7.3 이상**으로 업데이트해 주십시오. 설정의 음성 항목에 설치된 버전과 업데이트 버튼이 함께 표시됩니다.

옛 `ccb`는 설정 파일을 읽지 못합니다. 그래서 플러그인이 그런 버전을 쓰지 않고 업데이트하라고 안내합니다. 아무 데도 가리키지 못하는 방식으로 실패하는 것보다 낫기 때문입니다.

그 밖에 바뀌는 것은 없습니다. 터미널에서 `claude`로 잘 쓰고 계신 설정이라면 여기서도 그대로 동작합니다.
