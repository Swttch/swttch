# 음성 입력 키트 설치가 "됐다"고만 하고 안 되던 문제

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#298](https://github.com/Swttch/swttch/issues/298)

## 제보

v0.27.0 에서 음성 입력을 써보려던 사용자가 [#298](https://github.com/Swttch/swttch/issues/298)
을 올렸습니다. 마이크 버튼을 눌러도, 설정에서 직접 설치를 눌러도 결과가 같았습니다.

> 설치가 성공했다고 표시되는데도 설치가 안 됩니다. 그래서 음성 입력을 쓸 수 없어요.

곧 다른 사용자도 같은 증상을 겪는다고 댓글을 달았습니다.

v0.27.1 에서 원인 하나를 고쳤고 최초 제보자는 해결됐다고 확인해줬습니다. 그런데
두 번째 제보자는 업데이트 후에도 여전히 안 됐습니다. 그가 남긴 기록이 이번 수정의
단서가 됐습니다.

터미널에서 직접 설치해봤더니 이렇게 나왔습니다.

```
added 2 packages in 855ms
```

성공입니다. 그런데도 화면은 그대로였습니다. 그리고 몇 분 뒤 이런 댓글이 달렸습니다.

> 방금 다시 해봤는데, 두 번째에는 되네요 :)

**똑같은 명령을 한 번 더 돌렸더니 됐다**는 겁니다.

## 왜 "성공"이 성공이 아니었나

설치가 끝났는지를 우리는 **명령의 종료 코드**로 판단하고 있었습니다. `npm install`
이 0 을 반환하면 설치 완료로 보고 화면에 성공이라고 띄웠습니다.

문제는 종료 코드가 답해주는 질문이 우리가 궁금한 질문이 아니었다는 점입니다.

종료 코드가 말해주는 것은 **"명령이 잘 돌았나"** 입니다.
정작 사용자에게 중요한 것은 **"이제 음성 입력을 쓸 수 있나"** 입니다.

이 둘은 놀랄 만큼 자주 갈라집니다. 전역 npm 패키지가 어디에 깔리는지에 정답이
하나가 아니기 때문입니다.

| 도구 | 패키지가 깔리는 곳 |
|------|-------------------|
| volta | `~/.volta/tools/image/packages/…` (자기만의 저장소) |
| pnpm | `~/Library/pnpm/global/…` |
| yarn | `~/.config/yarn/global/…` |
| npm | 활성화된 Node 의 `lib/node_modules` |

여기에 `npm_config_prefix` 환경변수까지 끼면, 우리가 고른 npm 이 **전혀 다른 곳**에
설치할 수도 있습니다. 그래도 명령은 잘 돌았으니 0 을 반환합니다.

즉 설치는 A 에 했는데 프로그램은 B 를 보고 있으면, 명령은 성공하고 기능은 안 됩니다.
그리고 화면에는 "설치 완료" 라고 뜹니다. #298 의 모든 사연이 이 한 가지 모양입니다.

## 이제는 찾아봅니다

판단 기준을 바꿨습니다.

**설치가 끝났다는 근거를 명령의 출력이 아니라, 패키지를 실제로 찾았는지로 삼습니다.**

찾을 때는 음성 입력이 실제로 키트를 불러올 때 쓰는 바로 그 방법을 그대로 씁니다.
"설치한 곳" 과 "불러오는 곳" 을 따로 확인해 비교하는 대신, 처음부터 하나의 질문으로
합친 겁니다 — **지금 이걸 불러올 수 있나?**

이 방식의 좋은 점은 위 표의 경우를 하나씩 따로 처리하지 않아도 된다는 것입니다.
volta 든 pnpm 이든 `npm_config_prefix` 든, 어디에 깔렸든 상관없이 **불러올 수 있으면
성공이고 없으면 아직 아닙니다.** 사용자 입장에서도 그게 전부니까요.

## 못 찾으면 한 번 더

바로 실패로 처리하지는 않습니다. 제보자가 알려준 것이 있으니까요 — **같은 명령을 한
번 더 돌리면 됐다**는 것.

그래서 처음에 못 찾으면 설치를 한 번 더 실행하고 다시 찾아봅니다. 이미 깔려 있는
패키지에 `npm install` 을 다시 하는 것은 아무 일도 일어나지 않으므로 안전합니다.

다만 **명령 자체가 실패한 경우에는 다시 시도하지 않습니다.** 권한이 없어서 못 쓴
경우처럼 명령이 아예 실패한 것이라면 두 번 돌려도 결과가 같고, 진짜 오류를 보기까지
기다리는 시간만 두 배가 되기 때문입니다.

두 번 다 해봐도 못 찾으면 이렇게 안내합니다.

> 설치가 정상적으로 마무리되지 않았습니다. 다시 한 번 시도해주세요.

실패라고 단정하지 않습니다. 실제로 실패한 게 아니니까요. 그렇다고 "설치는 됐는데
못 찾겠다" 같은 내부 사정을 늘어놓지도 않습니다. 무슨 일이 있었고 무엇을 하면
되는지만 말합니다.

설치가 확인되면 그 다음 화면은 **버전 표시 기능에게 넘깁니다.** 버전 숫자를 눌렀을 때
다시 조회하는 그 기능 그대로입니다. 설치 쪽에서 "설치됨" 을 따로 기억해두면 두 군데
판단이 언젠가 어긋나기 때문입니다.

## 안내가 4초 만에 사라지던 문제

이번에 같이 고친 것이 하나 더 있습니다.

`/usr/local` 처럼 관리자 권한이 필요한 위치에 설치하려 하면 명령이 실패합니다.
이건 정상입니다 — 백그라운드에서 도는 프로그램은 비밀번호를 물어볼 수 없으니까요.

그래서 원래부터 실패하면 **그대로 복사해 쓸 수 있는 명령**을 안내하고 있었습니다.

```
sudo /usr/local/bin/npm install -g --prefix /usr/local @swttch/extend-kit
```

그런데 이 안내가 **4초 뒤에 사라지고 있었습니다.** 알림 기본 설정이 그랬습니다.

여러 줄짜리 안내를 읽고, 그 안에서 명령을 찾아, 터미널에 옮겨 적기에 4초는 턱없이
부족합니다. 실제로 제보자는 이 안내를 못 보고 직접 명령을 알아내서 실행했습니다.
읽을 시간이 없는 안내는 안내가 아닙니다.

이제 설치 실패 안내는 **직접 닫기 전까지 사라지지 않습니다.** 대신 닫기 버튼이
붙었고, 명령은 줄바꿈을 유지해 한 줄로 보입니다.

"설치가 정상적으로 마무리되지 않았습니다" 안내도 같은 길로 전달됩니다. 사용자에게
다시 눌러보라고 알려주는 유일한 통로이기 때문입니다.

## 정리

- 설치 완료를 종료 코드가 아니라 **실제로 찾았는지**로 판단합니다.
- 찾을 때는 음성 입력이 키트를 불러오는 것과 **같은 방법**을 씁니다.
- 처음에 못 찾으면 **한 번 더 설치**해봅니다. 명령 자체가 실패한 경우는 제외입니다.
- 두 번 다 안 되면 다시 시도해달라고 안내합니다.
- 설치 실패 안내는 **읽고 쓸 때까지 사라지지 않습니다.**
