# 슬래시 명령 안에서도 @ 파일 멘션이 동작합니다

> 언어: [English](./en.md) · **한국어**
>
> 관련: [#236](https://github.com/yhk1038/claude-code-gui-jetbrains/issues/236)

## 제보

한 사용자가 채팅 입력창에 `/opsx:apply @skill` 을 입력했습니다. `@` 를 치면 파일
선택 목록이 뜰 거라 기대했는데, 아무것도 나오지 않았습니다. 그래서 슬래시 명령
패널만 덩그러니 떠 있는 화면을 캡처해 [#236](https://github.com/yhk1038/claude-code-gui-jetbrains/issues/236)
으로 알려주셨습니다.

그리고 2분 뒤 남긴 댓글이, 결과적으로 이 문제를 푸는 열쇠가 됐습니다.

> 그런데.. 이 깃허브 링크를 찾으려고 "setup"을 눌렀다가 돌아와 보니.. 이게 보이네요..
> 아무래도 이벤트나 타이밍 문제인 것 같습니다

함께 올린 스크린샷에는 **완전히 똑같은 입력**(`/opsx:apply @skill`)인데 이번엔
파일 목록이 멀쩡히 떠 있었습니다. `dod/SKILL.md`, `diff-org-changes/SKILL.md` 같은
항목들이 그대로 보였죠. 같은 글자, 다른 결과. 제보자는 타이밍 문제로 짐작했습니다.

타이밍이 아니었습니다. 더 단순하고, 그래서 더 고약한 이유였습니다. 목록은 처음부터
준비돼 있었고, 다른 패널에 가려져 있었을 뿐입니다.

## 실제로 벌어지던 일

슬래시 명령 패널과 `@` 파일 선택 목록은 **화면상 같은 자리**를 씁니다. 입력창 바로
위 한 줄이죠. 둘이 동시에 있을 수 없으니 누가 이길지 규칙이 필요했고, 그 규칙은
이랬습니다. 슬래시 패널이 열려 있으면 파일 목록은 아예 그리지 않는다.

그리고 슬래시 패널은 자기가 열려 있을지를 딱 한 가지로 판단했습니다.
**"이 줄이 `/` 로 시작하나?"**

이 둘을 겹쳐 놓으면 문제가 드러납니다. `/opsx:apply @skill` 은 `/` 로 시작하니
슬래시 패널이 계속 열려 있습니다. 명령 이름을 치는 동안만이 아니라, 그 줄 전체에
걸쳐 끝까지요. 그리고 패널이 열려 있으니 파일 목록은 화면에 나올 기회가 없었습니다.
검색은 이미 끝나 있었고, 결과도 도착해 있었지만, 그저 그려지지 않았습니다.

제보자가 우연히 발견한 "해결책"도 이걸로 설명됩니다. 입력창 바깥을 클릭하는 것이
슬래시 패널을 닫는 유일한 방법이었기 때문에, 깃허브 링크를 찾으러 화면 밖을 누른
순간 패널이 스스로 닫혔고, 이미 불러와 대기하던 파일 목록이 그제서야 보인 것입니다.

여기엔 좀 얄궂은 사정도 있었습니다. 바깥을 클릭해도 사실 해결된 게 아니었습니다.
다음 글자를 치는 순간 패널이 다시 열렸거든요. 제보자가 찾아낸 우회법은 딱 한 글자
동안만 유효했던 셈입니다.

## 무엇이 바뀌었나

이제 판단 기준은 "줄이 슬래시로 시작하나"가 아니라 **"커서가 어디에 있나"** 입니다.

- 커서가 `@토큰` 안에 있으면 파일을 고르는 중입니다. 파일 목록이 그 자리를 쓰고,
  슬래시 패널은 물러납니다.
- 그 밖의 위치라면 아직 명령을 다루는 중입니다. 슬래시 패널이 그대로 자리를
  지킵니다.

이 한 가지 변경으로 두 기능이 자리를 두고 다투는 대신 나눠 쓰게 됐고, 덕분에
**모든** 슬래시 명령 뒤에서 `@` 멘션이 동작합니다.

## 달라진 점

- **슬래시 명령 뒤에 `@` 를 치면 파일 목록이 바로 뜹니다.** `/review @s`,
  `/opsx:apply @skill`, 직접 만든 스킬까지 전부 해당합니다. 바깥을 클릭할 필요도,
  기다릴 필요도 없습니다.
- **파일을 고르면 명령 패널이 돌아옵니다.** 항목을 선택하면 경로가 칩으로 삽입되고,
  멘션이 끝났으니 슬래시 패널이 알아서 복귀합니다. 예전에는 다음 글자를 칠 때까지
  패널이 사라진 채였는데, 같은 뿌리에서 나온 이 작은 문제도 이번에 함께 고쳤습니다.
- **커서를 토큰 안으로 되돌리면 파일 목록이 다시 나옵니다.** `@src/` 로 백스페이스해
  들어가면 다시 파일을 고르는 상태가 되고, 지나쳐 나오면 명령을 다루는 상태로
  돌아옵니다. 양방향 모두 매끄럽게 전환됩니다.
- **이메일 주소는 여전히 건드리지 않습니다.** `fred@example.com` 에서는 파일 목록이
  뜨지 않습니다. `@` 는 줄 맨 앞이거나 공백 뒤에 올 때만 멘션으로 봅니다.
- **두 패널이 겹치는 일은 없습니다.** 어떤 상황에서도 화면에는 하나만 떠 있습니다.

## 이슈 제목에 관하여

이 문제는 "스킬 맥락에서 @ 파일 멘션이 동작하지 않는다"는 제목으로 접수됐습니다.
제보자가 마침 스킬을 쓰던 중이었으니 충분히 그렇게 보일 만한 상황이었습니다.
다만 실제 원인은 스킬과 무관했습니다. 조건은 그저 "슬래시 명령 패널이 열려 있을
것"이었고, 이는 `/review` 같은 기본 명령에서도 똑같이 성립합니다. 그래서 이번
수정도 스킬에 한정되지 않습니다. 슬래시로 시작하는 무엇을 입력하든 `@` 멘션이
정상 동작합니다.
